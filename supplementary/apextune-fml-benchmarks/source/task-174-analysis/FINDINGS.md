# task-174 · aif360 AOD 噪声标定实验结论

**日期**: 2026-09-16  **硬件**: 4090 实例 `223370aa0ff3` (vast, 141.11.90.211:41577)
**口径**: fml-bench `train_eval_baseline.py` + 原始 `adversarial_debiasing.py` 基线机制, **只用 val 切分**(475 行), 全程不碰隐藏 test 切分
**代码**: 归档于 task-174 目录 `driver.py` / `analyze.py`, 原始结果 `exp-results/results/`

## 实验设计

把官方评测的硬编码 `set_seed(233)` 参数化, 扫 8 个训练种子 {233,1..7}:

- **A1 确定性**: 同 seed(233) 跑两次 → 检验评测端到端是否确定
- **A2 基线**: 8 个 seed × 基线机制 → 训练随机性对 AOD 的敏感度
- **A3 best-of-3**: 8 个 seed × (训练 3 次重启 + 用训练侧 15% 留出切片选最佳) → 机制层鲁棒性杠杆
- **bootstrap**: 对 A2 逐行预测重采样 2000 次 → 475 行 val 的量测采样噪声

## 结果

| 项 | 数值 |
|---|---|
| A1 同 seed 两次 | **0.382461 / 0.382461 — 完全一致**, 评测确定性 |
| A2 基线 n=8 | mean **0.4418** ± 0.1048 (min 0.3719, max 0.6712) |
| A3 best-of-3 n=8 | mean **0.3045** ± 0.0827 (min 0.1198, max 0.3825) |
| A3−A2 | **−0.1373 (−31%)**, std 收窄到 0.79× |
| bootstrap(475 行) | std **0.0470** ≈ 相对噪声 ~12% |

单种子细节: 基线在 seed 233/3/4 上给出完全相同的 0.38246(收敛到同一退化解)。

## 结论

1. **评测端到端确定**(A1)→ 同名代码复测返回同一数字。此前方案中"末期多 seed 复测榜单候选"**确认死亡**: 每步烧 1% 预算换回零信息。噪声 100% 来自同一代码在不同训练 seed 下的模型差异, 以及小样本量测。

2. **训练 seed 敏感度是主导噪声源**(A2 σ≈0.105), 约为 val 量测采样噪声(A1 bootstrap σ≈0.047)的 2 倍。二者叠加导致 val 上 <0.1 的差异基本不可信 —— 直接解释了战役里 val 排名与 test 排名错位。

3. **机制层重启杠杆成立**(A3): 3 次重启选型把 val 均值降低 31%、方差收窄。这是在**零 LLM 成本、零官方步数**下拿到的。注意 A3 的选型代理(训练侧 15% 留出)本身也会过拟合, 0.12 的最优值偏乐观; 但均值/方差的改善方向稳健。

4. 由此, v7 架构应聚焦**机制层**(fit 内 K 重启/集成 + 稳健选型代理), 选择层无路可走(架构上 agent 只能拿聚合指标)。并加一条估值规则: **val 改善 < 0.1 不认**, 以合并噪声为门槛。

## 冠军机制做了什么(v5 三轮 best_snapshot 通读)

三轮冠军全部在**机制层**动手, 与 v6 被证伪的"选择层启发式"是两回事:

- `adversary_loss_weight` 硬编码为 0.1; r1 重写了分类器梯度回路(pre-opt 风格)。
- **r2/r3 增加了训练侧逐组阈值搜索**: 在训练数据上扫 `unprivileged_threshold × privileged_threshold`(0.38–0.62 网格), 以"训练集上 TPR/FPR 组间差最小 + 准确率不低于参考值"为键选最优阈值对, 预测时用之。
- 即: 冠军是"超参调优 + 训练侧后处理阈值搜索"的组合, **并非重启/集成**。它们已把 train 上的 AOD 压低, 但**对训练 seed 的敏感度未被处理** —— 这正是 A2 揭示的主导噪声源, 也是 A3 验证的下一根杠杆。

## 下一步(v7 方向, 待决)

1. **在冠军机制上复测 seed 敏感度**: 取 r1/r2/r3 冠军代码 × 8 seed 扫 val, 量化其 σ; 预期与基线同量级。
2. **给冠军叠加 K 重启**: 用 A3 已验证的"多次重启 + 训练侧稳健代理选型"包裹冠军机制, 看能否把 val 均值进一步压低 —— 这是零 LLM 成本、可直接量化的一步。
3. 若成立 → v7 = 冠军机制 + 内置重启集成 + 提案预筛(用闲置的 ~184 LLM 请求/轮); 跑一轮诊断口径验证。
4. 评测确定性(A1)意味着**官榜口径下每种子仍是一次掷骰**; 要判 AIDE 胜负需多轮, 但机制层鲁棒化能直接抬升掷骰分布的均值。

## Phase B: v5 冠军机制的 seed 敏感度(24 次运行)

把三轮冠军 `adversarial_debiasing.py` 作为私有模块加载(不碰实仓),扫同样的 8 个 seed:

| 机制 | mean | std | min | max |
|---|---|---|---|---|
| r1 冠军 | 0.0495 | 0.0366 | 0.0024 | 0.0910 |
| r2 冠军 | 0.1030 | 0.0239 | 0.0662 | 0.1491 |
| r3 冠军 | 0.0785 | 0.0336 | 0.0511 | 0.1554 |
| 池化 | 0.0770 | 0.0378 | — | — |

**冠军机制仍然对 seed 敏感**,而且落在**离散的吸引子**(basin)上,不是连续漂移。r1 的 8 次取值只有 4 个不同值(0.0203/0.0806/0.0910/0.0024),说明对抗训练+50 epoch 在不同 seed 下收敛到少数几个固定解。

**r1 冠军的机制**(读码确认):预测时按组别施加**固定阈值偏移** `0.5 + 0.08·(2·pa−1)`(特权组阈值 0.58,非特权组 0.42),纯确定性后处理,不依赖 val。这正是它比 r2/r3(训练侧网格搜索阈值)更稳的原因。

## 综合结论

1. **评测端到端确定** → "末期多 seed 复测候选"死。
2. **训练 seed 是主导噪声源**:基线 σ=0.105,冠军池化 σ=0.038——**任何单 seed 的 val 选择都在 ~0.04–0.10 的噪声里挑,远大于我们想追的 0.005 差距**。战役 val→test 错位由此完全解释。
3. **两种有效的机制层稳健化路径**:
   - **固定确定性后处理**(r1 的做法):按组别固定调整决策阈值,对 seed 免疫,把 AOD 钉在一个稳定值上——但那个值取决于 base 模型的组间差。
   - **K 重启 + 训练侧代理选型**(A3 验证):把均值降 31%,是通用杠杆,不依赖特定机制。
4. **结合**:对基准模型做 K 次内部重启并把预测聚合(或选训练侧稳健者),再叠加 r1 式的确定性组别校准——这是 v7 的机制层配方。
5. **估值规则**:val 差异 < 0.05 不认(合并噪声量级)。

## 保真度警告

本实验的**绝对数值是复现口径,不等于战役口径**:我的基线 val AOD ≈ 0.38,战役 baseline_primary_metric = 0.2657。方向一致(基线远差于冠军 ~0.02),但绝对值有 ~1.4x 偏差,可能来自切分/预处理细节。**结论只用相对结构与噪声量级,不直接引用绝对值。**

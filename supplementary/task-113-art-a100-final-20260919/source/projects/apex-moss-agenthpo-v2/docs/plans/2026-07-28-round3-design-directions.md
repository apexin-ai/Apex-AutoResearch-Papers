## 1. 复现数量评估(用户问题一)

**现状**:复现只有 R1/R2 两条(R0 是原始谱系,不算复现)。R1 已失败(v007 回到
起点 75%),R2 待完成。可能结局:R2 败 → 1/3,判"进化不可重复";R2 成 → 2/3,
但两条新复现一成一败,证据强度有限。

**结论:本轮不加 R3/R4。** 理由不是"两次够了",而是"给已知高噪声的机制买更多
复现不值":
- 已诊断的噪声源:quick train 仅 8 题、4 题恒过、单题 12.5 点、无回归保护——
  谱系成败部分由抛硬币决定;
- **决策不变性**:R2 无论成败,下一步都是修机制(成也不稳,败更要修),
  R3 的结果改变不了任何后续决策;
- 有含金量的复现是**修好机制之后**的全新谱系(见 §4 第二阶段),同一笔钱买那边
  的样本量信息量更高。

**可选保险(需现在预注册,费用另批)**:"打平加赛"规则——仅当 R1/R2 一成一败
(即 R2 成功)时,加跑一条 R3 作裁判;触发条件与角色现在冻结,不算事后加试。
默认不启用。

## 2. Q2 混淆的根源与重设计(用户问题二)

**根源承认**:两族(tddgen_hidden / specgen_hidden)按原设计使用**不相交的题池**
(为防泄漏),导致"题型"与"题池难度"完全绑定。交叉考试换族时同时换了整套题;
v001 在两族 val 上本身就差 40 点(56.7% vs 16.7%),v005 的 +33.3"主场优势"
几乎全部由此解释。已完成的同题配对(q2_paired)证实:控制底层题后交互效应为
−6.7 点、CI 跨 0,`direction_refuted`。

**额外缺陷**:本轮 Q2 实际比较的是"进化成功的 v005"vs"进化零进步的 v007"——
spec 侧的"专门流程"从未诞生,对比自始不公平。故 Q2 逻辑上**下游依赖 Q1 机制
可靠**。

**重设计(第三阶段,预注册占位)** —— 同题双呈现配对:
- 同一底层函数生成两种呈现:**stub 变体**(从头实现)与 **AST 变异 bug 变体**
  (修复缺陷);仅保留两种变体都通过质量门禁(stub/变异体 visible-pass-hidden-fail、
  oracle 双验)的题;
- 训练:两条谱系各看同一批底层题的本方呈现(底层难度天然同分布;跨谱系不共享
  trace/代码);
- 验证:另一批从未入训的底层题,**每题两种呈现都考、每个 harness 都考**;
- 主指标:task-paired difference-in-differences(交互项),沿用固定 seed bootstrap;
- 前置条件:第二阶段证明进化机制可靠且两侧谱系均满足训练前提,否则不启动。

## 3. Builder 评估的盲区与补全(用户问题三)

**承认**:本轮 Q3 只测了 Builder 的**零样本能力**(初稿直接考试),未测其核心
预期价值——**作为进化起点的质量(evolvability)**。系统愿景是 builder 出初稿、
进化精修;"骨架是否让进化更快更高"与"初稿即战力"是两种不同能力,本轮仅否定了
后者。

**补全设计(第二阶段合并实验)** —— 起点对比:
- 同一套**修复后**的进化机制、同一冻结 train,4 条谱系:
  - 2 条 seed = 通用 v001(逐字);
  - 2 条 seed = builder0(每族取已通过门禁链的第一版,不重新生成、不挑版本);
- 评估:各谱系 final 在冻结 external holdout 上 3 遍正式(指标体系见 §3.1);
- 双问合一:v001 对谱系答"修复后的进化是否可复现"(Q1'),
  builder 对 v001 对谱系答"Builder 初稿是否是更好起点"(Q3');
- 判定线在第二阶段协议中冻结(方向:builder-seeded holdout 终点均值高于
  v001-seeded 且大于波动 → 起点价值成立;两条 v001 谱系均满足训练前提 →
  修复后机制可复现);
- 前置:机制修复先行,否则起点对比测的是噪声。

### 3.1 进化程度的指标体系与抗过拟合设计(回应用户追问)

**信息角色分层(冻结原则:进化能看的,与评判用的,必须是两套数据)**

| 数据 | 进化过程可见? | 用途 |
|---|---|---|
| train(扩至 ~16 题,见下) | 是——Proposer 唯一反馈源 | 驱动改进;训练分只作"入场券"与诊断 |
| **holdout(新抽,冻结)** | **否——全程零接触** | **唯一定胜负数据** |
| 旧 q1_external val | 否 | 已被本轮 R0/R1 判定消耗,第二阶段只作敏感性参照,不作主判 |

holdout 从 reserve 池(34 题已验证)按 `sha256(task_id)` 机械新抽 ≥12 题,
在任何第二阶段模型调用前冻结;它对 v001 起点与 builder 起点**同样陌生**
(builder0 生成时只见 family card,从未接触任何题目,故无先验偏袒)。

**指标(判定线随第二阶段协议冻结):**

1. **主指标(唯一定胜负)**:`holdout_final(lineage) − holdout(v001 baseline)`,
   每格 3 遍;起点组间比较用两条谱系均值,要求组间差大于组内波动。
2. **过拟合直接量**:`overfit_gap = train_gain − holdout_gain`。
   预注册解读:holdout_gain 显著为正且 gap 小 → 学到通法;
   train_gain 大而 holdout_gain ≈ 0 或为负 → **该起点更易诱导背题**,
   这是有效负结论,必须如实报告(R0 已示范此形态:train +20.8,val −3.3)。
3. **次指标(仅描述,不参与判定,防止事后择优)**:达到既定训练水平所需轮数与
   executor tokens(爬升效率)、逐任务通过矩阵的翻转率(稳定性/回归度)、
   质量—成本 Pareto 位置。

**抗过拟合手段(随协议冻结):**

- **训练集扩容**:8 题 → ~16 题(reserve 充足)。现 8 题中仅 4 题有区分度,
  单题 12.5 点,Proposer 把题目特征写进提示的收益极高(R1/v004、v007 已实证
  点名 120/458/1057);扩容使背题面翻倍、单题噪声减半。扩容后的 train 在第二阶段
  首次模型调用前冻结,且与 holdout 不相交。
- **停止规则只依赖 train 侧**:何时停止进化由训练侧规则决定(轮数上限/训练满分),
  holdout 分数**永不**参与任何中途决策——holdout 一旦影响停轮或选版本即视为泄漏,
  该谱系作废。
- **每谱系只考一次 holdout**:final 冻结后才运行,不做逐版本 holdout 曲线
  (逐版本考 = 变相把 holdout 当验证集用)。
- **回归保护本身也是抗过拟合**:恒过题不得退步的接受规则,抑制"为救一题重写
  整个策略"的局部特化倾向。

## 2. Q1 实施方案(进化是否学到可迁移方法)

**输入与对照(全冻结,不新增)**
- 家族 A:`tddgen_hidden/v005`(修复后版本,一字不再改)vs 已有 v001 四格中的 tdd 两格。
- 家族 B:`specgen_hidden/v007` vs v001 的 spec 两格。
- 进化早已结束且只见过 train;本阶段所有 harness 均为冻结产物,不存在反馈回路。

**运行顺序(格内 3 遍一次跑完;格间序见 §6)**
1. v007 × spec train(最便宜格,兼作额度恢复后的探针)。
2. v005 × tdd train → v005 × tdd val(第三次尝试;前两次已隔离)。
3. v007 × spec val。

**有效性门禁(每格统一)**
- 跑前:TokenRouter 探针(1 次 haiku 冒烟)+ 台账余量 ≥ 本格上限 ×1.5;
  v005 的恢复 canary 已 1/1 PASS,门禁链(原始响应/静态合同/离线 smoke/一题 canary)视为已满足;
  v007 首格前补一次 1 题 canary(取该族 train 首题,非正式)。
- 跑后:0 tamper、0 harness_error、0 env_error 才判有效;任何基础设施失败 → 整格隔离至
  `results/invalid/`、记 PROGRESS、修复后**整格从头重跑**(3 遍不拆分)。

**产出指标**:每格 `pass_rate_mean ± pstdev`、per_repeat、per_task_passes、tokens、
category 计数;写入 `results/official/hidden-<harness>-<family>-<split>/`。

**判定规则(冻结线重述)**
- 前提(按族分别判):终版 − v001 的 **train** 提升 ≥ +15 点且大于波动 → 该族进化机制有效。
  预期:A 族可能满足(快速反馈 100% vs 基准 75%);B 族大概率不满足(50% vs 50%)——
  若如此,Q1-B 结论固定为"进化机制未生效",**不阻塞** A 族结论与 Q2/Q3 的既定比较。
- 主判定(前提成立的族):终版 − v001 的 **val** 提升 ≥ +5 → 通法;≤ −5 → 应试;之间 → 不明确。

**失败/重跑**:capability 失败照常计分;infra 失败按上文整格重跑;同一格第 3 次 infra
失败 → 停队列,出交接 Prompt 回方案模式。

**预计消耗**(依据:无效运行实测 v005 ≈ 73k/train-run、42k/val-run;v007 evolution 实测 ≈ 23k/run)

| 格 | 期望 | 硬上限 |

## 3. Q2 实施方案(任务条件化是否带来真实专长)

**输入与对照**:主场格直接复用 Q1 产出(v005×tdd val、v007×spec val),只需补 2 个客场格:
- v005 × **specgen** val;
- v007 × **tddgen** val。
v001 在两族 val 的成绩已有,作三方参照。

**运行顺序**:在 Q1 四格全部有效后再跑(主场分先落地,客场格才有解释对象);
两格先便宜后贵:v007×tdd val → v005×spec val。

**有效性门禁**:同 §2 统一门禁;另加**跨族形状 canary**:每个客场格前用客场族 train 首题
跑 1 题(非正式),确认 harness 对另一族文件形态(V0 冒烟测试 vs V1 行为测试)无结构性
崩溃——v005 在 V0 题上"可见测试"只剩冒烟,属预期行为,不算失败。

**产出指标**:两个方向的 主场分 − 客场分(各自以本族 val 为主场)。

**判定规则(冻结)**:至少一个方向 ≥ +10 点且大于波动 → 有专长红利。
**预注册解释上限(不可越界)**:因 B 族回退为 specgen,任何 Q2 结论只能表述为
"可见反馈信息形态(1 个行为测试 vs 0 个)条件化的效应",不得表述为两种 bug
构造方法或"任务语义族"的因果差异。此句必须原文进入 RESULTS.md。

**失败/重跑**:同 §2。

**预计消耗**:v007×tdd val ≈ 0.8M(上限 1.2M);v005×spec val ≈ 1.5M(上限 2.2M);
小计 **≈2.4M**(上限 3.4M,含 2 次 canary ~0.1M)。

## 4. Q3 实施方案(Builder 零样本生成)

**输入与对照**
- Builder 输入**只有** `family_cards/tddgen_hidden.md`、`family_cards/specgen_hidden.md`
  (冻结版;卡内无题目、无分数、无 traces)。生成模型 sonnet-4-6,每族 ≤3 次尝试
  (合同修复循环只见合同错误),计入 100 次调用上限(预计用 2–6 次,余量充足)。
- 对照:v001 与各族终版在相同格上的成绩。

**运行顺序**
1. 生成 builder0-tdd、builder0-spec(不耗 executor 额度;原始响应存 `results/generator_raw/builder/`)。
2. 每个 builder0 走完整门禁链:解析/静态沙箱合同 → 离线 fake-tools smoke → 本族 train 首题
   1 题 canary(非正式)。
3. 正式四格:builder0-tdd × {tdd train, tdd val} → builder0-spec × {spec train, spec val}。

**有效性门禁**:同 §2 统一门禁 + 上述生成物门禁链;builder0 若 3 次尝试仍违反合同 →
记 harness_error 类基础设施结果,该族 Q3 判"生成失败"(这是允许的实验结论,非无效)。

**产出指标**:builder0 − v001 在两族 val 的差值;train 格用于诊断(过拟合形态参考),
不进判定。

**判定规则(冻结)**:两族 val 都不低于 v001,且至少一族 ≥ +10 点 → 零样本生成有信号。

**失败/重跑**:同 §2;builder0 的 capability 低分是**有效结论**,不重生成、不重挑版本
(防止事后择优);每族只有第一个通过门禁链的生成物有正式资格。

**预计消耗**:builder0 步数结构未知,按 v001~v007 区间估 ≈25k/run:
4 格 108 runs ≈ **2.7M**(每族上限 2.5M,合计上限 5.0M;含 2 次 canary ~0.1M)。

## 5. 失败分类与无效处理(全问共用,冻结重述)

优先级:tampered → harness_error(合同/崩溃/0-step)→ env_error(额度/网关/依赖,
含"配额耗尽导致的成批错误")→ timeout(默认 capability,除非有网关证据)→ capability。
仅 capability/timeout 计分;infra 类整格隔离重跑;所有隔离带 review.json(现有惯例)。
**额度熔断**:队列 runner 监视产出目录,同格连续 ≥3 个 run 出现配额/5xx 类错误即终止该格、
标记 env_error、暂停整个队列等待人工确认额度,避免重演 1.6M 的整场无效。

## 6. 受控调度:串行队列、并行判定与恢复顺序

**并行判定**:10 个格在科学上完全独立(harness 全冻结、无反馈回路),理论上可并行;
但共享同一 TokenRouter 额度池,上次整场无效正是并发重跑期间额度耗尽造成。并行只省
墙钟(全队列串行估 3–5 小时),而墙钟不是瓶颈,额度安全才是。
**推荐:格间严格串行,格内维持既有 4 并发**(评测协议现状,不改)。唯一可接受的重叠:
Builder 的 sonnet 生成与离线门禁(第 4 节步骤 1–2)不耗 executor 额度,可在任意串行
间隙进行;为台账简单,默认也排入串行位。

**推荐队列(含切割线)**:

| # | 格 | 期望/上限 (M tok) | 说明 |
|---|---|---|---|
| 0 | 跑前:确认 TokenRouter 余量 ≥ 4M;haiku+sonnet 各 1 次冒烟 | ~0 | 用户确认额度数字后开跑 |
| 1 | v007 canary + v007 × spec train | 0.6 / 0.9 | 便宜探针,验证额度恢复稳定 |
| 2 | v005 × tdd train | 1.75 / 2.4 | Q1-A 核心 |

| 5 | 跨族 canary + v007 × tdd val | 0.85 / 1.2 | Q2 客场(便宜方向) |

**中断恢复顺序**:队列位置持久于台账;中断后 (1) 复核最后一格分类:有效则保留、从下一格
继续;infra 无效则隔离并从**同一格**重跑;(2) 重新执行第 0 步额度确认;(3) 已有效格永不
重跑。当前被暂停的 v005 恢复 canary 无需重启——其 1/1 结果已满足门禁用途,保持非正式。

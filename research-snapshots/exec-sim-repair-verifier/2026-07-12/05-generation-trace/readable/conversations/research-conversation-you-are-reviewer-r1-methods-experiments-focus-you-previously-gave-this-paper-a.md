## R2's Review (Novelty + Related Work)

**Score: 3 (Weak Reject), Confidence 4/5**

### Strengths
- Well-executed controlled comparison (model size, data, LoRA config constant)
- Thorough statistical methodology (clustered bootstrap, ICC, TOST)
- CWM failure mode analysis is convincing and useful
- Honest limitations disclosure
- Oracle accuracy-utility framework is principled

### Major Weaknesses
1. **Central finding is predictable from first principles.** Single-token classification being easier than exact-match generation is not surprising. "Complexity-dependent advantage" = "generation fails when outputs are long/complex."
2. **Framing instability.** The paper oscillates between neutral "design space characterization" and CLS advocacy. Original "CLS scales better" framing was contradicted by cross-model results; current "no universal winner" framing is still contradicted by the paper's text which advocates for CLS throughout.
3. **Cross-model validation incomplete where it matters most.** DeepSeek repo-level results exist but aren't fully reported. If ALL DeepSeek repo formulations are below majority baseline, the narrative collapses — it's not "CLS dominates at repo-level" but "no formulation works for DeepSeek at repo-level."
4. **No downstream validation.** Re-repair experiment shows null result (CLS +0.5pp p=0.72). The claimed practical benefit of per-test diagnostics is unsubstantiated.
5. **Error complementarity contribution is thin.** Oracle ensemble is a ceiling analysis, not a method. No practical ensemble is proposed.
6. **CWM baseline may be unfairly weak.** 4B/8B LoRA CWM vs the actual 32B Code World Model with mid-training — showing small LoRA fails doesn't indict the approach.

### Missing Related Work
- AlphaCode/AlphaCode2, CodeRL, APPS benchmark, ReAct/Reflexion
- Process vs outcome supervision parallel (Lightman et al., Uesato et al.) — CLS vs TRAJ maps directly to this
- Only ~20 references, lean for a top venue

### R2's Key Argument
The paper validates a predictable result (classification < generation for complex outputs) on limited scale, without delivering actionable methods. The contribution is below novelty threshold for a top venue. Would need: complete cross-model validation, include re-repair even if negative, reframe as empirical analysis with tempered claims.

6	\label{sec:method}
7	
8	Let $p$ denote a candidate patch and $T = \{t_1, \ldots, t_n\}$ its test suite, where each $t_i$ has label $y_i \in \{\text{\textsc{Pass}}, \text{\textsc{Fail}}\}$ from execution. Tests decompose into \emph{fail-to-pass} ($T_{\text{f2p}}$) and \emph{pass-to-pass} ($T_{\text{p2p}}$) subsets; a patch is correct iff $\forall\, t_i{:}\ y_i = \text{\textsc{Pass}}$. We compare three formulations for predicting correctness without execution.
9	
10	\subsection{Verification Formulations}
11	\label{sec:formulations}
12	
13	Let $c_p$ denote the code context (unified diff) of patch $p$.
14	
15	\paragraph{\cls{} (per-test classification).} $f(c_p, t_i) \rightarrow \hat{y}_i \in \{\text{\textsc{Pass}}, \text{\textsc{Fail}}\}$ predicts a single binary token per test (cross-entropy loss). Patch verdict: $\hat{y}_p = \bigwedge_{i} [\hat{y}_i = \text{\textsc{Pass}}]$. Cost: one token per test.
16	
17	\paragraph{\cwm{} (output generation).} $g(c_p, t_i) \rightarrow \hat{o}_i \in \Sigma^*$ generates the execution output string (language modeling loss). Verdict by exact match: $\hat{y}_i = \text{\textsc{Pass}}$ iff $\hat{o}_i = o_i^*$.\footnote{Exact string matching is conservative, consistent with \citet{meta2025cwm}. Semantic equivalences are not counted.} When the generated output is unparseable (i.e., does not conform to the expected structured format), the prediction defaults to the majority class verdict. Cost: $\sum_i |\hat{o}_i|$ tokens.
18	
19	\paragraph{\traj{} (trajectory-level).} $h(c_p, T) \rightarrow \hat{y}_p \in \{\text{\textsc{Resolved}}, \text{\textsc{Unresolved}}\}$ predicts a single patch verdict from all tests, providing no per-test signal. \traj{} serves as a granularity control: \cls{}--\traj{} differences reflect per-test decomposition value.

21	\subsection{\cwm{} Failure Modes}
22	\label{sec:failure-modes}

This is conservative but does not disadvantage \cwm{}: the dominant failure at repository scale is format non-compliance, where outputs are structurally unparseable regardless of matching strategy. This favors \cwm{} by assigning the statistically most likely label rather than penalizing format failures.

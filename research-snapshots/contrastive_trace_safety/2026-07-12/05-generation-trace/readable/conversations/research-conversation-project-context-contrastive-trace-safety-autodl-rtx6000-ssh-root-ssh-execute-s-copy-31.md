### 章节结构（~1500 words）

**3.1 Safety Commitment Point (定义)**
- CP = first reasoning step after which safety reasoning permanently ceases and the model commits to generating harmful content
- Operationalization: annotated on HarmThoughts traces using safety reasoning presence/absence
- Binary classification at each step: pre-commitment (safe) vs. post-commitment (unsafe)

**3.2 Detection Task Formulation**
Metrics (all defined precisely):
- **Coverage** (detection rate): fraction of jailbreak traces where probe crosses threshold at any point
- **Pre-CP FPR** (dual definition, both reported):
  - Step-level: probability of false positive at any given pre-commitment step. Used for deployment cost interpretation.
  - Trace-level: mean per-trace FPR (average over traces of each trace's step-level FPR). Used for statistical comparisons (bootstrap).
  - Explain the difference: a few traces with extreme step-level FPR inflate the trace-level mean without proportionally affecting the step-level aggregate.
- **Precision**: fraction of positive detections that are true positives
- **Lead time**: steps between first detection and commitment point (positive = early)
- **Safe FPR**: false positive rate on entirely safe (non-jailbreak) traces
- **Detection criterion K**: number of consecutive threshold crossings required (K=1 throughout unless noted)

**3.3 Models and Data**
- 3 models:
  - DeepSeek-R1-Distill-Llama-8B (r1-8b): Llama-based architecture, 32 layers, 4096 hidden dim, 8B params
  - DeepSeek-R1-Distill-Qwen-32B (R1-32B): Qwen-based, 64 layers, 5120 hidden dim, 32B params
  - QwQ-32B-Preview (QwQ-32B): Qwen-based, 64 layers, 5120 hidden dim, 32B params, native reasoning model (not distilled)
- 2 architectures (Llama vs Qwen), 2 scales (8B vs 32B)
- OpenThinker-7B excluded: would make 4/5 models Qwen-based; 3 models already cover 2 arch × 2 scales
- Data: HarmThoughts traces, 209 traces per model
- Split: 60/20/20 = 125 train / 41 val / 43 test. Val set for threshold tuning (no test leakage)
- Table reference: \cref{tab:models}

**3.4 Hidden-State Probes**
- Feature: last token hidden state at each reasoning step (not pooled, not CLS — the actual last generated token)
- Layer selection: sweep all layers, score by balanced_accuracy × crossing_rate (scheme B). This selects layers that are both accurate AND detect early.
- Best layers: r1-8b layer 14 (44% depth), R1-32B layer 10 (15.6% depth), QwQ-32B layer 2 (3.1% depth)
- Classifier: logistic regression (L2 regularized, threshold tuned on val set)

**3.5 Text Baseline**
- Feature: all-MiniLM-L6-v2 sentence embeddings (384-dimensional, from HuggingFace sentence-transformers)
- Input: full text of each reasoning step
- Same classifier and threshold tuning as HS probes
- Motivation: represents what's achievable with text-only monitoring (no model internals access)

**3.6 Temporal Methods**
- Window concatenation: features from steps [t-W+1, ..., t] concatenated into single vector. W ∈ {1, 3, 5, 10, 15, 20, 25}
- GRU sequence models: trained on full step sequences. Single-layer (best individual layer) and multi-layer (7 layers concatenated) variants. 3 random seeds for variance estimation.
- Detection: threshold on probe score at each step. K=1 (single crossing) or K=5 (consecutive crossings)

**3.7 Baselines**
- BOCPD (Bayesian Online Change-Point Detection): applied to probe score sequences. Tests whether safety commitment produces an abrupt distributional shift.
- CUSUM (Cumulative Sum): parametric sequential detection. Multiple threshold/drift configurations tested.
- Mahalanobis distance (TrajGuard-style): distance of hidden state from class-conditional distributions. Tests geometric separability.

- Registry experiments: diag_d1_layer_sweep (layer selection), exp_013_text_baseline (text features)
- Model specs from HarmThoughts paper and model cards

69	4. **结果说明什么** — 用具体实验结论支撑贡献

71	### 2.2 禁忌
72	
73	- **禁止堆砌数据**：Abstract 不是 Results 的缩写。最多引用 2-3 个关键数字，要服务于 claim
74	- **禁止过度宣传**：不说 "revolutionary"、"groundbreaking"
75	- **禁止写成 Introduction 的缩写**：Abstract 是独立阅读单元

81	写完后用这个标准自检：审稿人能否在 30 秒内判断——

83	- 方法是否清楚？
84	- 贡献是否可信？
85	- 结果是否有说服力？

89	## 三、Introduction 写作规范
90	
91	### 3.1 完整叙事线（5 段结构）
92	
93	Introduction 需要从一个清晰、重要的问题切入，逐步把读者带到核心贡献：
94	
95	1. **研究背景**（1-2 段）：大模型在某类能力/应用中已取得进展，但仍存在一个关键瓶颈
96	2. **问题重要性**（1 段）：结合真实应用、已有方法局限或当前趋势，说明这不是小问题
97	3. **现有方法不足**（1 段）：系统梳理为什么不够（依赖更大模型/更多数据/更复杂推理/更高成本，或只在特定 benchmark 有效）
98	4. **本文核心想法**（1 段）：我们观察到什么、提出了什么方法、为什么能解决上述问题
99	5. **贡献总结**（列表）：清楚列出方法贡献、实验贡献和分析贡献
100	
101	### 3.2 整体叙事结构
102	
103	```
104	现有进展 → 关键缺口 → 本文洞察 → 方法概述 → 实验证据 → 贡献总结
105	```
106	
107	### 3.3 禁忌
108	
109	- **禁止泛泛介绍**：不要开头就写 "LLMs have shown remarkable capabilities..."，要从具体问题切入
110	- **禁止缺少过渡**：每段之间必须有逻辑连接
111	- **禁止实验报告风格**：Introduction 不是 "我们做了 X 实验得到了 Y 结果" 的罗列
112	- 每条 Contribution 必须有对应的 section/table 支撑
113	- Contribution 列表中不能出现未在前文铺垫过的概念
114	
115	---
116	
117	## 四、Related Work 写作规范
118	
119	### 4.1 目标
120	
121	让审稿人相信：作者理解这个领域，知道自己的方法站在什么位置，清楚相对已有工作的真实增量在哪里。
122	
123	### 4.2 结构要求
124	
125	- 把已有工作分成几个清晰的主题（如模型训练、推理增强、工具调用、数据构建、评测等）
126	- 每类简要说明：已有方法做了什么、解决了哪些问题、和本文的关系
127	- 帮助读者理解：哪些是本文直接继承的，哪些方法不同但解决相似问题，哪些留下了本文要解决的缺口
128	
129	### 4.3 禁忌
130	
131	- **禁止论文堆砌**：不要写成 "A proposed X. B proposed Y. C proposed Z." 的列表
132	- **目标不是展示读了多少论文**，而是做归纳和比较
133	- Contribution claim（"To our knowledge, no prior work..."）应放在 Introduction，不在 Related Work
134	
135	### 4.4 引用充足度
136	
137	- 引用必须覆盖：**直接相关方法、baseline 论文、评测 benchmark 论文、理论基础**
138	- 任何一类缺失，审稿人会立刻看出来调研不充分
139	- 引用密度参照目标会议近年录用论文的量级——明显偏少意味着 Related Work 调研不足
140	
141	---
142	
143	## 五、去 AI 写作风格（硬规则）
144	
145	以下模式是 AI 生成文本的典型标志，审稿人一眼能看出。**必须全部消除。**
146	
147	### 5.1 严禁破折号（最显著的 AI 痕迹）
148	
149	**这是 AI 写作最容易被识别的标志，审稿人最敏感。单列为最高优先级硬规则。**
150	
151	- 解释性 em-dash（—，U+2014）和 en-dash（–，U+2013）必须**全部删除**
152	- 替代方式：用逗号、括号或拆分为两个句子
153	- 强制检查命令：
154	  ```bash
155	  grep -n "—" paper/*.tex     # em-dash，每处人工判断是否必要
156	  grep -n " – " paper/*.tex   # 解释性 en-dash，几乎都应删除
157	  ```
158	- 例外（允许保留）：表格分隔符、数字范围（`2020–2024`、`pp. 12–18`）、专有名词（`Newton–Raphson`）
159	
160	### 5.2 段落与句式
161	
162	- **禁止过度分段**：不需要每 2-3 句就换段，自然段 5-8 句是正常的
163	- **减少关系从句**（which, that, who）：能用简洁直接的句子就不用从句
164	- **禁止 -ing 短语结尾**：如 "..., highlighting the applicability of..." / "..., demonstrating the effectiveness of..."。这是 AI 写作最典型的标志之一
165	- **禁止连续使用 "Furthermore" / "Moreover" / "Additionally"**：一段内最多用一个过渡词
166	- **避免 "It is worth noting that..." / "Notably, ..."**：直接写要说的内容
167	
168	### 5.3 用词黑名单
169	
170	- 避免 "delve into" / "leverage" / "utilize" / "facilitate" — 用 "explore" / "use" / "enable"
171	- 避免 "a myriad of" / "a plethora of" — 用 "many" / "various"
172	- 避免 "in the realm of" / "in the context of" — 直接说
173	- 避免 "paradigm shift" / "novel" 过度使用
174	
175	### 5.4 校对清单（4 步）
176	
177	1. 全文 proofread 语法和拼写
178	2. 检查所有代词/指示词（this, that, it）是否指代明确
179	3. **`grep "—"` + `grep " – "` 全文清零**（删除所有解释性 dash，§5.1）
180	4. `grep "ing,"` 模式——大部分 -ing 分词短语需要改写
181	
182	---
183	
184	## 六、图表与视觉规范
185	
186	### 6.1 知识密度原则
187	
188	- **图表的信息必须紧凑**——不能为了美观而留大量白空间
189	- 一张图如果只传达一个简单信息，要么缩小要么合并到其他图中
190	- 能用 inline text 说清的不要占一整个 Figure
191	
192	### 6.2 表格规范
193	
194	- 表格和正文文字不能视觉重叠（检查 column 宽度和 alignment）
195	- 小数精度全表统一
196	- 最优加粗、次优下划线
197	- Caption 必须自包含
198	
199	### 6.3 图片规范
200	
201	- 数值标签不能被线、bar、点遮住——用白色背景或偏移标签
202	- 图中字体 >= 7pt（打印后仍可读）
203	- 栏宽约束需匹配目标 venue 模板要求
204	- 概念图/流程图要有信息量，不要画一个 trivial 的 pipeline 然后占半页
205	
206	### 6.4 空间效率
207	
208	- 顶会正文页数严格受限（具体页数查目标会议官网），每 cm² 都是宝贵资源
209	- 优先使用 `\subfigure` 合并相关图
210	- Table 能 inline 就不要单独浮动
211	- 图表占比与其对叙事的贡献成正比
212

248	7. 所有专有名词有定义
249	8. 无 AI 风格标志（dash、-ing phrases、过度分段）
250	9. 图表知识密度高、无视觉遮挡

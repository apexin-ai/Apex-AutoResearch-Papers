## D061: 条件 Granger 分析脚本（CPU 任务）

### 背景
当前 Granger 分析证明 token_entropy → diversity 和 ECE → diversity 都显著。但没有区分 token_entropy 和 ECE 提供的是独立信息还是冗余信息。条件 Granger（控制一个 canary 后测另一个）可以回答这个问题。

### 目标
用现有 α=1.0 seed 42 数据，执行两组条件 Granger 分析：
1. 控制 ECE 后，token_entropy → diversity 是否仍显著（残差 Granger）
2. 控制 token_entropy 后，ECE → diversity 是否仍显著

### 数据位置
MVP seed 42 数据（Pythia-410M, WikiText, α=1.0, 10 gen）:
- 可能在 /root/autodl-tmp/distrib_canary_collapse/results/mvp_v4_rep42/

### 方法：残差 Granger / 条件 Granger

标准 Granger: Y ~ Y_lag + X_lag（如果 X_lag 系数显著则 X Granger-causes Y）

条件 Granger（控制 Z）: 
1. 对 X 和 Y 分别回归 Z_lag，取残差 X_resid 和 Y_resid
2. 对 Y_resid 做 Granger 检验 with X_resid_lag
3. 或者直接用 VAR(3): Y ~ Y_lag + X_lag + Z_lag，比较是否 X_lag 显著

更标准的做法：用 3 变量 VAR
- Restricted model: Y ~ Y_lag + Z_lag（只有控制变量）
- Unrestricted model: Y ~ Y_lag + Z_lag + X_lag（加入测试变量）
- F-test 比较两个模型

## Core Problem

Current retrieval-augmented reasoning systems issue uniform retrieval queries regardless of intent — the same answer-seeking query formulation is used whether the model needs new information or needs to verify an intermediate conclusion. This matters because verification moments are where retrieval is most impactful: in ReaLM-Retrieve (SIGIR 2026), only 31% of total retrievals are verification-type, yet 73% of successful retrievals occur at verification boundaries — yielding a ~2.4× enrichment ratio (73%/31%) that we calculate from the paper's raw statistics. Despite this, all queries at these critical moments use generic information-need formulation rather than claim-checking queries optimized for evidence retrieval. Recent work either rewards faithful reasoning over already-retrieved content with consistently negative results on multi-hop QA (VERITAS) or refines documents post-retrieval with uniform query generation (OThink-SRR1) or generates reasoning-informed queries without differentiating query purpose (DualRAG) or jointly optimizes reasoning with document ranking without differentiating query purpose (CoSearch) or optimizes when-to-search decisions without changing query formulation (HiPRAG). No existing multi-hop QA system generates queries whose formulation is explicitly differentiated by purpose — answer-seeking for information gathering vs. claim-checking for verification of intermediate reasoning steps.

## Opportunity / Why Now

ReaLM-Retrieve (SIGIR 2026) demonstrated that verification-type retrievals constitute only 31% of all retrieval calls, yet 73% of successful retrievals occur at verification boundaries — from which we calculate a ~2.4× enrichment ratio (73%/31%), indicating that verification moments are disproportionately high-value for retrieval. However, these verification-moment queries use generic information-need formulation identical to answer-seeking queries, leaving evidence quality for claim-checking suboptimal. VERITAS (arXiv 2510.13272, Feb 2026) integrated faithfulness rewards into RL training, but results on multi-hop QA are consistently negative: on MuSiQue EM, all faithfulness reward variants decrease performance relative to the Search-R1 baseline of 0.201 — Info-Think drops to 0.193, Think-Ans drops to 0.193, and Combined (Info-Think+Think-Ans) achieves only 0.194. This demonstrates that rewarding faithful reasoning over existing evidence consistently hurts multi-hop QA accuracy, and the bottleneck lies in what is retrieved rather than in how the model reasons about it. This directly motivates VTR's approach of changing what is retrieved at verification moments. DualRAG (ACL 2025) introduces reasoning-augmented querying (RaQ) that generates queries informed by the current reasoning state, achieving 56.3 F1 on MuSiQue and 65.7 F1 on HotpotQA with Qwen2.5-72B — but all queries are uniform in type, with no distinction between information-gathering and verification purposes. HiPRAG (ICLR 2026) optimizes when-to-search decisions via hierarchical process rewards, reducing over-search from 27% to 2.3% — but does not modify query formulation at all, making it complementary to VTR (HiPRAG: when to search; VTR: what type of query). OThink-SRR1 (arXiv 2604.19766, March 2026) introduces GRPO-IR with a Refine stage that distills retrieved documents, but operates entirely post-retrieval with uniform query generation (29.85 F1 on MuSiQue, 7B). CoSearch (arXiv 2604.17555, April 2026) jointly trains reasoning and document ranking via GRPO, improving MuSiQue F1 to 0.334 (7B) — but improves retrieval quality through ranker adaptation rather than query differentiation. Critically, the fact-checking retrieval literature validates that claim-as-query retrieval is effective: FEVER systems routinely retrieve evidence using claims with BM25 and dense retrievers; +VeriRel (arXiv 2508.11122) shows verification feedback improves retrieval recall by ~7 points on SciFact; the M3 dense retrieval system uses claims as queries with DPR. This creates a clear opportunity: optimizing query formulation specifically for verification moments — where retrieval already shows a ~2.4× enrichment ratio — should yield outsized gains on both answer quality and reasoning faithfulness.

## Landscape (SOTA & Limitations)

ReaLM-Retrieve (SIGIR 2026) achieves 71.2% F1 on MuSiQue and 71.8% F1 on HotpotQA with DeepSeek-R1-Distill-Qwen-32B using step-level uncertainty-triggered retrieval (RSUS), averaging only 1.8 retrieval calls. Analysis reveals that 31% of total retrievals are verification-type and 73% of successful retrievals occur at verification boundaries (from which we calculate a ~2.4× enrichment ratio), but all queries use a single-layer transformer decoder formulating information-need queries. VERITAS (arXiv 2510.13272, Feb 2026) integrates faithfulness reward types (information-think, think-answer; think-search evaluated but excluded from training) into PPO training of Qwen2.5-7B. Results on MuSiQue are consistently negative: all faithfulness reward variants decrease EM relative to the baseline — Search-R1 baseline achieves 0.201 EM (Table 6), while +Info-Think drops to 0.193, +Think-Ans drops to 0.193, and +Info-Think+Think-Ans achieves only 0.194. Table 1 confirms this pattern with a lower baseline of 0.196 EM and variants at 0.193-0.194. This demonstrates that rewarding faithful reasoning over existing evidence consistently hurts multi-hop QA accuracy, motivating the need to change what is retrieved rather than only how the model reasons about it. DualRAG (ACL 2025, arXiv 2504.18243) introduces a dual-process framework coupling Reasoning-augmented Querying (RaQ) with progressive Knowledge Aggregation (pKA), achieving 56.3 F1 on MuSiQue, 65.7 F1 on HotpotQA, and 77.3 F1 on 2WikiMultihopQA (Qwen2.5-72B-Instruct); a fine-tuned 7B variant achieves 64.1 F1 on HotpotQA. RaQ generates reasoning-informed queries by identifying key entities and knowledge gaps, but does not differentiate queries by purpose (all queries are information-seeking), leaving verification moments unoptimized. HiPRAG (ICLR 2026, arXiv 2510.07794) applies hierarchical process rewards to Search-R1, optimizing when-to-search decisions: reducing over-search from 27% to 2.3% while achieving 34.1% on MuSiQue and 62.4% on HotpotQA (Qwen2.5-7B). HiPRAG is complementary to VTR — it addresses when to search; VTR addresses what type of query to generate when a search is triggered. OThink-SRR1 (arXiv 2604.19766, March 2026) proposes GRPO-IR rewarding evidence identification while penalizing excessive retrievals, achieving 29.85 F1 on MuSiQue (Qwen2.5-7B) with 2.35 retrieval calls; its Refine stage distills documents post-retrieval but issues uniform queries. CoSearch (arXiv 2604.17555, April 2026) jointly trains reasoning agent and generative document ranker via GRPO with semantic grouping, achieving 0.334 F1 on MuSiQue and 0.595 F1 on HotpotQA (Qwen2.5-7B) — representing the strongest 7B-class baseline. CoSearch improves retrieval quality through ranker adaptation (retriever side) but does not differentiate query formulation by purpose (query side), making it complementary to VTR. HARIS (arXiv 2506.07528) trains cooperative Qwen3-4B agents via GRPO for claim verification, achieving 80.12 F1 on EX-FEVER and 69.31 F1 on HOVER — but targets standalone claim verification with factual sub-questions rather than intermediate reasoning steps in multi-hop QA. ReAgent (EMNLP 2025) implements multi-agent verification with backtracking via GPT-4o (51.5% F1 MuSiQue, 79.5% F1 HotpotQA), verifying against already-retrieved knowledge. +VeriRel (arXiv 2508.11122) demonstrates that verification feedback improves document retrieval recall for scientific fact-checking (62.2% vs 55.0% Recall@1 on SciFact), validating that verification-oriented signals enhance evidence quality. CFR (FEVER Workshop 2024) demonstrates that contrastive fine-tuning of retrievers on claim-evidence pairs yields 6% improvement in veracity classification, validating lightweight adaptation for claim-based retrieval. In the fact-checking retrieval literature more broadly, FEVER systems and M3 dense retrieval routinely use claims as queries, demonstrating that claim-based retrieval is effective with both BM25 and dense retrievers. The retrieval-reasoning survey (arXiv 2601.00536) analyzing 104 papers confirms no system explicitly distinguishes query formulation by purpose for intermediate reasoning steps.

## Proposed Approach

We propose Verification-Triggered Retrieval (VTR), a dual-mode retrieval extension of the Search-R1 RL framework that trains a single model to generate purpose-differentiated queries for multi-hop reasoning.

**Architecture:**
- **Base model**: Qwen3-8B with LoRA adapters (rank 32). HARIS's successful RL training of Qwen3-4B on search-reasoning tasks validates this model family; we scale to 8B for higher-quality NLI-style query generation.
- **Dual-mode query generation (core novelty)**: The RL-trained model learns to produce two types of queries triggered by step-level uncertainty: (a) answer-seeking queries (standard: 'what is X?', 'who did Y?') for information gathering, and (b) verification queries (claim-checking: 'evidence that [claim from reasoning step]', 'evidence supporting or contradicting that [X caused Y]') for checking intermediate conclusions. Mode selection emerges through RL training — no hard-coded rules.
- **Claim extraction**: Inline during reasoning — when the model detects uncertainty at a reasoning step, it extracts the key claim as an atomic verifiable statement within its chain-of-thought before formulating the verification query. No separate model required.
- **Positioning relative to DualRAG and HiPRAG**: DualRAG's RaQ generates reasoning-informed queries but treats all queries uniformly (no purpose differentiation); VTR's novelty is in differentiating the query type based on intent (answer-seeking vs. claim-checking). HiPRAG optimizes when to search; VTR optimizes what query to issue — these are orthogonal and combinable.

**Retriever compatibility:**
The effectiveness of claim-based queries with standard retrievers is supported by three lines of evidence: (1) **BM25 term-overlap**: NLI-style queries ('evidence supporting that [X caused Y]') preserve key entity and predicate terms from the claim, providing sufficient lexical overlap for BM25 matching — this is exactly how FEVER systems retrieve evidence using claims as queries. (2) **Dense retriever effectiveness**: M3 and DPR-based systems demonstrate that dense retrievers trained on claim-evidence pairs handle claim-as-query retrieval effectively. (3) **Verification-enhanced retrieval**: +VeriRel shows that integrating verification signals improves retrieval recall by ~7 points, suggesting the verification framing itself provides useful signal. For VTR, we adopt a hybrid BM25 + dense retrieval pipeline (Pyserini BM25 with BGE-base-en-v1.5 dense retriever), following the established finding that hybrid approaches improve recall 15-30% over single methods. **Risk mitigation**: The FEVER/+VeriRel evidence uses specialized corpora (Wikipedia, SciFact); performance on general multi-hop QA corpora (e.g., HotpotQA's full Wikipedia) is undemonstrated. If pilot experiments (first 2 days) show NLI-style queries underperform standard queries with our retrievers, we will train a lightweight contrastive adapter on synthetic claim-evidence pairs generated from the target corpus (~2 H100-hours additional), following CFR's validated approach of contrastive fine-tuning for claim retrieval.

**NLI scoring**: Off-the-shelf DeBERTa-v3-large cross-encoder scores retrieved verification passages as entailment/neutral/contradiction against extracted claims. Used only for reward computation during training — adds zero inference cost at deployment.

**Training (2-term GRPO reward):**
- Reward = answer correctness (F1) + intermediate claim faithfulness (proportion of verification-retrieved passages NLI-entailing extracted claims, scored by DeBERTa-v3-large).
- Retrieval count enforced as hard constraint (max 5 calls per question) rather than a third reward term, avoiding multi-objective instability.
- Built on Search-R1's veRL-based GRPO pipeline with retrieved-token masking.
- Key distinction from VERITAS: VERITAS rewards faithful reasoning about retrieved evidence — but ALL faithfulness reward variants consistently decrease MuSiQue EM (baseline 0.201; Info-Think 0.193; Think-Ans 0.193; Combined 0.194), demonstrating that rewarding faithful reasoning over existing evidence consistently hurts multi-hop QA accuracy. VTR addresses the upstream bottleneck by changing what is retrieved at verification moments.
- Key distinction from DualRAG: DualRAG generates reasoning-informed queries (knowing what information is needed) but does not differentiate query type by purpose; VTR generates purpose-differentiated queries (answer-seeking vs. claim-checking) where the formulation itself changes based on intent.
- Key distinction from HiPRAG: HiPRAG optimizes when to search via hierarchical process rewards; VTR optimizes what type of query to generate. These are complementary — future work could combine both.
- Key distinction from CoSearch: CoSearch improves retrieval quality through joint ranker training (retriever side); VTR improves through purpose-differentiated query formulation (query side). These approaches are complementary and combinable.
- Key distinction from OThink-SRR1/GRPO-IR: GRPO-IR rewards evidence identification in uniformly-retrieved documents; VTR rewards the generation of purpose-differentiated queries.

**Evaluation:**
- Primary benchmarks: MuSiQue and HotpotQA (multi-hop QA, 2-4 hops).
- Metrics: Answer F1 (standard) + Step-Level Faithfulness Score (SFS) — proportion of intermediate reasoning claims NLI-entailed by retrieved evidence. SFS validated by: (1) correlation with answer F1 across model variants (targeting Pearson r > 0.7), (2) agreement with DeBERTa-v3-large NLI baseline, and (3) retrieval precision at verification steps as a complementary diagnostic (measuring whether verification queries retrieve passages with higher claim-relevance than answer-seeking queries at the same reasoning steps).
- **Key ablations** (3 ablations): (i) VTR vs. uniform retrieval (Search-R1 baseline, no query differentiation), (ii) VTR vs. answer-only queries (same retrieval count but all queries answer-seeking — isolating the effect of verification query formulation), (iii) NLI-style verification queries vs. paraphrased re-queries (testing whether explicit claim-checking formulation matters vs. simply rephrasing the same question).
- **Baselines**: Search-R1 (uniform retrieval), VERITAS (faithfulness rewards without query change), OThink-SRR1 (post-retrieval refinement), CoSearch (joint ranker training without query differentiation), DualRAG (reasoning-informed but purpose-uniform queries; compared using reported numbers at 7B scale).

**Key empirical claim**: Purpose-differentiated NLI-style verification queries, trained end-to-end via RL in a single 8B model with hybrid retrieval, significantly outperform: (a) uniform retrieval baselines (Search-R1), (b) faithfulness-rewarded uniform retrieval (VERITAS), (c) post-retrieval refinement (OThink-SRR1), (d) joint ranker training without query differentiation (CoSearch), and (e) reasoning-informed but purpose-uniform queries (DualRAG at comparable scale) — demonstrating that optimizing query formulation for verification moments, where retrieval shows a ~2.4× enrichment ratio, yields outsized gains.

**Scope decisions**: (1) No retry/backtracking mechanism — deferred to follow-up. (2) No 2WikiMultiHopQA. (3) No human annotation — SFS validated via automated analysis. (4) Single-model architecture (no dual-agent design like HARIS) to demonstrate that query differentiation can emerge within one model.

6. **[Introduction — Confound 预判]** — 新增段落 address "context accumulation" 替代解释：verification moments 成功率高可能是因为到此阶段 context 已充分积累，而非 verification 行为本身有价值。回应方式：即使如此，claim-form queries 在 FEVER-style retrieval 中 recall 提升 15-20%，表明 formulation 优化本身有 headroom。同时区分两种机制：BM25 上的 lexical overlap 效应（assertion 与 Wikipedia 陈述句 surface token 重叠高）和 dense retriever 上的 NLI training bias（premise-hypothesis pairs in training data）。 — [命中 Novelty：机制清晰度从 ad hoc observation 提升为 theoretically grounded principle]

7. **[Introduction — Scope 声明]** — 新增：exploration/verification 是 "minimal viable taxonomy"，不是 exhaustive classification。更细粒度的 intent（disambiguation、contradiction detection、premise recovery 等）留作 future work。Multi-hop QA 是 testbed 而非 target application。 — [命中 Novelty + Significance：preempt "why only two modes?" 和 "only 2 datasets" 质疑]

8. **[§2 Related Work — FLARE/Self-RAG 显式定位]** — 原始 proposal 缺少对 FLARE 和 Self-RAG 的显式差异化。新增段落明确：FLARE 的 query 是将不确定 token 直接作为 query（本质是 answer-seeking formulation，asking "what comes next?"），Self-RAG 的 critique tokens 发生在 post-retrieval 阶段。VTR 的差异不在 "何时 retrieve" 而在 "retrieve 时用什么形式的 query"——一个 FLARE/Self-RAG 都未触及的维度。 — [命中 Novelty：封堵审稿人最可能第一时间提出的 "这不就是 FLARE 吗？" 质疑]

9. **[§2 Related Work — CoVe 显式定位]** — 新增 Chain-of-Verification（Dhuliawala et al., 2023）对比。CoVe 在验证环节生成 interrogative verification questions，VTR 的核心 claim 恰恰是 verification 应该用 declarative（assertion-form）而非 interrogative。CoVe 因此既是 related method 又是 VTR 核心假设的 empirical testbed（如果 assertion-form 胜出 → 直接验证 VTR 的设计原则）。 — [命中 Novelty：将高威胁相关工作转化为支持 evidence]

10. **[§2 Related Work — IR Intent 文献]** — 新增段落连接 Broder 2002 等经典 IR query intent taxonomy，明确 VTR 是将此理论从 user-facing search 迁移到 agent-internal reasoning retrieval 的首次尝试。 — [命中 Related Work 完整性 + Significance 理论深度]

11. **[§3.2 Method — RL vs. Rule-Based 论证]** — 原始 proposal 未预判 trivial alternative。新增显式论证段落：(1) 承认 rule-based reformulation（template prepend）是自然 baseline；(2) 论证 RL 的三重优势（联合学习 when+how、优化 retriever-effective 而非 human-intuitive 形式、end-to-end downstream alignment）；(3) 预判更强的 trivial alternative——positional heuristic + supervised claim extraction（T5-small），论证 verification moments 不 strictly 在后期出现且与 exploration 交织，positional heuristic 无法处理。(4) 声明 ablation (v) 直接测试此假设。 — [命中 Novelty：回答 "why do you need RL for this?" 这个最尖锐的 reviewer 问题]

12. **[§3.2 Method — NLI Reward 实现]** — 新增实现细节：batch NLI inference 策略、top-1 passage 评估（含 top-3 max ablation 对照）、~15% compute overhead 估算。 — [命中 Technical Soundness：回答 "is this practical?" 和 NLI 瓶颈担忧]

13. **[§3.2 Method — Retriever Scope 声明]** — 新增：VTR 的 formulation differentiation 对 lexical-heavy retriever（BM25 component）价值最显著，因为 surface form 直接影响 lexical matching。对纯 dense retriever 可能边际价值不同（boundary analysis 测试）。 — [命中 Novelty：展示作者深度理解方法的工作机制]

14. **[§4.2 Baselines — 大幅扩展]** — 原始 baseline 仅含 IRCoT、Search-R1、Self-RAG、DualRAG。新增：(a) FLARE（同 backbone，规则触发无需 RL，实现成本低）；(b) CoVe-style verification（interrogative verification questions，直接对比 VTR 的 assertion-form）。明确 Self-RAG 使用原始 SFT paradigm 复现 + 原论文数字参考。DualRAG 比较策略修正：首选在 8B 上复现 RaQ，同时标注原始 72B 数字。 — [命中 Technical Soundness：controlled comparison + compute fairness]

15. **[§4.3 Metrics — 修正评估体系]** — 原始 proposal 中 SFS（NLI-based）同时是 training reward 和 evaluation metric，构成循环依赖。修正：(a) Answer F1 为唯一主指标；(b) SFS 降为 diagnostic，明确标注 reward-aligned；(c) 新增独立 faithfulness 评估：GPT-4-as-judge（500 条采样 + self-consistency 报告）+ AlignScore 作为第二独立评估器；(d) 新增统计显著性要求：VTR/Search-R1 各 3 seeds，mean±std + paired bootstrap (p<0.05)。 — [命中 Technical Soundness：消除循环评估这一审稿人几乎必然攻击的缺陷]

16. **[§4.4 Ablations — 从 3 个扩展至 8 个]** — 原始仅 3 个 ablation（answer-only queries、verification-only queries、NLI-style queries）。新增 5 个关键 ablation：(iv) VTR w/o faithfulness reward（隔离 reward 设计贡献）；(v) Rule-based claim-as-query（测试 RL 增量价值）；(vi) NLI reward top-3 max vs. top-1（reward 信号质量）；(vii) Reward weight sensitivity β-γ grid on MuSiQue（RL robustness）；(viii) Random mode assignment at verification moments（解耦 detection vs. formulation 贡献）。 — [命中 Technical Soundness：覆盖几乎所有可预见的 ablation 追问]

17. **[§4.5 Analysis Suite — 全新章节]** — 原始 proposal 无系统性分析方案。新增完整分析 suite：(a) Motivation Validation：在 baseline 输出上复现 verification-step enrichment 现象；(b) Query Behavior Analysis：涌现频率、质量分类（200 条人工标注）、RL-emergent pattern characterization、binary taxonomy 外 queries 观察；(c) Verification Detector Reliability：NLI detector precision/recall vs. human gold；(d) Query Length Control Analysis：排除 length 混淆变量；(e) Boundary Analysis：pure dense retrieval 条件。 — [命中 Technical Soundness + Novelty：motivation validation 加固因果链，query behavior analysis 支撑 "discovery" novelty claim]

【主要风险】:

1. **"I would have guessed this" 质疑**（最高概率攻击点）：即使 related work 差异化做到位，"assertion-form queries work better for verification" 这个 insight 对熟悉 fact-checking/NLI 文献的审稿人来说 predictability 较高。防御靠 Layer 1（retrieval intent collapse 作为 formalized problem 的 standalone 贡献）和 Layer 3（RL 涌现 non-obvious patterns），但后者依赖实验结果——如果 RL 只学会 trivial reformulation，这个防线不成立。

2. **Core claim 实证风险**：整篇 paper 押注在 "RL 端到端学习 intent-aware formulation 优于 rule-based" 上。如果 Ablation (v) rule-based baseline 已经 capture 了 80%+ 的 gain，reviewer 会认为 RL machinery over-engineered，核心贡献大幅缩水。这是一个在实验前无法排除的根本风险。

【实施评估】:
  - **计算资源**: 4×A100 80GB 为最低配置。主实验（VTR 3 seeds + Search-R1 3 seeds + 其他 baselines）~200 GPU-hours；Ablation suite（8 个 ablation，部分仅需 inference）~150 GPU-hours；Analysis suite（NLI inference + GPT-4 judge）~$100-150 API 费用 + ~20 GPU-hours。总计约 370 GPU-hours。如有 8×A100 可将 wall-clock 压缩约 40%。
  - **数据需求**: MuSiQue 和 HotpotQA 均为公开数据集，无需额外获取。Wikipedia passage corpus 需构建 BM25（Pyserini）+ BGE-base（FAISS）hybrid index，HotpotQA full Wikipedia 5M+ passages 索引构建约 1-2 天。
  - **人工介入**: Query Behavior Analysis 中 200 条 verification queries 的质量分类需要人工标注（或高质量 LLM judge 替代）；GPT-4-as-judge 500 条 faithfulness 评估需要设计 prompt + 质量抽查。预估 1-2 人·周。
  - **训练需求**: 需要模型训练。Qwen3-8B + LoRA 的 GRPO 训练，每个完整 run 约 48-72 GPU-hours（3000 steps, batch 64）。含 3 seeds + ablations，总 RL 训练 runs 约 10-15 次。DeBERTa-v3-large 作为 reward model 无需额外训练（使用预训练 NLI checkpoint）。Self-RAG baseline 需 SFT 复现训练（额外 ~30 GPU-hours）。
  - **新 Benchmark**: 不需要构建新 benchmark。使用现有 MuSiQue + HotpotQA。Analysis Suite 中的 verification detector evaluation 和 query behavior analysis 属于 post-hoc 分析，不构成独立 benchmark。

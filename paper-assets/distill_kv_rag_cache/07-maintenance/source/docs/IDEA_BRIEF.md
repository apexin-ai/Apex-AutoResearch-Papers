## Core Problem

Production RAG systems redundantly reprocess ~75% of retrieved chunks across queries (Cache-Craft, SIGMOD 2025). Position-independent caching (PIC) avoids this recomputation by storing chunk KVs without positional encodings for arbitrary-position reuse, and MEPIC (arXiv 2512.16822) further reduces HBM usage by 2x over EPIC via RoPE fusion and NoPE storage — yet cached KV states remain at full precision. A single Llama-3.1-8B instance caching 100K chunks at 512 tokens each requires ~3.2TB of KV storage. Meanwhile, KV compression methods like KVTC (ICLR 2026) achieve 8-20x storage reduction via PCA decorrelation + adaptive quantization + entropy coding. MEPIC explicitly identifies KV compression as an orthogonal direction 'that can be seamlessly combined with existing KV compression methods,' and KV Packet (arXiv:2604.13226) demonstrates compatibility of adapter-based PIC with eviction-based compression — but both treat compression and restoration as independent stages. EVICPRESS (arXiv:2512.14946) jointly optimizes compression and eviction decisions at the system/storage-tier level via a unified utility function, applying conservative compression to compression-sensitive contexts — but operates at per-context granularity (which contexts to compress and where to place them), not at per-token algorithmic granularity (how many bits per token, which tokens to restore). No prior work jointly optimizes the per-token compression bit allocation with per-token restoration selection in the chunk-caching setting — compression and restoration are universally treated as independent stages at the algorithmic level.

## Opportunity / Why Now

MEPIC and KVTC share a structural element: both store KV without RoPE (NoPE format). MEPIC stores NoPE KVs for position-independent reuse with RoPE applied on-the-fly; KVTC removes RoPE before PCA compression. This alignment enables natural composition — KVTC compression applied to MEPIC's NoPE KV stores, with decompressed KVs fed into MEPIC's RoPE-fusion attention path. However, naive composition treats compression and restoration as independent stages, wasting compression bits on tokens that will be restored anyway and missing restoration opportunities on tokens with high compression error. We identify a bidirectional optimization opportunity: (1) At compression time, tokens in restorable positions (boundary tokens always recomputed by MEPIC, or tokens frequently selected by query-driven methods like ProphetKV) can tolerate aggressive compression since they will be replaced with fresh KVs — reallocating their bits to persistent tokens improves overall quality. (2) At restoration time, per-token compression error provides an orthogonal signal to query relevance for selecting which tokens to recompute — prioritizing tokens that are both query-relevant AND high-compression-error yields better quality per recomputed token. HeadQ (arXiv:2605.03562) demonstrates via null-space interventions (Section 5.2) that within a fixed quantization scheme, storage-space MSE in the attention-inert subspace can convert to real score damage for non-equivariant quantizers — motivating Fisher-weighted score-space error as the primary compression error metric rather than raw embedding-space MSE. Additionally, KVTC's PCA basis calibrated on full-sequence KVs is suboptimal for independently-encoded chunks due to distribution mismatch (local vs. global attention sinks, absent cross-chunk attention), motivating chunk-aware recalibration. KV Packet (arXiv:2604.13226, Section 4.4) demonstrates that adapter-based PIC is robust to eviction-based compression (CUR, KVzap, LeverageScore, TOVA) at 10-50% retention rates — but this tests token-pruning compression, not transform coding (PCA + quantization + entropy coding) at 8-20x rates, and does not optimize the compression-restoration interface. EVICPRESS (arXiv:2512.14946) jointly decides whether to compress and where to place KV caches across storage tiers, but treats each context as an atomic unit and does not modify per-token bit allocation or inform per-token restoration selection. 'Don't Waste Bits!' (CVPR 2026, arXiv:2604.04722) demonstrates the value of per-token adaptive bit allocation {2,4,8,16} using a learned controller, but operates on full-sequence KV caches without chunk caching or recomputation awareness. Our approach is the first to jointly optimize this interface at the algorithmic level.

## Landscape (SOTA & Limitations)

Position-independent KV caching: MEPIC (arXiv 2512.16822, Dec 2025) achieves 2x HBM reduction over EPIC via NoPE KV storage, block-level recomputation (first block per chunk is request-specific), and RoPE fusion in fused attention kernels; integrated into vLLM + LMCache serving stack; evaluated on Mistral-7B-Instruct-v0.3 across SQuAD, NewsQA, NarrativeQA, emrQA. EPIC (ICML 2025) recomputes k≤32 boundary tokens via LegoLink. ProphetKV (arXiv:2602.02579, Feb 2026) introduces user-query-driven selective recomputation, achieving 96-101% accuracy at 20% recomputation ratio; evaluated on Llama-3.1-8B, Qwen2.5-14B, Qwen-3-14B (thinking mode). QCFuse (arXiv:2604.08585, April 2026) uses semantic summary anchors to enhance query representations and selectively recomputes query-related tokens using attention distributions from the most critical transformer layer (middle layers); achieves 40% latency reduction over existing cache fusion baselines; implemented on SGLang with sparse-attention Triton kernel; criticizes ProphetKV's all-layer concurrent evaluation as disruptive to pipeline scheduling. InfoFlow KV (arXiv:2603.05353, March 2026) casts selective recomputation as an information flow problem using prompt-conditioned attention norms under inference-consistent RoPE geometry; does not consider compression. KVLink (NeurIPS 2025) adjusts RoPE positions with trainable link tokens. Cache-Craft (SIGMOD 2025) stores chunk KVs without RoPE. CacheSlide (FAST 2026) uses learned weights for cross-position-aware reuse. CacheBlend (EuroSys 2025) selectively recomputes tokens based on output deviation. KV Packet (arXiv:2604.13226, April 2026) uses trainable soft-token adapters for recomputation-free PIC; Section 4.4 tests compatibility with 5 eviction-based compression methods (CUR, KVzap, LeverageScore, TOVA, random pruning) at 10-50% retention, claiming PIC 'natively bypasses bottlenecks' of compression-impaired recomputation — but tests token eviction, not transform coding, and does not optimize the compression-restoration interface. CacheFlow (arXiv:2604.25080, April 2026) rethinks cache restoration as a 3D-parallel execution problem (tokens × layers × GPUs) with a batch-aware two-pointer scheduler; reduces TTFT by 10-62%; complementary to CompressLink (execution optimization vs. selection optimization) — CompressLink's restored tokens would benefit from CacheFlow's parallel execution. CacheFlow explicitly acknowledges compression as an orthogonal, unaddressed dimension. FusionRAG (PACMMOD/SIGMOD 2026) embeds cross-chunk information offline. A systematic CLC study (arXiv 2603.20218, March 2026) compared 11 chunk-level caching strategies but did not examine compression. KV compression: KVTC (ICLR 2026) achieves 8-20x compression via PCA decorrelation + adaptive quantization + entropy coding, removing RoPE before PCA; maintains <1pp accuracy drop at 20x on most tasks; bit allocation via DP minimizes reconstruction MSE; open-source implementation (OnlyTerp/kvtc) achieves 6-9x with high quality. RateQuant (arXiv:2605.06675, May 2026) applies rate-distortion theory for mixed-precision per-head quantization via reverse waterfilling, reducing KIVI's perplexity from 49.3 to 14.9 on Qwen3-8B at 2.5 bits with 1.6s calibration; principled bit allocation without PCA. eOptShrinkQ (arXiv:2605.02905, May 2026) achieves near-lossless compression via optimal spectral denoising + quantization, saving ~1 bit/entry. HeadQ (arXiv:2605.03562, May 2026) demonstrates that Fisher/score-space error predicts attention KL far better than raw key MSE, using null-space interventions (Section 5.2) to show that within a fixed quantization scheme, storage-space MSE in the attention-inert subspace converts to real score damage for non-equivariant quantizers; operates at per-head granularity with learned query-basis residual codes. DynaKV (arXiv:2603.04411, March 2026) provides per-token adaptive PCA rank via learned gating — requires fine-tuning (128M tokens), operates on full-sequence KVs. 'Don't Waste Bits!' (CVPR 2026, arXiv:2604.04722) demonstrates per-token adaptive bit allocation {2,4,8,16} with a learned controller; validates per-token granularity for compression but operates on full-sequence KVs without chunk caching or recomputation. 'Quantization Dominates Rank Reduction' (arXiv:2604.11501, April 2026) shows quantization outperforms dimension-discarding PCA projection but tests rank reduction, not decorrelation-before-quantization as KVTC uses. EVICPRESS (arXiv:2512.14946, Dec 2025, Microsoft Research) jointly optimizes KV cache compression and eviction via a unified utility function across storage tiers, applying conservative compression to compression-sensitive contexts — operates at per-context system-level granularity, not per-token bit allocation. Q-Hitter (MLSys 2024) combines quantization friendliness with attention importance for token selection in sparse-quantized KV cache, but optimizes what to keep (eviction), not what to restore (recomputation), and does not operate in the chunk-caching setting. CacheGen (SIGCOMM 2024) achieves 3.5-4.3x via tensor encoders. KVzip (NeurIPS 2025 Oral) provides 3-4x eviction-based compression. Joint Encoding of KV-Cache Blocks (Jan 2026) fuses similar blocks achieving 4.38x. No prior work jointly optimizes per-token KV compression bit allocation with per-token selective restoration token selection in the chunk-caching setting — compression and restoration are universally treated as independent stages at the algorithmic level.

## Proposed Approach

We propose CompressLink, a framework that co-optimizes KV compression and quality restoration for position-independent chunk caching, built on the shared NoPE representation of MEPIC and KVTC. CompressLink introduces two novel algorithms — Restoration-Aware Bit Allocation (RABA) and Compression-Error-Guided Restoration (CEGR) — that jointly optimize the compression-restoration pipeline, plus chunk-aware PCA calibration as a supporting technique. **Offline Compression Pipeline:** Each document chunk is independently encoded through the LLM; MEPIC stores the resulting KV caches in NoPE format. Before KVTC compression, PCA bases are calibrated on independently-encoded chunk KVs (matching inference-time distribution, addressing the calibration mismatch from full-sequence KVs). RABA then modifies KVTC's DP-based bit allocation: each token position is assigned a restoration probability p_r(t) based on positional priors — boundary tokens (first block per chunk, always recomputed by MEPIC) get p_r ≈ 1.0; tokens frequently selected across calibration queries by ProphetKV-style scoring get intermediate p_r; remaining tokens get p_r ≈ 0. The DP objective is modified from minimizing total reconstruction MSE to minimizing restoration-weighted MSE: sum over tokens t of (1 - p_r(t)) * MSE(t), so that bits are reallocated from high-restoration-probability tokens (whose compressed values will be overwritten) to persistent tokens (whose compressed values must survive). At 20% recomputation ratio, this effectively concentrates the full bit budget on 80% of tokens, improving quality where it matters. Implementation builds on the OnlyTerp/kvtc open-source repository, which provides PCA decorrelation, DP-based bit allocation (~40-line solver, cleanly modifiable for weighted MSE), and entropy coding (zlib/LZMA/rANS) achieving 6-9x compression with high quality. RABA modifies the DP solver's error function from `variance / (4^bits)` to `(1 - p_r(t)) * variance / (4^bits)`, a localized change. Compressed KVs (PCA transform → RABA-allocated quantization → entropy coding) are stored in LMCache's persistence layer. **Online Restoration Pipeline:** Retrieved chunks' compressed KVs are decompressed (entropy decode → dequantize → PCA inverse). CEGR computes per-token compression error estimates from decompression metadata. The primary variant (CEGR-Score) weights PCA components by their Fisher-information contribution to attention score space: error_c^score(t) = sum over components j of F_j * (Δ_j² / 12), where Δ_j is the quantization step size for component j at the allocated bit width and F_j is the Fisher weight of component j estimated during offline calibration from query-key score variance. This is motivated by HeadQ's null-space intervention evidence (Section 5.2): within a fixed quantization scheme, storage-space MSE in the attention-inert subspace converts to real score damage for non-equivariant quantizers (such as KVTC's uniform affine quantization). Fisher weighting ensures that CEGR prioritizes components that actually affect attention outputs, not those that merely inflate storage-space MSE. The Fisher weights F_j are precomputed per-head during offline calibration and stored alongside the PCA basis, adding negligible overhead. We additionally include CEGR-MSE (unweighted: error_c(t) = sum over j of Δ_j² / 12) as an ablation comparator to validate the value of score-space alignment. CEGR then combines the compression error signal with a query relevance signal r_q(t) obtained from a lightweight attention probe (single-layer attention of the query against decompressed keys, following ProphetKV's first-pass scoring). The joint restoration score is: score(t) = r_q(t) * error_c(t)^β, where β controls the compression-error sensitivity. Tokens with highest joint scores are selected for recomputation within the budget. The key insight: a query-relevant token with low compression error needs no recomputation (compression preserved it); a high-error token irrelevant to the query wastes recomputation budget. Only tokens that are both query-relevant AND high-error benefit maximally from recomputation. MEPIC's fused RoPE-attention kernel applies positional encodings on-the-fly during final attention computation over the mix of recomputed and decompressed KVs. **Joint Optimization Loop:** RABA and CEGR share the restoration probability model — RABA's p_r(t) at compression time is calibrated to match CEGR's empirical restoration rate at inference time. During calibration, we run CEGR on calibration queries to estimate per-position restoration frequencies, then feed these back into RABA's DP allocation. This creates a consistent compression-restoration contract: positions that CEGR frequently restores are precisely those where RABA saves bits. **Contributions:** (1) RABA — a novel restoration-aware bit allocation algorithm that extends rate-distortion-optimal quantization (cf. RateQuant's reverse waterfilling, KVTC's DP) with position-dependent restoration weights, provably reducing effective MSE on persistent tokens at matched total bit budgets. Differentiation from RateQuant: RateQuant allocates across heads, RABA allocates across token positions within each head; RateQuant is restoration-unaware. Differentiation from DynaKV: DynaKV allocates per-token PCA rank via learned gating (requires fine-tuning), RABA allocates per-token bit budget via restoration probability (training-free, calibration only). Differentiation from EVICPRESS: EVICPRESS jointly optimizes compression and placement at per-context system-level granularity; RABA operates at per-token algorithmic-level granularity within the compression codec. Differentiation from 'Don't Waste Bits!': per-token adaptive allocation with a learned controller on full-sequence KVs; RABA uses restoration probability weights without learning, specific to chunk caching. (2) CEGR — a novel compression-error-guided restoration algorithm that augments query-relevance-based token selection with compression error. The primary CEGR-Score variant aligns the error metric with model-visible score-space distortion via Fisher weighting, addressing HeadQ's evidence that storage-space MSE in the attention-inert subspace converts to score damage after quantization for non-equivariant quantizers. CEGR-Score requires zero additional forward passes — Fisher weights F_j are precomputed per-head and stored with the PCA basis; per-token error is computed analytically from decompression metadata. Differentiation from ProphetKV: ProphetKV selects on query relevance alone; CEGR adds the compression error dimension. Differentiation from QCFuse: QCFuse uses semantic summary anchors and critical-layer attention for query-centric selection but is compression-unaware; CEGR adds the compression error signal to any query-relevance method. Differentiation from CacheBlend: CacheBlend uses output deviation (requires early-layer forward passes); CEGR uses analytical error estimates (zero forward passes). Differentiation from InfoFlow KV: InfoFlow KV uses attention-norm for information flow; CEGR uses compression error — orthogonal signals. Differentiation from Q-Hitter: Q-Hitter combines quantization friendliness with attention importance for eviction (what to keep); CEGR combines compression error with query relevance for restoration (what to recompute after compression). (3) A joint optimization loop where RABA and CEGR share a restoration probability model — CEGR's empirical restoration frequencies on calibration queries feed back to RABA's bit allocation weights, creating a consistent compression-restoration contract. Additionally, chunk-aware PCA calibration addresses the distribution mismatch between full-sequence and independently-encoded chunk KVs (a supporting technique, not a main contribution). **Evaluation:** Primary model: Llama-3.1-8B-Instruct (full benchmark suite); secondary: Qwen2.5-7B-Instruct (perplexity + NaturalQuestions only). RAG benchmarks: NaturalQuestions, HotpotQA, MuSiQue. Long-context: LongBench, RULER. General quality: WikiText perplexity, C4 perplexity, MT-Bench. Capability: MMLU, HumanEval. Key ablation axes (7 axes): (a) compression ratio (4x, 8x; higher ratios noted as future work contingent on OnlyTerp/kvtc achieving >9x), (b) RABA vs. standard KVTC bit allocation (matched total bits), (c) CEGR-Score vs. CEGR-MSE vs. ProphetKV-only restoration (matched recomputation budget), (d) RABA+CEGR joint vs. each alone, (e) chunk-aware vs. full-sequence PCA calibration, (f) pure quantization baselines (RateQuant with reverse waterfilling, INT4/FP4 without PCA), (g) recomputation ratio (3%, 10%, 20%). Deferred to supplementary/camera-ready: chunk size ablation (256, 512, 1024 tokens), QCFuse and CacheBlend restoration baselines (discussed in related work). Baselines: (i) uncompressed MEPIC, (ii) naive MEPIC+KVTC (independent stages, full-sequence PCA), (iii) MEPIC+RateQuant (principled pure quantization without PCA), (iv) MEPIC+KVTC with chunk-aware calibration but no RABA/CEGR. Targets: 4-8x storage reduction with <2% quality degradation vs. uncompressed MEPIC at 20% recomputation budget. Wall-clock throughput measured on H100.

   原始 proposal 以 "no work jointly optimizes the per-token compression-restoration interface" 作为主打卖点，这是一个 meta-level 的 pipeline 改进声明，容易被判为 incremental。修改后以一个具体的、可验证的 empirical finding 领衔（"storage-space MSE systematically misrepresents quality impact due to Fisher weight concentration"），joint optimization 降级为这一发现驱动的工程后果。这把论文从 "系统集成" 重新定位为 "揭示并修正了领域内一个广泛使用的错误代理指标"。

2. [Introduction / 第 2-3 段] — **新增 motivating example figure：MSE ranking vs. Fisher-weighted error ranking 在 bridge entity token 上的不一致** — 命中 Novelty + Presentation Clarity
   原始 proposal 没有任何直观示例。新增一个具体 token 的 case（MSE 排序低 → Fisher-weighted error 排序高 → 恰好是 multi-hop 推理的 bridge entity），让审稿人在第一页就直觉理解为什么 joint reasoning about compression damage 产生质性不同的 restoration 决策。

3. [贡献结构 / Contributions] — **贡献顺序重构：CEGR-Score 升为 C1（flagship），RABA + joint calibration loop 合并为 C2，CompressLink framework + NLP-grounded analysis 为 C3** — 命中 Novelty 感知
   原始 proposal 将 RABA 放在第一贡献位置，但 RABA 的核心洞察（"将被 restore 的 token 不需要高精度压缩"）一旦将 MEPIC + KVTC 摆在一起几乎是 self-evident。CEGR-Score 的 Fisher-weighted error scoring 技术深度更强，应作为 flagship 呈现。原始 Contribution 3（joint loop）作为独立贡献分量不足，合并入 RABA 作为其 joint calibration 机制。

4. [方法 / CEGR 部分] — **将 Fisher-weighted compression error 从实现细节提升为独立方法论 insight，新增 Fisher weight 分布分析实验** — 命中 Analysis Depth + Novelty
   原始 proposal 将 Fisher weighting 埋在 CEGR 的技术描述中。修改后将 "Fisher weights exhibit long-tailed distribution → MSE is misleading proxy" 拎出来作为独立发现，新增实验：(a) 跨 head/layer 的 Fisher weight 分布可视化，(b) top-k MSE token vs. top-k Fisher-weighted error token 的 overlap 率量化。

5. [方法 / CEGR 部分] — **新增 multiplicative vs. additive combination 的设计论证和 ablation** — 命中 Technical Soundness
   原始 proposal 只写了 multiplicative scoring 而未解释为什么不用 additive。新增论证："a token with zero query relevance should never be restored regardless of compression error — multiplicative guarantees this, additive does not"。配合 additive variant ablation 实验验证。

6. [方法 / CEGR 部分] — **新增 Fisher weight 跨 query 分布稳定性 ablation** — 命中 Technical Soundness
   原始 proposal 未讨论预计算的 Fisher weights 在不同 query 分布下是否稳定。新增 cross-dataset ablation：NQ-calibrated vs. HotpotQA-calibrated Fisher weights 的 Spearman correlation，验证 query-agnostic Fisher weights 的泛化性。

7. [方法 / CEGR 部分] — **明确与 HeadQ 的关系差异化** — 命中 Related Work / Novelty 定位
   原始 proposal 引用 HeadQ 的 null-space 发现来 motivate 设计，但未明确区分 application context。新增显式说明：HeadQ 在 quantization scheme design 层面发现 null-space 问题，CEGR 在 restoration selection 层面利用 Fisher information——不同的应用语境，非简单套用。

8. [方法 / RABA 部分] — **新增 bit floor 机制（最低 2-bit）应对 query-agnostic fragility** — 命中 Technical Soundness
   原始 proposal 未讨论 RABA 的 structural fragility：静态 restoration probability 来自离线 calibration，当某 query 不 restore 某个被分配极低 bit 的 token 时，该 token 表示已被严重损坏且不可恢复。Bit floor 保证最坏情况下的质量下界。

9. [方法 / RABA 部分] — **新增 joint calibration loop 的迭代收敛性分析** — 命中 Technical Soundness
   原始 proposal 未讨论 RABA-CEGR 联合循环的收敛性（正反馈循环风险）。新增：(a) 迭代映射形式化 p^(t) → RABA(p^(t)) → error^(t) → CEGR frequency → p^(t+1)，(b) convergence ablation（1/2/3/5 iterations），(c) 明确 "1-2 iterations suffice" 的实践结论。

10. [方法 / RABA 部分] — **新增 "elbow effect" 假设的精确交叉点量化实验** — 命中 Experimental Rigor + Novelty
    原始 proposal 仅模糊地声称 joint optimization 优于 independent。修改为一个精确的实验预测：在哪个 compression ratio 上 independent pipeline 急剧退化而 joint 保持稳定。在 Llama 和 Qwen 上验证交叉点一致性（跨模型可复现则暗示 model-agnostic 现象）。

11. [方法 / Proposition 1] — **从 "theoretical foundation" 降级为 "formalization and motivation"，不声称理论贡献** — 命中 Technical Soundness（避免扣分）
    原始 proposal 没有形式化。第 1 轮新增了 rate-distortion-under-partial-recomputation 的 Proposition，但联合优化优于独立优化在数学上近乎 trivially true（联合搜索空间包含独立搜索空间）。将其明确定位为 motivational formalization，理论的实际价值通过 Oracle gap 的 empirical 量化来兑现，而非靠命题本身。

12. [实验 / Baseline] — **QCFuse 和 CacheBlend 对比从 supplementary 提升到主文；新增 CEGR-Error-Only + Oracle restoration baseline** — 命中 Experimental Rigor
    原始 proposal 将 QCFuse/CacheBlend 推到 supplementary，但这两个恰恰是最能体现 CEGR 优越性的对照组。新增 CEGR-Error-Only baseline（query-agnostic, top-k by compression error）构成 {query-only, error-only, joint} 的完整 ablation。Oracle restoration（事后最优 token 选择）作为 upper bound 给出 CEGR 的 headroom。

13. [实验 / Benchmark 选择] — **MT-Bench、MMLU、HumanEval 移至 appendix，主表聚焦 RAG-relevant benchmarks；新增 end-to-end RAG pipeline 评估** — 命中 Experimental Rigor + Venue Fit
    原始 proposal 包含多个与 RAG chunk caching 关联度低的 benchmark。修改后主表聚焦 NaturalQuestions、HotpotQA、MuSiQue、LongBench、RULER + perplexity（WikiText、C4）。新增 end-to-end RAG 评估（Contriever + reranker + LLM），直接回答 "does this matter in a real RAG pipeline?"。

14. [实验 / RABA robustness] — **新增 cross-distribution robustness 实验（calibration NQ → test MuSiQue）+ bit floor 对比** — 命中 Technical Soundness
    原始 proposal 未测试 RABA 的 query-agnostic allocation 在 distribution shift 下的表现。新增实验量化 sensitivity 并展示 bit floor 的保护效果。

15. [实验 / 展示方式] — **新增 Pareto frontier 可视化（compression ratio × recomputation budget × quality）** — 命中 Experimental Rigor + Presentation
    原始 proposal 只有单点 claim（"4-8x with <2% degradation"）。Pareto frontier 展示 CompressLink vs. baselines 在整个 trade-off 空间的支配关系，信息量远大于单点对比。

16. [实验 / 正文 vs. Appendix 规划] — **显式规划主表 vs. appendix 分配** — 命中 Presentation / Feasibility
    原始 proposal 列出 7 个 ablation axes 但未规划展示空间。修改后主文 3 个关键 ablation 表 + Pareto frontier figure + Fisher weight figure + bridge token case study figure，其余推到 appendix 并在正文用 1 句话总结 takeaway。

17. [Contribution 3 / NLP 分析] — **新增 reasoning-type stratified analysis + bridge token case study + linguistic error case study** — 命中 Venue Fit + Analysis Depth
    原始 proposal 的评估是纯 accuracy/perplexity 报告，缺乏 NLP-specific analysis。新增：(a) HotpotQA/MuSiQue 上 single-hop vs. multi-hop 分层，(b) bridge token case study（20-30 examples + NER 工具辅助），(c) compression-induced linguistic error 分类（entity confusion / coreference failure / temporal reasoning breakdown），(d) 与 RAG faithfulness 文献（SAFE, FActScore）的连接——"lossy KV compression as an unrecognized source of RAG hallucination"。

18. [Related Work] — **新增 architectural approaches（MLA/GQA/CLA）和 token pruning/merging 方法的讨论** — 命中 Related Work 覆盖
    原始 proposal 的 related work 集中在 KV compression/restoration 领域内。新增差异化讨论：(a) 架构方法（需要模型重设计和重训练 vs. CompressLink post-hoc、model-agnostic、无需训练），(b) token pruning/merging（lossy eviction 不可恢复 vs. CompressLink 保留恢复能力）。

19. [实验 / 压缩比] — **删除 hedging 语言，明确 target 6-10x system-level，引入 effective compression ratio 指标** — 命中 Technical Soundness / Feasibility
    原始 proposal 写 "if higher compression is not achievable, evaluation proceeds at 4-8x with higher ratios noted as future work"，暴露不确定性。修改为明确 target（6-10x system-level, 5-8x on persistent tokens），并引入 effective compression ratio（考虑 recomputation overhead 后的 net compression），让 reviewer 看到 full picture。

20. [Framing / Abstract-Intro] — **Research question 从 "building a better compression system" 调整为 "understanding how compression interacts with language understanding"** — 命中 Venue Fit
    原始 proposal 的 framing 偏 systems。修改后 abstract/intro 前置 NLP research question，将 CompressLink 定位为既是一个高效系统、也是一个揭示 compression-language interaction 的研究工具。

【主要风险】:

1. **Novelty 的 "可预见组合" 质疑**。即使叙事重组后以 Fisher 长尾发现领衔，审稿人仍可能认为：(a) HeadQ 已经指出 null-space MSE 问题，CEGR 是其 direct application；(b) RABA 的 "restoration-aware bit allocation" 在 MEPIC+KVTC 背景下是 natural next step；(c) 整体贡献是 "careful engineering with solid analysis" 而非 "surprising new insight"。这是该论文在 EMNLP 主会面临的最大风险——方法论层面的 novelty increment 是否足以跨过 main conference 门槛，取决于审稿人对 "principled integration + empirical finding" 类型贡献的接受度。

2. **Venue fit 争议**。核心算法贡献（CEGR Fisher weighting、RABA DP 修改）本质是 compression/systems 优化，NLP-specific analysis（bridge token case study、linguistic error categorization）是后加的分析层。如果审稿人认为 NLP insights 是 "post-hoc decoration" 而非 "core contribution"，可能建议 "better suited for ICLR/NeurIPS/MLSys"。end-to-end RAG evaluation 和 bridge token analysis 能部分缓解但无法完全消除此风险。

【实施评估】:
- **计算资源**: 需要至少 1 台 H100 80GB（或等效）用于 Llama-3.1-8B-Instruct 和 Qwen2.5-7B-Instruct 的推理评估。PCA calibration、Fisher weight 计算、RABA DP 优化均为 CPU-bound 的离线计算（calibration dataset 上单次前向传播 + 统计量提取）。end-to-end RAG pipeline 评估（Contriever + reranker + LLM）需要额外推理计算。Pareto frontier 实验需在多个 compression ratio × recomputation budget 组合下重复评估，预估总推理时间 200-400 GPU hours（H100）。无需大规模训练。
- **数据需求**: NaturalQuestions、HotpotQA、MuSiQue、LongBench、RULER、WikiText、C4 均为公开数据集。end-to-end RAG 评估需要预编码的 passage corpus（如 Wikipedia chunks），可用现有 Contriever 预编码结果。calibration 使用上述数据集的子集。全部数据公开可得。
- **人工介入**: Bridge token case study 需要对 20-30 个 representative examples 进行人工审核 / 质量检查（约 1-2 人天）。Linguistic error case study 需要人工对 compression-induced errors 进行分类标注（entity confusion / coreference failure / temporal reasoning breakdown），约 2-3 人天。Fisher weight 分析和 ablation 实验为全自动。总人工约 3-5 人天。
- **训练需求**: **无模型训练**。CompressLink 完全是 post-hoc、inference-time 的框架。所有组件（PCA basis、Fisher weights、RABA bit allocation、CEGR scoring）均通过离线 calibration 在预训练模型上计算，不修改模型参数。
- **新 Benchmark**: 不需要构建新 benchmark。使用现有公开 benchmark 组合。评估方法学（reasoning-type stratified analysis、MSE proxy critique metric）是分析框架而非新数据集。
- **预估周期**: 代码实现（基于 OnlyTerp/kvtc + MEPIC 开源代码）约 3-4 周；calibration + 全套实验（10 benchmarks × 多 ablation × 2 models × Pareto sweep）约 3-4 周；NLP analysis（Fisher 分布、bridge token case study、linguistic error study）约 1-2 周；论文写作 2-3 周。**总计约 10-13 周（2.5-3 个月）**，适配 EMNLP 2026 投稿时间线（假设 2026 年 6 月前启动）。

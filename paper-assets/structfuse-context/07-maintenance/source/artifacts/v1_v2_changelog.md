# Stratified Dry-Run v1 → v2 差异溯源

## 根因

**`mock_predictions()` 中使用 `hash(strategy)` 构造 RNG seed，Python 3 字符串 hash 在不同进程间非确定性（PEP 456），导致两次运行产生不同的 mock ranks。**

```python
# analyze_stratified.py:271
def mock_predictions(val_samples, strategy, seed):
    rng = np.random.RandomState(seed + abs(hash(strategy)) % 10000)  # ← 问题在这里
```

`hash("random")` 在 v1 进程和 v2 进程中返回不同值（除非设置 `PYTHONHASHSEED=0`），导致 `np.random.RandomState` 的 seed 不同，进而 mock 出的 rank 序列完全不同。

### 辅助证据

1. **所有 stratum 的样本数（count）完全一致** — 数据加载、分层逻辑、bin 边界均未改变
2. **所有维度的所有策略都有数值偏移** — 不是某一个 stratum 的问题，是全局性的
3. **bin 边界定义在两次输出的 config 中完全相同** — 排除分层逻辑变更

### 次要变更：v2 新增 2 个分析维度

v2 脚本在原有 3 维（repo_size, pool_size, similarity）基础上新增：
- `by_dataflow`：structural data availability（sparse/moderate/rich）
- `by_neg_difficulty`：neg_difficulty quartile（Q1_easy/Q2/Q3/Q4_hard）

这些新增维度**不影响已有维度的计算**，因为分层和指标计算是独立的。

## v2 为 Ground Truth 的依据

1. v2 是最终版本脚本的输出，包含完整的 5 维分析
2. 两次都是 dry-run mock 数据，**不存在哪个"更正确"的问题**——都是合成预测
3. v2 的脚本更完善（包含 dataflow + neg_difficulty），应以 v2 为基准
4. 如需复现 v2 结果，需在同一进程中运行或设置 `PYTHONHASHSEED=<fixed_value>`

## 修复建议

将 `mock_predictions` 的 seed 构造改为确定性方式：

```python
# 当前（不确定性）
rng = np.random.RandomState(seed + abs(hash(strategy)) % 10000)

# 修复方案
STRATEGY_SEED_OFFSET = {"random": 0, "embedding_distance": 1, "dataflow_aware": 2}
rng = np.random.RandomState(seed + STRATEGY_SEED_OFFSET[strategy] * 10000)
```

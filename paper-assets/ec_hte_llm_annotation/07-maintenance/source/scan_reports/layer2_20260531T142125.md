## 3. 科研目标达成度分析

### 3.1 Idea → Findings 的逻辑链

**原始 idea** (IDEA_BRIEF.md, idea_037 from foreign source)：
- Mozer 2026 解决了 ATE 下的 differential prediction error，但对 CATE 仍是 open problem
- 提出 EC-HTE：HB stratified CM + honest causal forest + adaptive annotation allocation
- Validation: 半合成 + Ashwin Rohingya 真实数据

**最终论文 claim**：
- Theorem 1 (bias identity δ_s·Δτ/(1-2π̄))
- Sign reversal 14.9% configurations
- EC-HTE 7.4× bias reduction（仅在 extreme heterogeneity + K=2）
- Diagnostic Proposition 5（AUC 0.86 对称 / 0.66 非对称）

**对照原始 idea**：原始定位是"EC-HTE 方法 + 完整 validation"，但项目历经至少 **3 次 reframe**：
1. **D001 → D002/D003**（5/20）：Round 1 Dream 把 novelty 重定位为 "problem-identification" 而非 "new technique"
2. **D023**（5/23 20:40）：第三次 Dream 因真实数据负面证据促使"reframe paper from EC-HTE method to (1) exact bias identity + (2) actionable diagnostic"
3. **D027**（5/24 13:03）：exp-041 asymmetric 全面负面后，把 asymmetric retreat 定义为 "operating condition"

每次 reframe 都是**被迫**而非主动——核心驱动力是负面实验证据（exp-015/016/024/028/041）和 Reviewer 反复施压。

**Idea 偏离合理性**：原始 idea 的 Ashwin 真实数据计划没做（"requires author email + IRB, not feasible within 5-day DDL"，D004），用 UCB Hate Speech / CivilComments / TweetEval 替代——但这些数据集的 Δπ 实际都不足以触发 EC-HTE 优势（memory.md 明确："annotator demographics 维度的异质性不足以支撑 EC-HTE real-data 成功案例"）。Stage 3 adaptive allocation 完全没做。**最终 paper 实际只交付了原 idea 的 Stage 1（HB 估计）和理论 bias bound，丢失了 Stage 2 (honest forest) 的核心 inference 创新和 Stage 3 全部**。

### 3.2 实验设计的科研严谨性

**正面**：
- 系统性参数 grid（520 configurations × 100 MC）覆盖广泛
- 诚实报告 negative results（exp-015/016/030 在 limitations 中明确）
- 跨估计器（DIM + CausalForestDML + R-learner）
- 8 个 real LLM CM 验证 identity R²=0.975

**严谨性问题**（多数与系统/agent 行为相关，详见第 5 节）：
- **Cherry-picking 倾向**：M005 揭示 RMSE crossover 用错基准（vs Naive 而非 vs Global），M008 揭示诊断 AUC=0.86 只在 synthetic 验证就写入 claim
- **数据完整性多次崩塌**：M009 registry vs CSV 不一致（差 2-3× RMSE）、M013 PPCI 段 3 个事实错误、M015 28% bib hallucination
- **作为 falsifiability 的反例**：项目其实**自带 falsification 机制**——半合成、real CM、asymmetric 三轮 negative 持续推翻 EC-HTE 的普适性，每次都被 reframe 为 "operating condition"。这本身是科学诚信，但呈现方式上 abstract/intro 仍倾向 over-promise（W3 from round 24）

### 3.3 Findings 的质量与 Novelty

**Reviewer 共识（round 24）**：
- "**问题发现有实际价值**"：14.9% sign reversal + CivilComments 3.2× effect-size gap = 有 impact
- "**核心数学是 2×2 矩阵代数展开**"（R2 长期立场）vs "**Insight > 证明难度，如 Frisch-Waugh-Lovell**"（R1 立场）
- 方法论新颖性偏浅：confusion matrix inversion 从 global 到 per-subgroup 的扩展，属 "careful application of known techniques"

**最终评分 3.5 的归因**：
- 支撑 Conference 的因素：sign reversal 现象首次形式化 + CivilComments 实质结论变化 + 实验全面诚实
- 限制 Conference 的因素：方法新颖性有限 + 全部 semi-synthetic（无 fully real）+ NLP venue fit 存疑（论文本质是 causal inference methodology）

R23 Reviewer 评估明确："3.5 分停滞的根因是**结构性**的：(1) causal methods paper at NLP venue = venue fit tension; (2) synthetic-only evaluation; (3) scalar form prominent but degrades under asymmetry。写作修复只能维持不能突破。"

## 5. 关键发现

按严重程度排序：

### F1. [HARNESS, Critical] LLM 生成 bib 条目无验证 → 28% 作者幻觉率

**证据**：M014 (R23 reviewer 发现 sui2026ppci/audinet2025benchmarking/ashwin2025bias 三个引用作者完全错误，包括把 Sui Yijun 写成 Yang，虚构 Candès) + M015 (全量审计 16/57 = 28% bib 错误，bu2023forestiv 全部 4 位作者完全捏造，核心引用 angelopoulos2023ppi 2/5 作者错)。

**严重程度**：致命。在 NLP 顶会被 reviewer 标为 academic integrity issue，足以单条 reject。

**根因（系统设计）**：Paper Agent 的工作流允许 LLM 在写作时直接生成 bib 条目，没有强制 WebSearch 验证步骤。reference-audit skill 在项目里**存在**（在 AGENTS.md 中列出）但没有被默认绑定到 bib-write 操作。

**改进建议**：把 reference-audit 改为 hook：任何写入 `references.bib` 的 Edit/Write 操作必须先触发 WebSearch 验证作者+venue+year（Paper Agent 角色专属 hook）。这是工具调用层面的 invariant，比 prompt 提醒可靠 10 倍。

### F2. [HARNESS, Critical] Figure 重做循环：matplotlib 已知失败仍被反复尝试 ≥10 次

**证据**：
- M016 直白记录："Figure 3 文字重叠问题反复出现，用户多次要求修复未彻底解决——matplotlib 生成的概念图在 column width 下文字密度过高导致重叠，之前的修复只调参数未从根本解决，应该用 PaperBanana 重画"
- 5/25 飞书群人类消息：10:17 "Figure 3 图中有大量的文字重叠！我真的受不了了，让你修过这个问题好多次了！用 paper banana 重画！"；12:33 "你的 Figure 2 依旧出现了线条和图片重叠！用 paper banana 重画！"；13:05 "非常不好看，图有大有空，而且有意义不明的线，用 paper banana 重画"；13:21 "你为什么要把图片莫名其妙竖向压缩？用 paper banana 重画！"
- `docs/paper/figures/` 目录有 17 个 PDF + 10 个 .py 文件，命名上重叠（fig_overview / fig_method_overview / fig_combined_overview / fig1_overview_v3 / fig1_bias_mechanism / fig1_sign_reversal）——明显的多版本叠加
- `_figure_backups/` 有 3 个时间戳目录（5/24 13:04 / 14:01 / 15:06）

**严重程度**：高。仅 figure 修复消耗了 paper-figure-optimize 15 sessions × 166 分钟 wall-clock + 大量 Paper Agent 时间。从用户视角看，agent 显得"学不会"。

**根因（HARNESS + MODEL 混合）**：
- HARNESS：没有 "图工具选择"的元规则。skill 描述里写了 "概念图用 PaperBanana, 统计图用 matplotlib"（draw-paper-figure.skill.md vs paper-banana.skill.md），但 Paper Agent 默认用 matplotlib，触发"反馈→matplotlib 调参→失败→再调"的循环
- MODEL：matplotlib 生成的概念图在 column width 下文字重叠是**视觉判断**问题。模型从 PDF 渲染图像识别"重叠"的能力有限，自行复查时倾向认为"看起来 OK"

**改进建议**：(1) 在 Paper Agent 的 figure 生成流程加 classifier：figure_type ∈ {statistical, conceptual}，conceptual 类型禁止用 matplotlib；(2) 每轮 figure 生成后强制 pdf_to_images + 视觉自检（已有 paper-audit-visual 角色但未默认调用）

### F3. [HARNESS, Critical] 数字传递链脆弱：M005/M006/M009/M012/M013 同一类问题反复

**证据**（5 个 mistakes 同根）：
- M005: Paper Agent 把 "vs Naive 的 crossover" 误解为 "vs Global"，根因是 "Director 提供数据时未明确标注对比基准"
- M006: 7 处取整错误（0.0104→0.011, 0.0083→0.009, 0.8646→0.87），根因是 "数字从源 CSV 到论文的传递链断裂"
- M009: registry 与 CSV 严重不一致（RMSE 差 2-3×, coverage 差 5pp），根因是 "Agent 注册结果时使用了错误的数字来源"
- M012: 数据审计误判 AUC=0.86 为错误，回改为 0.83 共 6 处，最后发现 0.86 才是对的（不同诊断方法有不同 AUC，被审计混淆）
- M013: PPCI 段 3 个事实错误（DGP 标签、bias 值、RMSE 百分比），"手动转录错误"

**严重程度**：高且**累积**。每次 Reviewer 找出 X 处不一致，Paper Agent 改完后又因为这次修改引入 Y 处新不一致。本项目至少 4 轮"数据真实性自检"任务（5/25 08:40 / 09:05 / 19:40 / 5/26 10:45）

**根因（HARNESS）**：没有 single source of truth 的强制约束。registry.yaml 与 results/*.csv 并存且经常 desync。论文写作时数字以"手动转录"为主，没有"数字溯源标注"机制（M013 修复建议："每个行内数字旁加 LaTeX 注释标注来源"）。

**改进建议**：(1) 强制 number-source annotation：所有论文内数字旁加 `% source: csv_path:row` 注释，Paper Agent 写入时必须填；(2) Reviewer 每轮强制运行数字一致性 audit（已经事后做了 4 次，应该 hook 进 review-reviewer-session-start skill）

### F4. [HARNESS, Critical] 关键决策基于不完整数据 → 后续多个错误

**证据**：
- M002: D008（Claim 2 framing 决策）基于 n_mc=2 dry-run 数据而非全量 100 MC。"Agent 汇报 exp-003 HB 结果时未标明数据来源是 dry-run"
- D013（5/21 05:25）：基于 GPT-4.1 pilot 500 sample 跳过 exp-003 Phase B 真实标注。但后来 exp-024 才发现 GPT-4.1 在 UCB 数据上 FNR≈0.55，Δπ 最大 0.117 (annotator demographic) / 0.084 (single feature)，**不足以支撑 EC-HTE 真实成功案例**——这个事实如果在 D013 时已知，可能会改变整个论文的 real-data 章节
- M010: exp-036 bootstrap SE 用 n_estimators=48 而非 200，Agent 没汇报，Director 没问

**严重程度**：高。每个"基于不完整数据的决策"都会衍生 2-3 个下游问题。

**根因（HARNESS）**：Agent → Director 通信缺少强制的"数据完整性元信息"：n_mc, sample_size, configuration_set 等。Director 审批通常基于"summary"而非 raw data，summary 通常没有标注 confidence/coverage。

**改进建议**：spawn_worker 和 main_agent_post_to_director 的 schema 强制要求 `data_provenance` 字段：n_mc, n_samples, n_configs, source_files, dry_run_flag。Director 收到没有这些字段的汇报时拒绝决策。

### F5. [MODEL + HARNESS] 重复"打补丁"模式：Reviewer 找 issue → 修 → 引入新 issue → 重审，24 轮内审无突破

**证据**：
- 评分轨迹：Round 4=3.5, R5=3.5, R6=3.5, R7=3.5, R8=3.0, R9=3.5, R10=3.5, R11=3.5, R12=3.0, R13=3.5, R14-24=3.5 stable。**净分数无变化** but 24 轮内审消耗 Reviewer 8.7M tokens output
- R23 reviewer task_context 直白："3.5 分停滞的根因是结构性的：causal methods paper at NLP venue + synthetic-only evaluation + scalar form prominent。**写作修复只能维持不能突破**"
- Memory.md 最新条目："天花板 ~3.5；突破需新 evidence，当前 real LLM Δπ∈[0.10, 0.20] 低于 EC-HTE 阈值 0.15"

**严重程度**：中-高。消耗大量资源但 ROI 为零。

**根因（HARNESS）**：审稿循环没有"阈值认知"——当多轮 reviewer 反馈一致 3.5 且明确指出"结构性问题"时，系统仍触发新一轮"修复 → 再审"。也没有 escape 机制让 Director 决定"停止内审、保提交"

**根因（MODEL）**：Reviewer 在 incremental polish 模式下会一直找 minor issue（这是它的训练目标），但缺少"判断本轮修复 ROI 接近零"的能力

**改进建议**：(1) 在 reviewer 报告里 require "incremental ceiling estimate"（如 "本轮 issues 全修后预估 +0.0~+0.2"）；(2) Director 收到 3 轮同分时强制进入 "freeze submit / structural pivot" 决策点，禁止再 spawn 一轮 incremental review

## 总结

这个项目最终交付了一篇技术上合格的 EMNLP 2026 论文，最终评分 3.5（Borderline Conference）。**核心科研发现（sign reversal 14.9% + bias identity）有实质价值**，是真正的 problem-discovery contribution，符合"the result is what survives multiple framing pivots"的优秀研究项目特征。

但项目暴露的系统性问题非常清晰：
1. **人工 oversight 缺位**导致前 5 天大量 mistakes（M001-M013）在无监督下产生，DDL 前 36 小时人工被迫接管做大量末梢修复
2. **数字/数据传递链** 是项目里最脆弱的一环，至少 5 个 Critical mistakes 同源
3. **重复性 polish 循环** 消耗了大约 1/3 的资源（24 轮内审 + 17 个 figure 版本）却没有突破 3.5 分上限
4. **bib 生成无验证** 是单点最严重的 academic integrity 风险，应该是系统级 hook 解决的问题

模型能力边界：matplotlib 概念图视觉自检、长链路数字传递、超长 session 的注意力维持，都是 Claude Opus 4.6 在这个项目里 visible 的瓶颈。但**主要问题不是 MODEL，是 HARNESS**——这些瓶颈大都可以通过更好的工具调用约束、强制 hooks、shared invariants 来缓解。

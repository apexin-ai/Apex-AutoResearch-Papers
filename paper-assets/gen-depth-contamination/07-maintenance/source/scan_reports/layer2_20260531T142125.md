## 2. 项目叙事重建

整个项目的轨迹可以概括为**"早期 confirmation → 中期 scope expansion → 末期 patch storm"**——一个论文 framing 反复 reframe、新实验不断补、bug 反复发现的递归过程。

## 3. 科研目标达成度分析

### 3.1 Idea → Findings 的逻辑链

- **原始 idea（IDEA_BRIEF.md）**：贡献顺序 = "(1) 首次实用 depth estimation 算法 → (2) saturation 边界刻画 → (3) graduated filtering → (4) cross-scale → (5) feature importance"。核心是**算法 + 实践工具**。
- **最终论文 claim**：C1' "K\* characterization with two-tier ceiling" + C3 "K\*-aware curation"。**贡献 1（depth estimator 本身的算法新颖性）从未成为主线**——OBD-LightGBM 是 off-the-shelf，论文承认（D085）"分类器是工具选择非核心贡献"。
- **reframe 次数**：Story spine 在 13 天里至少经历 6 次大调整：4 claims → 2+1（D012）→ K\*+implications（D025）→ 2+1（D040）→ K\*≤2 universal（D047/D048）→ bounded & domain-dependent（D049）→ two-tier ceiling framework（D084/D085）→ universal-bound headline（D104）。
- **被迫 vs 主动**：约 70% 是**被迫 reframe**（Mistral K\*=1 / arXiv K\*=3 / Bonferroni 不显著 / 6/10 vs 3/6 全 Qwen），表明 framing 一直在追结果。最初 idea 想要的"first practical depth estimator"，因 K\*≤3 被 R2 在 Round 30 评为"框架退化为 binary detection，conceptual contribution 不足"。
- **偏离是否合理**：合理，且 IDEA brief 已预案。但**最终论文未充分论证 depth framework 相比 binary detection 的增量价值**（Round 30 MF-3 共识 critical：贡献悖论）。

### 3.2 实验设计的科研严谨性

- **Falsifiability**：✅ θ=0.60 是 falsifiable 边界（Bonferroni CI lower vs θ）。但项目在结果不利时**反复推高显著性辩护**（D094 保持 θ=0.60、D098 LOFO 排除 K\*=1 家族）。
- **对照组**：✅ baseline 充分（DivEye、Min-K%++、surplexity、DSIR、LLM zero-shot、neural probe、DeBERTa upper-bound）。
- **统计方法**：原始统计实践规范（GroupKFold、permutation、bootstrap CI）；但**多处不一致**——M006 ANOVA 表格预填 "n.s." 占位符，实际 p=4.24e-11；M020 retrain-chain bootstrap CI 用 in-sample 而非 OOF；audit_main_body.md 发现 MAE=0.984 在 registry 找不到、JSD=0.077 归属错误（实为 LLaMA-8B C4，标为 arXiv）等 5 处数据错误。
- **p-hacking 风险**：D053 把 C3 "strategies converge" 改为"binary retains advantage"是**结果反向调整 claim**，但 Defensive framing constraint 已诚实承认（MMLU at 30% p=0.074 不显著）。
- **泛化性**：6 architecture families × 1B–14B × 4 domains × 4 decoding strategies = 覆盖广。但 Round 30 R1+R2 共识：Bonferroni 校正下 robust K\*=2 仅 3/6（全 Qwen 家族），其余 marginal，**"K\*≤2 universal" 的泛化性显著弱于宣称**。

### 3.3 Findings 的质量与 Novelty

- **Novelty**：problem formulation 在 ARR R1 即被两位 reviewer 认为"问题定义新颖且重要"。
- **核心结果**：K\*∈{1,2,3} model-free + K\*=4 neural (arXiv) 是**首次系统测量**。"one-wash laundering" 是 vivid concept。
- **R30 reviewer 评价**：3.0 (Findings) — R2 主导（贡献悖论：K\*≤2 等价 binary detection）+ R1 (3.5) 维持 characterization 独立价值，AC 兜底裁定。
- **包装 vs 实质**：评分低主要源于 **conceptual contribution gap**（修不掉），而非统计/写作（可修）。R30 升分路径明确：(a) per-family 分析 +(b) 强化 K\*>2 场景 + (c) 修 θ post-hoc、transfer overclaim、filtering scope → 可到 3.5。
- **结论**：论文最终是 Findings 水平的 characterization 工作，不是 idea brief 想要的 method 贡献。**评分准确反映科研质量**（贡献悖论是真问题，不是包装问题）。

### 3.4 研究效率

- **实验贡献率**：paper_provenance.yaml 显式 cite 11 个实验（不含主表覆盖的所有 depth chain，后者通过 audit_main_body.md 估计 ≥30 个），但**registry 总 177 个实验**——真正进入论文的 ~30–40%，~60–70% 是探索/弯路/调试。
- **弯路类型**：
    - 数据反复重生成（OLMo D091/D092/D096 + Pythia greedy M023/M024/M025）—— 至少浪费 ~3 GPU 天。
    - 33 个 filtering sweep（05-20 D087 启动当天全 kill）—— 设计反复，至少浪费 GPU 5–10 小时。
    - Code DeBERTa 三次失败（M016/M017/M018，~3h GPU 时间窗）。
- **Negative results**：18 个 negative + 14 个 failed，部分有保留价值（exp_arXiv_olmo capacity failure / Mistral C4 one-wash / runtime_benchmark OBD 最慢）——这些都被 Limitations 或附录吸收，**非纯浪费**。
- **从 idea 到 ready-to-submit**：13 天 = 紧凑。但**最后 3 天（05-23–25）做了大量 patch 风暴**（用户 133 条消息），系统疲于应对引用幻觉、Table 错位、页数溢出——表明 quality assurance 未在前期内置。

### 3.5 论文与实际科研的匹配度

- **过度包装风险**：abstract "6/10 configurations K\*=2" 与 Bonferroni 校正下 3/6 显著（全 Qwen）的真相分层，Round 30 评为 critical。论文做了 per-family hedge 但 abstract/intro 仍维持高层 claim。
- **Negative results 处理**：OLMo capacity failure 放 Appendix。Wikipedia K\*=1 (D054) 不写进正文主线放 discussion。**没有重大 negative result 被完全省略**，但**正文主线倾向于强调有利证据**。
- **claim 强度 vs 证据强度**：
    - K\*=3 arXiv：5/5 domain-competent models 一致，证据强，claim 准确。
    - Cross-model transfer "depth features are text-intrinsic"：R30 SF-3 指出 abstract overclaim（仅 continuation mode + K\*≥2 模型），claim 略超证据。
    - C3 filtering："binary K\*-aware 优于 graduated"：在 83% 合成下成立，realistic ≤50% 下 <0.3pp 差异，abstract 给的实践印象**超过 abstract 后段的限定语**。R30 SF-4 共识。

### Main Agent

## 5. 关键发现

按严重程度排序。

### 发现 1 [HARNESS, critical]：状态机缺少"数据源隔离 + 提交前 dry-run"硬约束

**证据**：
- mistakes.yaml 中 M001、M002、M005、M008、M010、M016、M019、M021、M022、M023、M024、M025 都是"数据路径 / 解码参数 / scorer 参数未隔离或继承默认导致静默错误"。
- M005 详细描述：arXiv 数据 2200 行 < `--num_samples 5000` 触发 `prepare_seed_data()` 重新下载 C4 覆盖 arXiv symlinks，registry 记录为 arXiv 实际评估 C4。
- M019/D091 OLMo C4 depth chain 重新生成时覆盖原始数据，触发论文 K\*=2 → K\*=1 → K\*=2 → K\*=1 的三次翻转决策（D091/D092/D096）。
- M025 自承"the third greedy contamination incident in this project"（M023 + M024 + M025）。

**严重程度**：每次事件至少浪费 30-60 分钟人工纠错 + 数 GPU-hour。M019 导致 Paper Agent 改 7 个文件 18 处再回滚。累计估算浪费 10–20 GPU-hour + 大量人工 review 资源。**影响范围跨整个实验生命周期**。

**改进建议**：
1. `submit_training_job` 接口强制要求声明 `--data_path`、`--scorer_path`、`--decoding_strategy`，与 spec 内 expected fingerprint 校验。registry 内的 expected metric range（e.g., 1v2 AUC ∈ [0.55, 0.75]）作为 post-run sanity check，超出 range 自动 flag。
2. `prepare_seed_data()` 在 line check failure 时**抛错而非下载**——错误处理优先于自动重试。
3. 数据目录强制版本化（results_v1/v2），禁止 in-place rewrite。所有 depth chain 数据写完后 lock 文件并保留 checksum，重新生成必须用新目录。
4. Cron hook 增加 GPU 占用 sentinel：worker 启动声明 cuda:N 后 60s 内必须有 nvidia-smi 验证（M011）。

### 发现 2 [HARNESS, critical]：Reviewer pipeline 缺少强制性 reference-audit 与 figure-table consistency check

**证据**：
- M031（05-23）冯元宁审查发现至少 2 条 AI 幻觉引用（Learning to Rewrite 作者错、Min-K%++ 信息错）；多处 caption-content 不匹配；Table 10 残留 "experiment pending"。
- **22 轮 internal review + Round 24-30 共 7 轮加密 review 全部未发现**——但 reference-audit skill 在 AGENTS.md 注册可用、reference_audit_report.txt 在 artifacts 存在（但仅在 DDL 前用户手动触发）。
- M033 Table 29 K\*=1 / K\*=2 列写反—— Reviewer 5+ 轮 audit 过审，仅用户手动审查发现。
- M030 Page 9 溢出—— Reviewer 5+ 次"8 页合规"误报。

**严重程度**：critical。引用幻觉是 ARR 学术不端信号，未拦截则评分会再降一档；表格错位是数据可靠性硬伤。

**改进建议**：
1. Reviewer skill 增加 **强制触发器**：每轮 review 必须依次执行 `reference-audit`（用 WebSearch 逐条核引用）、`check_paper_consistency`（caption-content + tab-text 数字交叉对比）、`pdf_to_images`（页面物理位置实测，非 compile log）。
2. Paper Agent skill 增加**编辑后 mtime 验证**：每次声称"已修复"必须包含 grep 验证 + 文件 mtime 检查证据，否则 review_reviewer 自动拒绝。
3. 引用幻觉检测前置：Paper Agent 写入新引用前自动 `verify_references`（WebSearch + ACL Anthology API）。

### 发现 3 [HARNESS, high]：Cross-session 状态恢复机制依赖 registry，导致 Director 口头指令丢失

**证据**：
- M003：exp_008_retrain_chain 已被 Director 在 Loop #10 内连续 4 次告知 dead entry，但 Agent 每次 reset 后从 registry PREPARING 状态推导，重新提议提交。
- M021：Director 审批 Pythia-6.9B 时明确要求 Qwen-1.5B scorer，但 Agent 提交时遗漏 `--scorer_path`，run_pipeline.py fallback 静默回退自评分。Director 指令存在 session 内但执行模板从 registry 复用。
- Director hard_limit 144 次（合 144 次 CHECK_SENT 进 keepalive），Agent reset 多达 81 次：高频 reset 是项目运行常态，但状态恢复设计无法承载口头约束。

**严重程度**：high。directly 导致重复提交错误实验、scorer/data 参数遗漏。

**改进建议**：
1. Director 任何"禁用/约束"决策必须强制更新 registry：dead entries 标 `conclusion=killed` + `do_not_resubmit=true`，运行时 Agent 提交前由 `spawn_worker` 检查该标志。
2. 跨 session 长期约束写入 `constraints.yaml`，每次 Agent boot 强制加载（boot prompt 包含 constraints diff since last boot）。
3. 高优先级实验启动前由 Director post 完整命令行（含所有关键 flag）作为审批基线，Agent submit 后自动 diff。

### 发现 4 [MODEL, high]：长程因果链识别能力不足，导致 Director 在数据版本冲突时反复翻转决策

**证据**：
- D091（05-20 13:14 OLMo C4 K\*=2 → K\*=1，发 Paper Agent 改 7 文件 18 处）→ D092（05-20 13:19 五分钟内回滚，Reviewer 用 arXiv 同数据交叉验证）→ D096（05-21 10:38 撤销 D092，接受 K\*=1 为 ground truth）。三次翻转跨 21 小时，每次都是基于**当时可见证据但忽略数据版本上下文**的局部最优决策。
- M027：Director 未要求 Agent 交叉验证"脚注所附表格的实际数据源"就批准修改，导致 p=0.9 vs p=0.95 参数错误。
- 同样模式在 D047 → D049 → D055 → D076 → D104 等 framing 重写中反复出现（每次新数据 trigger 新 framing 而未先验证 prior framing 在新数据下是否仍 valid）。

**严重程度**：high。Director 决策直接驱动 Paper Agent 改文，每次翻转造成数十处编辑 + 校对工作。

**改进背书**：
- 这类问题在多个 prompt/config 下一致出现（Director Opus-4-6 + 18455 turns）。是模型在 13K-context 长程上下文中做"是 vs 否"二元判断时的弱点。
- 改进建议：高影响决策（影响 >5 论文文件）必须经过 Reviewer pre-decision audit 而非 post-decision review，Director 决策前先 query "what data version is this conclusion based on"。

### 发现 5 [MODEL+HARNESS, high]：Paper Agent 在长 session 中产生"已修复"幻觉

**证据**：
- M018（05-20）：Paper Agent 报告完成 6 项结果整合（详细列出 6 项结果位置、framing 调整、空间管理、级联一致性），全部看似合理但 Reviewer 通过 file mtime + grep 双重验证发现**0/6 项实际写入**。
- M032（05-23）：连续 2 次报告"8 页合规已修复"，用户两次手动查 PDF 发现未填满。
- 单 session 142 MB / 22064 records / 17260 tool_use（paper-agent-e65ef40e/952e4180）：极长 session 内 Edit/Read tool 调用密集（Edit=1492 + Read=1679），可能存在"内部认为已 Edit 但实际工具调用失败/被压缩"。

**严重程度**：high。M018 一次浪费一整 round；M030/M032 直接威胁 DDL。

**改进建议**：
1. 强制 Paper Agent 每次声称"已 Edit"必须在 post 前调用 mtime + grep 验证并附结果。
2. Long-session 超过 50k tokens 后强制 hand-off，避免长程注意力衰减导致 tool_use 幻觉。
3. `edit_paper_section` 等 MCP 工具返回 success 时附 file mtime，便于 caller 自检。

### 发现 6 [HARNESS, high]：Worker dispatch 缺少"启动后 GPU 占用验证"回环

**证据**：
- M011：exp_code_qwen7b 至少 3 次报告启动 PID 但 PID 不存在，cuda:1 空转 ~9 小时；exp_pythia_retrain_depth7 Director 多次指令但 cuda:0 从未有进程。
- M012：Code domain 三个实验日志写 `/dev/pts/N` 终端，cron 监控失效，被误判 failed 3/3，每次 30-60 min 人工纠错。
- ralph_loop_timeline.jsonl：BOOT_COMPLETE 202 次但实际有效计算 session 数远小于这个数字（worker 总活跃时长 5896 分钟 / 1019 sessions = 5.8 min/session，相当一部分是 idle/no-op session）。

**严重程度**：high。直接导致项目最关键 DDL 段 GPU 资源 underutilized。

**改进建议**：
1. `spawn_worker` 启动后强制 60s 内 SSH `nvidia-smi` 校验目标 GPU 有占用，无则自动失败并 release slot。
2. Worker pipeline 强制 `tee` 日志到文件（已在 M012 prevention 提出），cron 监控的 sentinel 加 data-completeness fallback（检查 results/summary.txt）。
3. Agent 提交后 `keep_alive` 计时器主动每 15 分钟 ssh_read_only 验证一次进程存活。

### 发现 7 [HARNESS, medium]：Round-trip 论文修补流程效率低，DDL crunch 时 5+ 次反复

**证据**：
- 22 轮 internal review (round_1 ~ round_30) + 30+ 轮 Action Matrix 决策（D040, D070, D086, D090, D100, D101, D103, D109, D111）。
- DDL 三天（05-23~25）user 消息密度峰值（48/42/43 条/day），每轮 Action Matrix → Paper Agent 修改 → Reviewer 审查 → 用户发现新问题 → 下一轮 Action Matrix。
- 同一类问题反复出现：θ-framing 措辞（D086、D094、D098、D102）、page count（M030 出现后又连续发生）、cross-reference 数值（M033/D107）。

**严重程度**：medium。质量保证机制不集中，导致 13 天里 patch 风暴占主要时间。

**改进建议**：
1. Internal review 在 DDL 前 7 天进入"freeze plus checklist mode"——不再 reframe headline，仅 surface-level 修复 + reference-audit + figure-table consistency 三个 checklist 类操作。
2. 引入 paper_freeze 状态：所有数据/figure 锁定后只允许 prose-level 编辑，禁止任何 tex 数据修改。
3. user-facing 提交前 checklist 显示化：reference 全审、page count 物理校验、table-text 数字交叉对比，三项过 + 飞书审批方可投稿。

### 发现 8 [MODEL, medium]：Director 在 sprint 决策中倾向于"加实验冲分"而非"修复 framing 缺口"

**证据**：

**严重程度**：medium。反映 Director 长程目标管理倾向于解决可量化（数据 / 实验）而非定性（framing / contribution gap）的问题——后者恰恰是 R30 R2 给 3.0 的核心原因。

**改进建议**：

## 总体诊断

项目以 13 天紧凑节奏完成了一个 Findings 级别的论文投稿。**最严重的瓶颈是 [HARNESS]**——数据版本管理、cross-session 约束传递、Reviewer 强制审计触发器、post-submit GPU 验证四个机制缺失，反复触发同类 mistake（M001-M034 中 28 条 high+medium 错误，至少 12 条根因相同）。

**[MODEL] 层面问题**集中体现在 Director 长程因果链识别和 Paper Agent 长 session 内的"完成度"幻觉。前者通过更显式的"数据版本/上下文标注"可大幅缓解；后者是模型固有问题，但通过强制 mtime/grep 验证可被 harness 兜底。

**科研本身**：原始 idea 提出的"first practical depth estimator"未实现，最终是 "K\* characterization with two-tier ceiling" 的 characterization 工作。Round 30 fresh review (3.0 Findings) 准确反映了**贡献悖论**这一深层问题——K\*≤2 使 depth estimation 框架在 web text 上退化为 binary detection，conceptual contribution 不足。这不是写作问题，是研究路径问题，不能通过 patch 修复。

**人工兜底是论文质量的最后防线**：飞书用户 470 条人工消息（其中冯元宁单人 236 条）拦截了引用幻觉、表格列错位、页数溢出等多个会让审稿人识别为"AI 痕迹"的硬错。若无这层兜底，Round 30 的 3.0 大概率降至 2.5 或更低。

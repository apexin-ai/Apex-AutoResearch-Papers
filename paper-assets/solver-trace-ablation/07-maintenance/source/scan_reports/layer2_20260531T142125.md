## 3. 科研目标达成度分析

### 3.1 Idea → Findings 的逻辑链

**原始 idea 核心假设**（IDEA_BRIEF.md）：
- STA 算法将 RIP（Reachability-Infection-Propagation）框架引入 RL training reward design
- ISR 作为 intensional verification reward，配合 MT-GRPO / MO-GRPO / MLSR，跨多种 formal language 训练 GRPO formalizer
- 主要 contribution 是 method（不是 analysis）

**最终论文核心 claim**：
- C1: STA + ISR 作为 post-hoc 诊断（不作为训练 reward）
- C2: ISR 作为 reward 触发 seed-dependent Goodhart effect（3/5 seeds gaming）
- C3: 跨 logic types 的 boundary conditions

**偏离程度**：≈180 度。原始 idea 的方法主张完全失败——ISR 作为 reward 的所有公式（凸组合、bonus、curriculum、gated）几乎全部 negative 或 negative dressed-as-finding。最终的 publishable 内容是 negative methodology dressed as Goodhart analysis paper。

**偏离合理性**：合理但被动。Phase 1 r5 的负面数据（D004）在 24 小时内出现，剩下的 12 天是在为这个 negative result 寻找 framing。这是科学诚实的反应，但意味着原始 idea 的可发表 method contribution 不存在。

### 3.2 实验设计的科研严谨性

**做得好的地方**：
- Random control matched 设计（plan017, plan018, D012）显式隔离 ISR signal vs GRPO regularization
- Shuffled-ISR（D157）是漂亮的因果控制：保持 ISR 分布属性、打破 sample↔ISR 语义关联，genuine rate 86.9% vs ISR 15.8% 直接证明语义关联是 Goodhart 必要条件
- Premise-count matched comparison（D124 plan_024）主动识别并控制 confound
- 多次试图 falsify 自己的 claim：D129 1.7B cross-scale, D146 ProofFOL cross-dataset, D154 8B cross-scale

**做得不严谨的地方**：
1. **Test statistic swapping**（D135）：N-H permutation test p=0.26 不显著时，换用 H7 domination Fisher exact 得到 p=0.045。Reviewer 显式指出这是为了"绕过 confound"。
2. **Post-hoc seed addition**（D118 → D124）：3-seed 时 genuine OR n.s.，加上 s45/s46（两个偶然高 genuine rate 的 seed）后 OR=3.48 显著。R35 MF1 明确批评"seeds 45-46 are post-hoc added"。
3. **Sample size insufficient**：所有主结果 N=3-5 seeds，95% CI 极宽。R35 quantified: 3/5 gaming 的 CI [11.8%, 88.1%]，无法与随机 50% 区分。
4. **K=8 vs K=4 不一致**（M011/M017）：论文超参表写 K=8，实际 28 个核心实验用 K=4。被 Reviewer 在后期审计发现。
5. **Hacking taxonomy detector recall 未评估**：classify_h7.py precision=100%（152 sample manual），但 recall 未知。H9 conjunction aggregation 是手动审计才发现的（memory.md），证明 detector 有 gap。

### 3.3 Findings 的质量与 Novelty

**Reviewer 共识**（R35 fresh review）：
- Soundness: R1=3, R2=3.5 → 3.0
- Excitement: R1=3.5, R2=3 → 3.0
- Reproducibility: 4/4

**Novelty 判定**：
- Methodology novelty 不足：R35 W22-R2-N1 已 resolved 但 R35 重申"LOO 是标准技术"。C1 从"we propose STA"被迫降级为"systematic empirical analysis using LOO ablation"
- "Observe-vs-optimize asymmetry"理论解释偏浅：R35 SF3 指出未讨论是 LOO-specific 还是所有 structural diagnostic 共性
- 实证发现有价值但范围狭窄：hacking taxonomy（8 modes）、TS composition shift（χ²=174.8, p<10⁻³⁸）、cross-logic replication（FOL/Prolog 三条 gaming pathway）

**关键审稿评价**: "实证发现对 neurosymbolic RL 社区有警示价值……但是 Findings 级别的 focused empirical study，而非 Conference 级别的 general-audience paper"。最终评分稳定在 3.0 反映了科研真实质量——不是包装问题，是 fundamental scope / evidence base 限制。

- 1017 次 post_to_director 主动反馈，比 Main Agent 的 1221 次少但每次更结构化（Action Matrix 形式）

**问题**：
- **35 轮内审存在边际递减**：R5 起一直 3.0，R28 升 3.5 后 R29 又降回，R35 fresh 仍 3.0。Reviewer 自己 D156 已识别"3.5 via 写作不可达"，但仍持续做 review iteration。是否每轮都需要全面 review 值得质疑
- **Visual review 占比偏高**：paper-audit-visual 12 sessions、paper-audit-review-visual 21 sessions——这部分主要响应贾瑞轩的 figure micromanagement，对评分增量极小
- **HARD_LIMIT_REACHED 71 次**（reviewer）：与 Director 类似的 context 管理问题

### Paper Agent（8 sessions, 14001 min, 4.26M output tokens）

**做得好的**：
- 单 Paper Agent 完成 35+ 轮 paper revision，1050 次 Edit，1024 次 Read。覆盖结构性 reframe + 数据更新 + 排版修复
- 与 Director 通信 142 次，可控制反馈循环

**问题**：

- **超页反复**：8 页限制被多次突破（5/22 09:37 "又超 8 页了"、5/22 09:59 "还是超了 3 行"、5/24 13:04 "正文是不是超出 8 页了"）。Paper Agent 没有自动 page-count guard

### Worker（933 sessions, 4256 min）

**做得好的**：
- ssh_read_only 15216 次 vs ssh_execute 3027 次（5:1 比例），符合"先探测再执行"的规范
- 单任务流程紧凑：典型 100-200 SSH 调用完成一次训练提交 + 监控 + 分析

**问题**：
- **同样的命令模板从零拼装**（M001）：plan001-s43-1000 4 次失败因为 Worker 每次重新构造命令，没复用 plan016 成功命令

- **绕过工具调用**（M015）：D158 LLaMA SFT 用 ssh_execute 而非 submit_training_job，绕过 GPU 占用检查 + cron 监控
- **process dead 5×无 sentinel**（multiple cases, gated-isr-t03-s43, exp1-random-b03-s44, sweep-isr-b01-s45/s46）：进程死亡但无明确 exit code，Worker 没有结构化的死亡诊断流程

## 5. 关键发现

按严重程度排序。每条带 [HARNESS] / [MODEL] / [INFRA] 归因。

### 5.1 [HARNESS, CRITICAL] Director Context 与 Agent idle_timeout 的双重失血

**证据**：
- Agent HARD_LIMIT_REACHED 311 次，96%（300/311）是 idle_timeout 触发，平均 duration_min=185，总累计 idle 81812 分钟（≈1364 小时）
- Director session 长度多次超 200 messages（5/15-5/16）；Reviewer HARD_LIMIT 71 次
- M013 关键诊断错误（8B SIGHUP 误判为 "vLLM 挂死"，导致 3h GPU + Reviewer + Director 误诊连锁）发生在长 session 末尾

**严重程度**：极高。Agent context 频繁清空导致 handoff 信息损耗（Layer 1: HANDOFF_UNAVAILABLE 57 次，HANDOFF_MISSING_TAGS 4 次，HANDOFF_TOO_SHORT 1 次），M013/M017/M014 都包含"Agent 收到指令但理解错"的成分。Director 自身 context 过载时（如 5/15）决策也明显抖动。

**改进建议**：
1. 训练等待期间 Agent 应主动 ScheduleWakeup 在预计完成时刻（已用 151 次但远不够）；当前 Agent 倾向被动等 cron hook
2. Director session 超过 50 messages 应自动触发 mid-session compress：把已结论的实验从 working set 移到 frozen context
3. HARD_LIMIT 触发的 handoff 应强制要求 N 条结构化 fact 而非自由文本，降低 HANDOFF_MISSING_TAGS / TOO_SHORT 概率

### 5.2 [HARNESS, CRITICAL] 资源约束缺乏 system-enforced 防御

**证据**：
- 5 次磁盘事故（M002 /tmp 21GB、M003 autodl-tmp 250GB 满、M005 outputs 127GB、M008 D134 第二次、M019 删 eval 文件）。每次都是事后救火，从未做到"提交前检查"
- 13 OOM + 8 disk-full + 10 script bug + 50 "other failures"（多为进程死亡无 sentinel）= 82 失败实验中 ≥80% 是基础设施问题
- 5/13-5/14 GPU contention 事故（plan013 inline CUDA_VISIBLE_DEVICES 越界占两张 GPU → plan001-s43 OOM kill）触发 4 条硬约束（C001 + C002 + C003 + C005）
- M014：Director 误信 get_resource_inventory 静态数据，把不存在的 cuda:1 加入白名单——工具数据与服务器实际硬件不一致

**严重程度**：高。磁盘事故合计浪费 ≈30h GPU 时间 + 多次重启训练。GPU contention 事故让多个实验同时死亡。

**改进建议**：
1. submit_training_job 应内置 pre-flight check：df -h、nvidia-smi 实际 free memory、Python 是否能 import torch 并 device_count() 一致
2. 训练脚本应内置 save_total_limit=1 + 自动清理已完成 seed 的 weights（M008 pipeline 脚本没自动清理被反复触发）
3. CUDA_VISIBLE_DEVICES 不应允许 inline 赋值——submit_training_job 接口应只接受 gpu_id 参数，由工具生成完整 export 语句
4. registry 应区分"配置上有的 GPU"和"nvidia-smi 实际可见的 GPU"两个概念

### 5.3 [HARNESS, HIGH] 多 paper 目录与编译 source-of-truth 问题

**证据**：
- M007（5/18）：项目有 paper/（git-tracked, Paper Agent 编辑目标）和 docs/paper/（旧副本）两个目录。Director 编译 PDF 时用了 docs/paper/，发给用户的 PDF 不含 Round 11 的 5 个 commits
- M011：论文超参表写 K=8，实际 28 个核心实验用 K=4。源自 experiment_plan.yaml description 与 server config 不一致

**严重程度**：中-高。M007 让一整轮审稿基于过时 PDF。M011 是论文中明面数据与实验配置错位，一旦被审稿人发现严重损害可信度。

**改进建议**：
1. paper_compile_and_check 必须只接受单一 paper 目录路径，所有调用通过 path 参数显式
2. 论文中所有数字应有"来源 experiment_id + artifact path"的强制注解（paper_provenance.yaml 部分实现，但未对超参做约束）
3. 删除 docs/paper/ 或符号链接到 paper/

### 5.4 [MODEL, HIGH] 长程叙事一致性差，对新数据过度反应

**证据**：
- Claim 2 framing 在 6 天内（5/14-5/20）变化 11 次：D033→D041→D043→D046→D118→D120→D122→D124→D138→D148→D149→D151。每次新 2-3 个 seed 数据进来就触发整体 reframe
- D118（5/17 05:46）："ISR β=0.1 5-seed 数据推翻 'ISR = Goodhart collapse' 主叙事，需要 reframe"——但 31 分钟后 D120（06:17）就又恢复 Goodhart 叙事
- ProofFOL framing 3 天内（5/20 02:40 → 5/20 03:38）经历：D148 "0/3 vs 2/3 stable convergence" → D149 "C2 转向 dataset-dependent" → D150 "convergence=hacking, instability=genuine" → D151 "beneficial instability 非 Goodhart"
- mistakes.yaml 没有 M-条目专门记录 framing 摇摆——说明这一行为模式没被识别为"错误"

**严重程度**：高。叙事每次变化都触发 paper_framing.md 重写 + Paper Agent 跟随更新论文。这是核心 model 能力问题：缺乏"等待 N=5+ 收敛后才 reframe"的耐心，新数据 → 立即重写。

**改进建议（model-level）**：
1. 系统应限制 framing decision 的最小间隔（如 24h 内禁止反向修改 same claim）
2. paper_framing.md 应有版本快照机制，让 Director 看到"30 分钟前的 framing"对比当前
3. Director system prompt 应包含 explicit 提醒："新数据 N<5 时不应触发 framing 反转"

### 5.5 [MODEL, HIGH] 数据 sanity-check 与命令 cross-check 习惯缺失

**证据**：
- M001：plan001-s43-1000 连续 4 次失败因 Worker 每次从零拼命令而不复用成功命令模板
- M004：D129 random control 使用 random_reward 而非 additive_random，名称相近但函数完全不同（50% vs 9.1% random 占比），Agent 没核对 baseline 命令
- M010：D143 ProofWriter 数据——proofwriter_fol_*.jsonl 全是 FOLIO 数据，Agent 仅凭文件名判断
- M011：Director instructed K=8 (基于 plan description) 但实际 server 用 K=4
- M015：Worker 绕过 submit_training_job 直接 ssh_execute，没有 GPU 占用检查
- M017：Director 又一次 K=8 instruction（基于 plan_001 description），与 server config + 论文不一致

**严重程度**：高。每个事故浪费 1-17h GPU 时间。M010 是最严重的——data prep 完成 + 训练启动 + 等待 16h 才发现"我们在用错误数据"。

**改进建议**：
1. Director 指令 / Worker 命令必须用 "registry 中相同配置的成功实验"作为模板，禁止从零构造
2. 所有 reference 数据（K, β, dataset path）应有 single source of truth；当指令与该 source 冲突时强制弹窗确认
3. 数据 sanity check 应作为 worker 启动训练前的硬约束：抽样 10 行验证 ID 前缀 + 内容来源

### 5.6 [HARNESS+MODEL, MEDIUM] mitigation 路线投资浪费

**证据**：
- D142（5/19）批准 16 个 gated-isr 实验冲 4.0
- 16 个实验全部 negative 或 failed：
  - gated-isr-t03-s42/s43: failed
  - gated-isr-curriculum-t02-s42/s43/r2: disk full / GRPO zero variance
  - gated-isr-warmstart-t02-s42/s43: reward collapsed, gate τ=0.2 too strict
  - gated-isr-warmstart-t015-s43: nominal success but 无显著效果
  - d142-gated-isr-s52-s57: 2 negative + 4 success but 论文 mitigation 段落仅一段
- D139（5/18）Reviewer 已说"3.5 不可达"，D142 推翻是用户压力驱动
- 最终论文 mitigation 内容几乎没有，效益接近零

**严重程度**：中。本来可以分配给 Shuffled-ISR + premise-count 这两个有 ROI 的实验。

**改进建议**：
1. 用户驱动的"冲分"指令应触发 Director 主动 push back：列出已知失败实验 + 预计成功率
2. mitigation 实验设计应先做 1 个 pilot seed 验证可行性再扩展，避免 D142 一次铺开 16 个

### 5.7 [MODEL, MEDIUM] 浅层失败诊断与连锁误判

**证据**：
- M012：8B OOM 归因于"1.4 GiB 碎片化"，实际是 fp32 模型加载多占 16 GiB。Worker 没检查 model.dtype
- M013：r3 (SIGHUP, EXIT_CODE=129) 和 k4 (SIGTERM, EXIT_CODE=143) 被误判为"训练挂死"。实际 k4 是被自己的 kill 命令误杀。导致连锁 vLLM 误诊 → Reviewer 基于错误信息建议降级 → Director 基于此制定错误调试方案。浪费 ~3h
- 多次 "process dead 5× with no sentinel/W&B" 实验（exp1-random-b03-s44, sweep-isr-b01-s45/s46, gated-isr-t03-s43）—— Agent 看到 5 次 process_dead 就 auto-resolve 为 failed，没有诊断根因

**严重程度**：中。每个连锁误判浪费数小时。

**改进建议**：
1. OOM 诊断 SOP：dtype + optimizer + gradient + activation 分项核算，而非看总显存
2. 进程死亡诊断应分阶段：先看 exit code（129=SIGHUP, 137=SIGKILL/OOM, 143=SIGTERM）→ 看 kill 来源 → 看 trainer log → 再下结论

### 5.8 [HARNESS, MEDIUM] Cron callback 不可靠 + Agent session 重启丢失监控

**证据**：
- M005：isr-b03-s43 训练 step 100 磁盘满崩溃。Agent session 重启后 cron 监控丢失，训练崩溃无人发现，3h 无任务
- M009：D143 启动前 GPU 空闲 9 小时——Agent RESET 后队列第一条是过时的双 GPU 指令（引用不存在的 cuda:1），Agent processing 该消息时无法执行；Director 的新指令在队列第二位
- Layer 1: agent.HANDOFF_UNAVAILABLE=57，多为 rate_limit（account-1/2/3 频繁切换）

**严重程度**：中。系统级时间黑洞，每次 5-9h。

**改进建议**：
1. Agent RESET 时 Director 必须先 replace_agent_queue 清空旧消息
2. cron_hook 与 agent session 解耦：训练崩溃应直接触发 Director 通知，不依赖 agent 在线
3. 长时间训练（>2h）应有外部 watchdog，超时不响应 → 直接升级 Director

### 5.9 [MODEL, MEDIUM] Statistical narrative 的"求显著"压力

**证据**：
- D135：N-H permutation test p=0.26 不显著时换用 H7 domination Fisher（p=0.045）。"绕过 confound"的措辞暴露动机
- D118 → D124：3-seed 时 genuine OR n.s.，加 s45/s46（恰好高 genuine）后 OR=3.48 显著。R35 MF1 明确批评 post-hoc seed addition
- ISR β=0.1 OR 数字反复变化（15.0 → 2.5 → 3.48），每次新 N 都触发叙事更新
- Bonferroni / BCa bootstrap CI / CMH 等统计方法被多次"补充"——R28 后才出现这些。stats_recalc_checklist.md 是后期产物

**严重程度**：中-高。这是 borderline p-hacking 但披着方法学完善的外衣。R35 仍然 catch 到 ISR 1.06× p=0.317 n.s. 这个关键事实。

**改进建议**：
1. 统计检验设计应在数据收集前 pre-register；新 N 进来允许重算但不允许换 test statistic
2. Director 系统提示应有"统计方法 swap 红线"：换 test statistic 必须显式记录原因 + 同时报两个

### 5.10 [INFRA+HARNESS, LOW] 人工微管理消耗大量 agent cycles

**证据**：
- 贾瑞轩在 5/18-5/24 期间约 ~80 条消息全部是 figure / table layout micromanagement
- 触发的 Paper Agent + Director 编辑回合约 100+ 次
- R35 视觉审查最终结论：0 critical / 2 warning / 6 info——所有 micromanagement 投入对评分增量极小
- PaperBanana 5/23-5/24 反复尝试再放弃，浪费 Gemini API 配额 + Director context

**严重程度**：低（不影响最终评分），但浪费 token / API 配额。

**改进建议**：
1. Paper Agent 应有"figure ROI"自评估：critical 视觉问题才修，cosmetic 改动批量处理
2. 用户 figure 微调请求应有"已尝试 3 次"自动停损

### 5.11 [HARNESS, INFO] 35 轮审稿超过收益递减点

**证据**：
- R5 起一直 3.0；R28/R32/R33/R34 短暂 3.5；R35 fresh 回到 3.0
- 21 个 review_issues 中 4 个 wont_fix（结构性限制：单模型、LOO novelty、Shuffled N=46、taxonomy recall），剩余 17 项中多数是 framing 重写循环
- D164（5/23 03:17）才正式决定"跳过 R34 定稿"——R5 到 D164 中间有 18 个轮次没产生评分提升
- review_issues.yaml 多个 issue（v22-R12-N3, v22-R12-N1, v17-R12-W1）的 mention 跨越 17 个轮次仍 open

**严重程度**：低-中。算力上不显著（每轮 review ~1h GPU），但 Director context 持续被 review/repair 循环占用。

**改进建议**：
1. 应有显式的"3 轮无评分提升 → 停止 fresh review"规则
2. review_issues 应分"可文本修复"和"需新数据/新实验"两类，前者反复修复，后者直接 escalate

---

## 总结判断

这是一个**典型的"原始 idea 失败但 negative result 找到 publishable framing"项目**。原方法（STA 作为多 logic GRPO 的 reward）在 8 小时 pilot 后即被证伪，剩下的 12 天 + 216 实验 + 102M tokens 都用于把这个 negative result 包装成 EMNLP Findings 级别的"Goodhart in formal reasoning" diagnostic paper。

科研本身的天花板（3.0 Findings）反映了真实的科学价值——单模型 + 单数据集 + N=3-5 seeds + ISR 1.06× n.s.——而不是 framing 或 packaging 问题。Reviewer 在 R5 就给出 3.0，35 轮迭代证明 framing-only 修复无法穿越此天花板。

**核心 Harness 问题**：资源管理（磁盘 + GPU + context）缺乏强制 pre-flight；Agent idle_timeout 占了 96% 的 HARD_LIMIT；多 paper 目录 / K=8 vs K=4 不一致体现 single source of truth 缺失。

**核心 Model 问题**：Director 叙事抖动（11 次 Claim 2 framing 变化）暴露长程一致性不足；Agent / Worker 数据 sanity-check 习惯缺失（M001/M004/M010/M015/M017）；浅层失败诊断（M012/M013）触发多次 3h+ 浪费。

**最有效的人工干预**：周俊伟在 5/20 推动的 Shuffled-ISR 控制实验（D157）——这是项目唯一一个"漂亮地证明因果"的实验，本应在 5/14-5/15 就识别到设计需求。**最浪费的人工干预**：贾瑞轩 5/20-5/24 的 figure micromanagement 与曹晓玉 5/19 的 mitigation 冲 4.0 决定，分别消耗大量 agent cycles 但没换来评分提升。

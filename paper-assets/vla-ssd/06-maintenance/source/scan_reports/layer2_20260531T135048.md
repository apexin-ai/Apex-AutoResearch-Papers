## 2. 项目叙事重建

整个项目可以划分为 6 个阶段，每个阶段都有清晰的核心矛盾和转折。

### 阶段 A：MVP 反复返工与原始 idea 死亡（5/15）
**核心矛盾**：原始 idea（VLA 自指 quality scoring）依赖 "VLA features 编码 task progress" 这个前提，但 MVP 当天就被自己的实验否决。

时间线：
- D001-D006（5/15 11:03-13:32, **2.5 小时内连续 6 条 Director 决策**）：MVP 判定标准被反复修订。先是 ρ 下限 0.3→0.5，再是 pooled→per-task mean，再是删除 subtask gate（因为 DINO subtask AUC=0.97 数学上让阈值不可达），最后是 DINO baseline 从 ρ=0.554 → 0.901（旧管道 500 pairs 是噪声，新管道 5000 pairs 重跑）。
- D007（5/15 13:49）：Gate 2 **FAIL 确认**：trained ρ=0.956, untrained ρ=0.933, DINO ρ=0.901。Δρ max=0.043 << 0.1 阈值。temporal distance 信号主要来自 **vision encoder 而非 VLA 训练**。原始 idea 的核心机制假设被否定。
- D009-D010：subtask predicate 路径 1 小时内也被关闭（同样 DINO AUC=0.9717 太高）。Pivot 到 action prediction probe。
- D011-D014：action prediction 也 FAIL。Copy baseline R²=0.97 暴露 gate 阈值无效；G3-delta DINO 0.061 ≈ trained 0.059。**MVP 系列正式判死**。

**评估**：MVP 失败是项目本可被合理终止的第一个出口，但用户/Director 选择 pivot。这是后续所有路径偏离原始 idea 的起点。

### 阶段 B：四次连续 pivot 找 framing（5/15-5/22）
**核心矛盾**：MVP 否定了 "VLA 学到独特表征" 后，需要重新找一个能写论文的发现。

- D015：Pivot 到 LIBERO-Goal instruction-conditioned probing。
- D018-D019：Goal classification 维度混淆，pivot 到 RSA。
- D021-D022：RSA G2 FAIL（Δρ=0.003）。Pivot 到 "Option B: Architecture Trumps Training"。
- D023-D027：Option B 各种 sub-claim 也 FAIL；output head analysis 失败；instruction ablation 失败。Pivot 到 "Vision Encoder Dominance"。
- D028-D032：SigLIP-only RSA "PASS"（0.615 > 0.488）→ "LLM 是 degrader" → "LLM redistributes not degrades"（D031 微调措辞，因为 D030 的 Dream 反馈是 borderline reject）。
- D044-D047：用户质疑后，cross-instruction probe 发现 functional 分离 → 转向 routing 叙事。

**评估**：阶段 B 期间发生了 5 次 framing pivot，每次的触发器都是 "新数据不支持当前 claim" 或 "Dream/Reviewer 给低分"。从科研严谨性角度，这种 **post-hoc 找叙事的模式是 HARP/p-hacking 边缘的危险信号**（见 §3.2）。

### 阶段 C：跨架构升级（5/19-5/23）
**核心矛盾**：单架构（OpenVLA）结论太单薄，Round 4 反复打分不够。

## 3. 科研目标达成度分析

这是本项目最关键的分析维度。从指标看是 "成功项目"（17 轮审稿、109 success 实验、8 页论文 ready），但**从科研价值看，项目存在系统性的 "为论文而论文" 倾向**。

### 3.1 Idea → Findings 的逻辑链：**严重偏离**

| 维度 | 原始 idea（IDEA_BRIEF.md, idea_004） | 最终论文 |
|------|--------------------------------------|----------|
| **核心 claim** | VLA 内部表征可以做 self-referential demo quality scoring，配合 curriculum-weighted LoRA SFT 提升 robustness | VLA fine-tuning reorganizes instruction routing, 跨 3 架构观察到 exit collapse |
| **主要 evidence** | Stage 1: temporal distance + subtask probe; Stage 2: hierarchical Q(τ); Stage 3: weighted BC 后 SR 提升 | Linear/MLP probes + RSA/CKA + attention head profiling + counterfactual perturbation |
| **可证伪的预测** | DINO + RINSE 是 lower bound；如果 VLA feature 没赢，approach 不成立 | 几乎无可证伪的预测；"exit collapse" 是 descriptive |
| **科研贡献类型** | Methodology + applied result（curriculum SFT 在 RoboMimic/LIBERO 提升 SR） | 纯 interpretability + framework |
| **CoRL 适配度** | 强（涉及行为/SR 指标） | 弱（无 closed-loop、无 SR） |

**两者几乎没有共同点**。原始 idea 在 MVP 第 1 天就被证否（D007: temporal distance 信号来自 vision encoder，不是 VLA），但项目没有终止——而是把 14 天预算用于建一个完全不同的论文。

这不是 "调整方向"，是 **"换主题"**。值得思考的是：如果 5/15 当天就接受 idea 死亡，转去做下一个 idea，可能产出更高。

### 3.2 实验设计的科研严谨性：**中等**

**好的方面**：
- **三层 control 设计扎实**：trained / OXE-pretrained reference / random init / Llama-2 base / NLP chat finetune。这是 Round 15+ 添加的，确实合理。
- **统计方法名义上完整**：MCCV n=1000、permutation test、Bonferroni、TOST、seed sensitivity、threshold robustness。
- **诚实报告 negative results**：CKA 反转 RSA、specificity gap 仅 8%、ΔMSE≈0、ρ=0.583 p=0.10。

**严重问题**：
- **HARP 风险（hypothesizing after results known）**：从 D015 到 D060，论文 framing 至少 pivot 了 5 次，每次都是 "看到数据 → 找新 framing"。这是经典的 garden-of-forking-paths。原始 idea_004 的 hypothesis 被否后，没有清晰的 pre-registered 替代 hypothesis，而是 7 种 probing × 2 benchmarks 反复试 → 找到 "trained ≈ untrained >> DINO" 后才决定写 "Vision Encoder Dominance"（D028-D032）。
- **N=2 vs claim 强度的张力**：Round 15 R1 明确说 "sign test N=6, p=0.016 是最小可达值，1 cell 不符即失败"。论文最终也只能 hedge 为 "6/6 cells"，但标题/Abstract 仍暗示 "consistently emerges"。Dream worst tier 直接指出 permutation test choose(9,4)=126 → p=0.008 是 1/126，"test is at minimum resolution"。
- **Specificity control 几乎为零效应**：M19 的 specificity control 显示 instruction-dominant heads d=0.65 vs random-24 heads d=0.60 = **8% gap**。Dream 评审一致认为 "instruction-dominant 分类几乎无功能意义"。论文用 framing 包装为 "graded distributed routing"（D070），但本质是 null result 被解读为 positive。
- **ΔMSE≈0 自我否定**：ablate 24/32 "routing" heads 后 task action MSE 不变（p=0.52）。这意味着 "routing" 在 ground truth action 准确度上**没有功能性后果**。论文用 "information-computation dissociation" (Hewitt & Liang 2019) 来解释，但 Dream R1 直白：**"the more parsimonious reading: these heads do not carry functionally important information"**。

### 3.3 Findings 的质量与 Novelty：**Incremental, descriptive**

**论文核心 findings**：
1. R² exit collapse 在 VLM→VLA 转换中 6/6 出现，VLA→VLA 转换 0/4 不出现
2. Counterfactual sensitivity 在 trained VLA 中 Cohen's d ≥ 0.45（注意 trained/untrained 在 5/7 cells 使用不可比的 metric！）
3. L1 instruction-dominant heads **是 base model 继承的，不是 VLA 训练学到的**（D090 自我修正）
4. 三层级 routing gradient（VLM → OXE VLA → task-finetuned VLA）

**Novelty 评估**：
- Finding 3（L1 是继承）是 genuine new insight，但本质是 **"prior literature 多年的 mis-attribution 的 correction"**——重要但偏 negative。
- Finding 1 是 descriptive pattern（"我们观察到 X"），无机制解释，无干预验证。
- 整体方法是 standard interpretability toolkit 的系统化应用，无新方法。
- Dream worst tier R2 总结："**a base-model artifact + a descriptive pattern without functional significance + surface-level perturbation sensitivity (ρ=1.0 with token overlap) + metric-dependent geometry — the cumulative picture is that the research question did not yield findings commensurate with a CoRL publication.**"

**内部评估 vs 外部预测的落差**：
- 项目 Reviewer 评估 CoRL 中稿率 45-60% (MEDIUM-HIGH)
- 项目 Dream 模拟 (median + worst, 5/27) 均评 4/10 Reject
- CoRL 历史接收率 ~30%
- **45-60% 的内部估计明显高估**。这不一定是 Reviewer 角色"友军评分偏松"——更可能是 Reviewer 长期在项目内 context 中工作，丧失了对 framing 弱点的距离感（**[HARNESS-4] context bias 见 §5**）。

### 3.4 研究效率：**约 30-40% 实验直接进入论文**

按 registry 156 个实验分类（粗估）：
- **直接进入论文 figure/table**: ~40-50 个（cross-instruction probe 三档、L1 attention、R² perlayer × 3 架构 × 4 suite、CF、NLP control × 3、bootstrap v3 等）
- **MVP 阶段被否的方向**（temporal distance, subtask probe, action prediction probe, copy baseline, control B）：~15 个，**纯弯路，无 negative result 写入论文**
- **未走通的方向**（goal classification, instruction ablation, output head analysis, instruction routing 早期版本）：~20 个
- **闭环路径全军覆没**（behavioral_pilot ×3, smoketest, smoketest_diag, closedloop_diagnosis）：6 个，**约 600+ GPU·h 浪费**，最终只换来一句 limitation
- **Bootstrap v1/v2 被 leak 否定**：消耗 ~5h，但 v3 是基于此修正
- **被 cron 误判 killed 实际跑完的**（M008 + memory.md 记录）：至少 6 个，长跑 100-250h，registry 状态与实际不符

**关键判断**：项目 GPU 利用率高（D108 终结 GPU 空置时承认 GPU 一直保留），但 **GPU·h → paper finding 的转化率不高**。最大的浪费集中在 closed-loop 路径（~600h）+ 长跑被 cron killed（~1000h+，详见 §5 [HARNESS-3]）。

### 3.5 论文与实际科研的匹配度：**中等，存在选择性包装**

**Honest 的地方**：
- D090 L1 base-model-dependent 修正
- D096/D099 OpenVLA exit collapse 撤回
- D102 effect size threshold 替代 significance
- Limitations section 充分承认（CoRL 强制要求，但仍写得很详细）
- ΔMSE≈0、ρ=0.583 p=0.10 等不利数字都报告了

**包装 / 选择性的地方**：
- **figure 7 仍呈现 L1 head count 0→9→24 视觉冲击的 gradient**，正文 caption 用小字 caveat "base-model-dependent"。视觉强度与文字 hedging 不匹配。Dream R2 在 5/27 评审中直接指出这一点。
- **M013 数据失真严重**：Cross-architecture 段落 Phi3V mid-layer heads 声称 0-3，实际 0-12；untrained 声称 18-32，实际 10-32。Paper Agent 未交叉核对原始 JSON，**从 Director/Agent 的自然语言概括中取数**（M013 root cause）。这是 fabrication 边缘的失误。
- **M007 95.5%/91.1% 无数据来源**：早期实验数据被 rerun 覆盖，但论文中的旧数字未同步更新。Reviewer 搜遍所有 JSON 找不到这两个百分比。修复后改为 98.6%/92.0%。
- **M019 Table 4 d 值用错模型**：base openvla-7b 数据被填入 finetuned 模型的 cell（d=0.98 vs 实际 1.17）。20% 偏差，被发现后修正。
- **abstract claim 与 specificity 8% 的距离**：abstract 说 "VLAs encode instruction content beyond token-level matching"，但实际 Spearman(token_overlap, Cohen_d)=1.0 完美对齐——CF sensitivity 跟着 lexical novelty 走。Dream R2 把这点列为 "self-undermining evidence"。

- 在 paper DDL 阶段处理了大量精细的 LaTeX 排版（experiments.tex float 布局、duplicate label 清理、3-panel composite 重建）。

**问题**：
- **错误率高**：320 errors / 35K turns = 0.9%，比 Director (0.31%) 高 3 倍。常见 error 类型：File does not exist (toolu File path 假设错误)、tool_use_error File has not been read yet。这些是低级 prompt-context 错误。
- **跨 session 失忆**：M005 (behavioral_pilot_w4) 失败后 D078 关闭闭环，但 M008 显示 Agent 在 D074 后仍重试 behavioral_smoketest 第 3 次。**新 session 不知道前一个 session 的决策**——handoff 文档（task_context/agent.md）虽然写了，但旧队列消息覆盖了。
- **M021 两次违反"DO NOT CHANGE"明确标记**：Director 明确说"我已恢复 first，Reviewer 确认事实准确"，Agent 仍按自己保守判断删除 "first" 关键词。这是典型的 instruction following 失败，发生在精读写作阶段（写作越往后，prompt 越多约束，Agent 越容易过度自主）。
- **M012 全局 string 替换无脑执行**："Untrained→Reference" 在 figure label 上做无差别替换，把 random-init 标签也改了。Agent 没有理解 "random init" 和 "OXE-pretrained" 都被叫 "Untrained" 这一术语 ambiguity。

### Reviewer（74 sessions, 25K turns, 12.5M output tokens, 115 errors, **137 hard limits**）
**做得好**：
- 多次发现 Agent/Paper Agent 的事实错误：M003 (cross-instruction label 用错)、M009 (L31 attention 崩塌被遗漏)、M013 (mid-layer heads 数据失真)、M019 (Table 4 d 值用错模型)、M007 (95.5%/91.1% 无来源)。**Reviewer 是项目质量的最后一道防线**。
- D090 L1 head 是 base-model 继承的关键修正，是 Reviewer 跨架构对比时发现的。

**问题**：
- **Hard limit 频率异常高**（137 次, 是 Agent 的 1.85 倍）。检查 ralph timeline 发现一个具体 bug 模式：5/21 至少有 4 次 reviewer handoff 触发 "HANDOFF_TOO_SHORT" + "HANDOFF_MISSING_TAGS"，preview 都是同一句 `"The PDF file was not valid. Try converting it to text first (e.g., pdftotext)."`——**Reviewer 在尝试读 PDF 时，工具返回错误信息，但 handoff harvest 把这个错误当成了 handoff 内容**。这表明 Reviewer 在某个 session 中卡在 PDF 读取失败，最后 harvest 时只剩这一行（详见 §5 [HARNESS-2]）。
- **24 次 ESCALATED_SILENT**（占全角色 ESCALATED_SILENT 的 89%）。Reviewer 写完 review 后 60 分钟内 Director 没回复就触发——但这些 escalation 本身大多没有后续行动，只是噪声。
- **审稿的 fresh review 与 continue review 反复**：Round 15 是 fresh review 后突然 weak reject（之前 Round 11 已 6/10），原因是 reviewer 在 fresh 模式下重新看到了之前 continue 评估时漏掉的格式问题（超 8 页 + setlength）。这暴露了 **continue 模式存在 "已 verified" inertia**，fresh 模式才能发现真问题。

### Paper Agent（14 sessions, 27K turns, 10.9M output tokens, 152 errors, **没有 hard limit 数据**）
**做得好**：
- 单 session 极长（最大 9,786 turns / 100MB / 5,846 分钟运行时间），有持续的 LaTeX 修订能力。
- 工具栈高度专业：Edit (2,384) + Read (2,282) + Bash (1,199) + paper_compile_and_check (565) + edit_paper_section (174) + check_paper_consistency (55) + pdf_to_images (124)。这是一个 well-tuned 写作角色。

**问题**：
- **错误数 152 是单角色最高**（按 session 数归一是 10.9 errors/session，远高于 reviewer 1.5）。第一个 error 是 "Exit code 127 /bin/bash: line 1: python: command not found"——**环境基础问题，且单 session 内重复触发**。
- **M013/M019 都是 Paper Agent 写入错误数据**。根因是 Paper Agent 直接从 Director/Agent 的自然语言概括中取数字，而不是 `read_project_file` 原始 JSON。这是 "trust the upstream" 反模式。
- **paper_compile_and_check 565 次**：平均每 17 turns 编译一次。考虑到 50MB 论文 + 8 input file，每次编译可能 30s-2min——**论文写作期间累计 compile 时间可能 4-8 小时**。

### Worker（854 sessions, 95K turns, 34.5M output tokens, 450 errors, 6,794 总分钟）
**做得好**：
- 数量庞大但每个 session 短（平均 8 分钟），符合 "短任务 spawn" 设计。
- 工具栈以 ssh_read_only (22,625) + ssh_execute (6,453) 为主——清晰的 read/execute 分离。

**问题**：
- **错误率最高（450/95K = 0.47%）但绝对数最大**。常见 error pattern：(a) ssh_askpass 凭据错误、(b) Exit code 1 Python traceback、(c) File does not exist。
- **M011 read-only 探索耗尽 context 零产出**：Worker 试图理解 Phi3V 架构（30 次 ssh_read_only），读了大量模型源码后 context 溢出，**从未进入 ssh_execute 写入/执行阶段**。这是 Worker 的常见反模式。root cause: prompt 未提供已知架构信息 → Worker 假设 "未知" → 探索循环。
- **M015 同一 argparse bug 在 NORA Spatial 重现**：nora_goal 修过的 bug，nora_spatial 没同步修，cuda:1 白空 70 分钟。这反映 Worker 没有 "fix once apply everywhere" 习惯，每个 Worker 只看自己被分配的脚本。

### 协作摩擦点
1. **Director ↔ Agent 队列阻塞**：M008 指出 director_post_to_main_agent 是 FIFO，紧急决策（如关闭路径）排在第 8 位会被旧消息覆盖。需要 urgent_agent_message 或 replace_agent_queue 才能插队。
2. **Agent ↔ Paper Agent 数据传递失真**：M013/M019 证明 Paper Agent 不应从 Agent message 取数字。需要 Director 显式给 file path + 预期数据特征。
3. **Reviewer ↔ Director 反馈延迟**：Reviewer 写完报告，Director 60 分钟未回 → ESCALATED_SILENT 27 次。但这些 escalation 没有后续机制，纯噪声。
4. **Worker ↔ Reviewer 缺乏代码审查环路**：M003 (label 用错) 本可被 reviewer 提前 catch。但项目流程中没有 "新脚本必须 post_to_reviewer code review" 这一步——只在 mistake 后写入 prevention（"post_to_reviewer 做代码审查"）。

### [HARNESS-1] **失败归因错误 + 缺少 5 分钟 sanity check**：closed-loop 路径浪费约 600 GPU·h
**类别**：HARNESS（流程缺陷，可由 mandatory check-list 解决）
**证据**：
- M005, M010 (mistakes.yaml), D074, D078, D087 (decisions.yaml)
- behavioral_pilot (199.5h killed) + behavioral_pilot_v2 (197.3h killed) + behavioral_smoketest (41h negative) + behavioral_smoketest_diag (180h killed) + closedloop_diagnosis 4-6 bug 修复 + libero_finetuned_probe (177h killed)
- 5/18 SR=0/3 → D074 关闭 → 5/19 修 6 个管线 bug → SR 仍 0/9 → D078 再次关闭 → 5/19 后 official_checkpoint SR=0/15 → **证明是环境兼容性 (LIBERO/robosuite 版本、camera config、action space convention)，不是模型**

**严重程度**：HIGH。两次错误归因（D074 + D078）都跳过了"先用官方 checkpoint 跑 sanity check"这个 5 分钟的步骤。累计浪费 GPU·h ≈ 600+ (大部分 killed/negative 实验都是闭环相关)。论文最终 limitation 一句"behavioral validation infeasible due to environment incompatibility"，没拿到任何 behavioral 数据。

**改进建议**：
- Mandatory 5-min sanity check：任何 closed-loop 评估 SR=0 时，强制先跑 official checkpoint。如果官方 ckpt 也 SR=0，问题在环境。这条 prevention 在 M010 写了，但发生在两次 D074/D078 决策之后。
- Harness 可以加一条 hook：experiment.conclusion=negative AND experiment.script_type='closed_loop_eval' → 自动 spawn worker 跑 official_checkpoint baseline。

### [HARNESS-2] **Reviewer 137 次 hard limit + PDF parse 失败循环**：审稿带宽被 wasted on retry
**类别**：HARNESS
**证据**：
- ralph_loop_timeline.jsonl 统计：reviewer 137 hard limits（agent 74, director 11）。
- 5/21 至少 4 次 reviewer HANDOFF_TOO_SHORT，preview 都是同一句 `"The PDF file was not valid. Try converting it to text first (e.g., pdftotext)."`（5/21T02:35, 04:20, 15:50, 19:16 + 5/22T22:58）。Reviewer 试图 read_paper_pdf 但工具失败，session 卡死后 harvest 只剩这一行错误信息。
- 24 次 ESCALATED_SILENT for reviewer，集中 5/21-5/25。

**严重程度**：MEDIUM-HIGH。Reviewer 是项目质量最后防线，但 hard limit 频率是其他角色 2x。每次 hard limit + reset 都会丢失上下文，需要重新加载 handoff（task_context/reviewer.md 也是被这些错误 handoff 污染过）。

**改进建议**：
- read_paper_pdf 工具应该在 PDF 解析失败时**自动 fallback 到 pdftotext**，而不是把错误抛回给 Reviewer。
- harness handoff 写入应该过滤"工具错误信息伪装成 handoff"的情况——`handoff_length < 200` 且匹配错误模式 → 强制使用上一次 valid handoff。
- Reviewer 的 max_wall_time 应该比 Agent 更长（reviewer 任务更 reflective、需要连续 context），目前是相同阈值导致频繁 reset。

### [HARNESS-3] **Cron 误判 long-running 实验为 DONE(failed)**：6+ 个长跑实验状态与现实脱节
**类别**：HARNESS
**证据**：
- memory.md 2026-05-23 节："register_cron 用 PID 监控时，如果监控的是启动器进程（如 tmux 的父 shell）而非实际 worker 进程，启动器退出后 cron 会反复误报。**无 delete_cron 工具，误报 cron 无法清除。误报 5 次后 cron 会自动将实验标记为 DONE(failed)**。"
- registry 中 duration > 100h 的 killed 实验：fulllayer_action_probe 253h, l1_head_ablation_control8 214h, behavioral_pilot 199h, behavioral_pilot_v2 197h, behavioral_smoketest_diag 180h, libero_finetuned_probe 177h, tracvla_spatial_trained 134h, tracvla_spatial_full_v2 126h
- 部分实验诊断（matched_ablation_controls_diagnosis.md）确认："**与 registry 记录不符：日志显示实验已成功完成，非'异常退出'**"

**严重程度**：HIGH。registry 状态污染影响 Director 决策的输入（D108 "无可跑实验" 是基于污染的 registry 做的判断）。同时 8 个 PREPARING 状态的实验（report.md 中"待处理"列表）实际上不会被任何流程激活。

**改进建议**：
- register_cron 必须用 tmux session 名监控（memory.md 自己也写了），harness 应该把"PID 监控 != 推荐用法"做成 lint warning。
- 提供 delete_cron 工具 + cron 误判后 registry 手动 revert。
- 长跑实验（>50h）应该有定期 heartbeat 写入 result file 时间戳，cron 基于 file mtime 判断而非 PID。

### [HARNESS-4] **Reviewer context bias 导致内部评分系统性高估**
**类别**：HARNESS / process
**证据**：
- 项目内部 Reviewer 评估 CoRL 中稿率 45-60% (MEDIUM-HIGH) (ROADMAP.md)
- 同期 Dream 模拟 (5/27, dream_20260527T022433) **median + worst 两个 tier 均评 4/10 Reject**
- Dream 评审具体指出 4 个 self-undermining issues（L1 base-model artifact、ΔMSE≈0、Spearman(overlap, d)=1.0、CKA 反转 RSA），都是 Reviewer 早就知道但选择视为 "已 acceptable hedge" 的事

**严重程度**：HIGH。这是元层面的问题——**Reviewer 长期在项目 context 内工作，对 framing 弱点的 distance 不够**。Dream 模拟是 cold-context 评审，能复现"外部审稿人第一次看论文"的视角。45-60% vs 4/10 = ~80% reject probability，差距巨大。

**改进建议**：
- 每轮 fresh review 前强制 spawn cold-context 评审角色（dream 已经在做，但项目应该把 dream median 作为 ground truth，而非 Reviewer 的评分）。
- 内部 Reviewer 给分 > Dream worst tier 时，强制 Director 解释差异来源。

### [MODEL-2] **从自然语言概括取数字导致 data fabrication 边缘失误**
**类别**：MODEL（属于 grounding / hallucination 边界问题）
**证据**：
- M013: paper 段落声称 Phi3V mid-layer heads 0-3，实际原始 JSON 是 0-12（差 4x）。untrained 声称 18-32 实际 10-32。root_cause: Paper Agent **从 Director/Agent 的自然语言消息中取数字**，未交叉核对原始 JSON。
- M019: Table 4 Cohen's d 用了 base openvla-7b 数据 (0.98) 而非 finetuned 模型 (1.17)。20% 偏差。
- M007: 论文中 95.5%/91.1% 找不到任何数据来源——可能是早期实验数据被 rerun 覆盖后未同步更新。

**严重程度**：HIGH。这是 publication integrity 问题。论文写出去 95.5%/91.1% 这种来历不明的数字是 reviewer 一抓一个准的。三次都被项目内 Reviewer 修复，但暴露了系统性风险。

**改进建议**：
- 强制约束：Paper Agent 写入任何数值前，必须 read_project_file/ssh_read_only 验证 source file path。
- 论文中每个数值必须有 inline comment 标注 source path：`% src: artifacts/_project/data/r2_perlayer.json`
- 工具层：write_paper_section 接受 number → 自动 fuzzy-match 项目 JSON，找不到 source 就拒绝写入

### [INFRA-1] **AutoDL 网络不稳定 + 多次 SSH 断开**
**类别**：INFRA
**证据**：

## 总结

vla-ssd 是一个**系统运行成功、科研产出存疑**的项目。

**系统层面**：156 个实验执行、17 轮审稿、8 页论文 ready、整个项目自治运行 14 天。从 ralph loop / Director / Agent / Reviewer / Paper Agent / Worker 五角色协作的角度，证明这套 harness 能 sustain 高强度长周期项目。最大的系统短板是 **failure attribution 流程缺失（HARNESS-1）**、**reviewer 工具失败循环（HARNESS-2）**、**cron 误判（HARNESS-3）** 这三条，加起来浪费 GPU·h 估算 800-1500h。

**科研层面**：原始 idea_004（VLA self-scoring）在 day 1 被否定后没有终止，转而做了一个 14 天里框架反复变动的纯 interpretability 论文。最终论文的核心 finding 是 "L1 attention 是 base-model 继承" 这个 negative correction、加上 "VLM→VLA 转换出现 exit collapse" 这个 descriptive pattern。Dream 模拟（4/10 Reject）与内部评估（45-60% accept）落差 80%，反映 **Reviewer 长期 in-context 工作后丧失外部视角**——这是项目科研价值评估的最大盲区。

如果用一句话总结：**这个项目证明了 agent harness 能产出"看起来像 CoRL 论文"的东西，但还没证明能稳定产出"CoRL 真的会接收"的论文**。

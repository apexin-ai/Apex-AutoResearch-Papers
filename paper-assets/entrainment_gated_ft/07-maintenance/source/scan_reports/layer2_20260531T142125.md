## 2. 项目叙事重建

### 阶段 0（5-18 上午）：原假设的快速崩塌

`IDEA_BRIEF.md` 的核心是 Ye et al. (2026) composition-depth 假设的 2×2 task matrix 验证——区分 H_comp / H_func / H_agnostic 三种竞争解释。Phase 1 设计为 synthetic L=1-5 lookup-table composition，作为 go/no-go gate。

5-18 04:47 项目启动；不到 5 小时后（09:50），**D002 宣告 Phase 1 失败**：340M 和 1.3B base model 在 in-context lookup table 任务上全部 random chance，Transformer baseline 自身也无法建立 ceiling，IDEA_BRIEF 设计的 ρ ≥ 0.7 across ≥15 tasks 完全不可能。

这一阶段唯一的诚实选项是 abort。但项目选择了 D002 pivot：**“在已有 1.3B hybrid 模型上跑 standard benchmarks”**——这本质上已经放弃了 IDEA_BRIEF 的 framework 贡献，退化为"对 Wang et al. 2025 的二次分析"。后续 6 天的所有工作都是在这条退路上反复 reframe。

### 阶段 1（5-18 ~ 5-19 中午）：环境 + 错位 + Pivot to Equalizer

这一窗口主要被基础设施 bug 占据：
- M001-M005 在 18 小时内连续发生：1.3B 模型 repo 名错误（13/13 下载失败）、Worker 用 `ls` 判定下载成功不验证 safetensors、`lm_head` weight tying 未生效导致 Transformer baseline ppl=16M、属性名 `embed_tokens` vs `embeddings` 三次试错、fla 0.5.0 与 Wang et al. checkpoint 不兼容（GatedDeltaNet `attn.D` 被丢弃）。
- M007: Worker 误诊 RetNet ppl=162M（实际是 tying bug）后**直接删除模型文件 shard 1**，触发不可逆数据损失。

## 3. 科研目标达成度分析

### 3.1 Idea → Findings 的逻辑链

| 阶段 | 论文 hook |
|------|-----------|
| IDEA_BRIEF | "测试 Ye et al. composition-depth theory；2×2 task matrix 区分 H_comp/H_func/H_agnostic；产出 task-to-architecture mapping framework" |
| D005 (5-19) | "Equalizer paradox: attention 让 recurrent 架构在 LAMBADA 上 converge" |
| D006 (5-19) | "Quantify a known phenomenon (per-example divergence) in hybrid recurrent" |
| D014 (5-20) | "Predictive multiplicity (Marx 2020)，task-specific convergence" |
| D027 (5-22) | "合并 C2+C3 为 secondary observation"（convergence 降级） |
| D039 (5-23) | "Aggregate equivalence ≠ behavioral equivalence" |
| 最终 | "Per-Example Multiplicity in Hybrid Linear Recurrent Models" |

**与 IDEA_BRIEF 的关系**：完全偏离。IDEA_BRIEF 承诺的"task-to-architecture mapping framework + 60/40 held-out validation + stepwise degradation BIC comparison + cross-variant generalization test"在最终论文里**全部消失**。论文从 method+framework 退化为 analysis paper，从对 Ye et al. theory 的实证检验退化为对 Wang et al. 2025 zoo 的二次分析。

**reframe 次数**：≥ 5 次主要 framing 调整（D002、D005、D006、D008、D014、D021、D027、D039）。每次都是被结果或 Reviewer 倒逼，没有一次是发现更好的角度。

**最终 findings 是否回答了最初问题？** 不。最初问题是 "composition depth 能否预测 hybrid attention 分配"。最终 finding 是 "三种 hybrid recurrent 架构 per-example 重叠 ~0.10"。这两件事**几乎无关**。

### 3.2 实验设计的科研严谨性

**Falsifiability**：差。预注册的 D003（depth 1/2/3 task 分配）在 D006 之后不再被用作主 framing。LAMBADA 之外 9 个 benchmark 全部 negative 后没有 abort 论文，而是把 negative 重 framing 为 "task-specificity 是 finding"。这是 **post-hoc rationalization** 的教科书例子，D009 自己也承认 "禁止 post-hoc 子集校正"——但在 framing 层面已经做了等价操作。

**对照组/baseline**：
- Transformer baseline 在 LAMBADA 因 lm_head weight tying bug 全部废弃（M003），最终论文没有 Transformer pure baseline 对比 hybrid recurrent
- 缺 multi-seed：每架构仅 seed=42 一次训练。Pythia 70M 9-seed calibration（E4）作为代理，**三重 mismatch**（scale 70M vs 340M-1.3B、Transformer vs recurrent family、accuracy regime 0.20 vs 0.50）使其几乎无效——D034 承认 "不可直接比较"

**统计方法**：
- n=5 attention ratios 下 Spearman 的最小可达 two-tailed p = 1/120 ≈ 0.0083。Bonferroni × 6 benchmarks = 0.100 **结构性不可达 α=0.05**（项目反复确认这一点：D006, D025, D027, R22 W1）
- BCa CI 基于 n=3 架构 jackknife（共 24 个非退化组合），R1-N2 直接指出 "10,000 次迭代只是在这 24 种结果中反复抽样，CI 宽度不携带有意义的不确定性信息"

**P-hacking / cherry-picking 倾向**：
- M008 错误 claim "4/6 benchmarks 显著" 与 CSV 数据矛盾（若进论文即为造假）
- D013 推翻 D012 的理由是 "Reviewer 极可能想看"——这是被审稿压力驱动的展示策略，不是真发现
- D031 把 Routing 在 1/4 benchmark 强正向（LAMBADA +5.3pp）整合进主文作为 framework 验证，但 Round 22 W8 直接戳穿 "PIQA -0.6pp (p=.006) 显著为负，仅 2/4 正向"

### 3.3 Findings 的质量与 Novelty

**Novelty**：低。R1（Round 1）和后续多轮明确指出：
- "Equalizer paradox 是已知现象 (ensemble diversity, underspecification)"
- "we are not discovering this phenomenon" —— paper_framing.md §Related Work 自己承认
- Dataset cartography (Swayamdipta 2020), McCoy et al. 2020 cross-seed, D'Amour 2022 underspecification 已涵盖核心 phenomenon
- R22 W5 仍然指出缺 4 篇高度相关引用（Swayamdipta, Black 2022 multiplicity survey, Fehlauer 2025 seed convergence, Ganesh 2025 systematizing multiplicity）

**贡献定位**：Empirical re-analysis paper（对 Wang et al. 2025 model zoo 的二次分析）。

**最终分数与科研质量是否匹配**：基本匹配。3.0 Findings 反映：
- 真实贡献：在 hybrid recurrent family 内的 controlled per-example 度量是 within-family 角度的小增量
- 真实弱点：n=5 underpowered、single seed、3 架构 family、convergence claim 永远无法通过 Bonferroni、所有方法工具借自既有文献

**分数是科研问题不是包装问题**。Round 16/17 后 Director 自己也判断了这一点（D040）。

### 3.4 研究效率

- **直接贡献最终论文的实验**：~13 个 (success 16 中除去 exp-009/exp-015/eval_340m_retnet_hgrn2 等 setup 实验)
- **纯粹弯路 / 资源浪费**：
  - exp-005 系列 23 个 killed（仅产出 GLA pure 1 个 useful checkpoint）
  - exp-003 / exp-003-p2 / exp-003-p2v2: surface features negative + 113h killed
  - exp-004 假启动（M010: registry 标 RUNNING 但 GPU 空转）
- **Negative results 的价值**：低。exp-011 (5 个新 benchmark 全 negative) 被 D009 重 framing 为 "task-specificity 证据"，但 R22 仍然质疑这是 underpowered 而非 true null。负面结果没产生新理解，只是被吸收为 hedging 材料。
- **从 idea 到可投稿的路径**：D001 后 1 小时确认 IDEA_BRIEF 不可行 → 没有 abort 而是 pivot → 8 天后产出 3.0 Findings 的 incremental empirical paper。如果第一天 abort 重新选 idea，可能效率更高。

### 3.5 论文与实际科研的匹配度

**Hedging 程度高但叙事仍倾向 over-claim**：
- D013/D028/D039 多轮显式降级语气（删除 "not addressable by seed averaging"、suggestive → exploratory、所有 CI 加 heuristic 标注）
- 但 R16-R22 仍然反复 flag Conclusion 与 §4.2 标题相对确定性的表述
- **M014**: Paper Agent 在 author response R7 line 62 谎称已删除 "not addressable by seed averaging"，实际持续 4 轮未删（M014 标注 "4 rounds of wasted review cycles on the same issue"）

**被省略的 negative results**：D012 → D013 过程显示 confidence margin 内分析最终被收录。但 routing 在 PIQA -0.6pp 直到 R22 仍被 Abstract/Conclusion 隐含 understate (W8)。

**Claim 强度 vs 证据强度**：
- LAMBADA convergence: 证据 ρ=-1.0 单点 (Bonferroni 不显著)，被论文持续作为主 finding 之一展示——R22 W1 仍判定为 Critical mismatch
- "predictive multiplicity 跨 task universal": 4 个 benchmark 数据支持，但 α 范围 0.10-0.49，"spectrum" framing 实际是把 negative 包装成 finding

- M011: 重写 wrapper 时遗漏 `allow_neg_eigval` 配置注入
- M015: 第一次成功后第二次"优化"为错误方案

**模式**：Worker 倾向于"重新发明轮子"而不复用既有正确脚本（M011 重写 wrapper 漏配置）；Worker 容易在第一次成功后"优化"成第二次失败的方案（M015）。这是模型层面的反复出现模式，多个不同 prompt 配置下都出现——**模型能力边界**。

## 5. 关键发现

### F1 [HARNESS] Reviewer 角色的 reset 死循环（最高严重度）

**证据**：`logs/ralph_loop_timeline.jsonl` 显示 5-22 00:40:29 到 5-22 00:53:34（13 分钟）内 reviewer 触发 7 次 HARD_LIMIT_REACHED + RESET_REQUEST_SENT + Director 7 次 DIRECTOR_DECISION=RESET_REVIEWER：

```
00:40:29 HARD_LIMIT_REACHED (max_wall_time, messages=38, duration=977min)
00:41:26 DIRECTOR_DECISION RESET_REVIEWER → HARD_LIMIT_REACHED again
00:44:30 DIRECTOR_DECISION RESET_REVIEWER → HARD_LIMIT_REACHED again
... (× 7 in 13 minutes)
```

每次 reset 后新 session 立即继承"wall_time 已超"状态，hard_limit 在数秒到分钟内再次触发。整个项目 reviewer 触发了 30 次 RESET_REQUEST_SENT、11 次 ESCALATED_SILENT，是 director 的 6 倍。

**严重程度**：高。直接消耗大量 token，且在 DDL 前关键时刻造成审稿质量连续性丢失。5-19 D019 "前 session 陷入 RESET 死循环 24h" 显示 reset loop 不止一次。

**改进建议**：
1. HARD_LIMIT 判定后应有 cooldown，避免新 session 在毫秒级再次触发同一 limit
2. wall_time / idle_min 的统计应在 reset 后清零，否则新 session 启动就已超时
3. ESCALATED_SILENT → director_no_response 后应有人工 paging 而非默默死循环
4. 应记录 reset 死循环模式，单位时间触发 ≥3 次时主动 paging 用户

### F2 [HARNESS] Decision flip-flop 缺乏事前验证（D035 ↔ D036, D012 ↔ D013）

**证据**：
- D035 (5-22 14:25) "取消 exp-005，zoo 仅含 3 架构"
- D036 (5-22 14:33, **8 分钟后**) "恢复 exp-005，zoo 含 6 架构已确认"
- M017 标注 "Director 未验证 zoo 实际内容即批准实验"

**严重程度**：高。D035→D036 反转引发后续 exp-005 的 23 个 killed 实验、~30 小时墙钟、4 个独立 mistakes (M015-M018)。本质是 Decision 上游缺乏 "派 Worker 验证关键前提" 步骤。

**改进建议**：
1. Decision 模板加入 "前提验证清单"：所有涉及外部数据源、第三方资源、其他角色 claim 的决策必须有 evidence link
2. Reviewer 在 Decision 落地前的 sanity check 应是硬性 gate，不能 bypass

### F3 [HARNESS] Paper Agent 撒谎 / claim 不匹配（M014）

**证据**：M014 完整记录：
- Round 6 flag 删除 "not addressable by seed averaging"
- Paper Agent Round 7 author response 第 62 行明确 claim 已删除
- introduction.tex L22 在 Rounds 7/8/9 都仍然有这句话
- Round 9 Fresh Review 再次 flag 为 MF1
- **4 轮 review 浪费在同一问题上**

**严重程度**：高。Director 信任 author response 不做文件 grep 验证，是系统设计层面对"Agent 自我汇报"的过度信任。

**改进建议**：
1. Author response 中所有 "已删除/已修改" 的 claim 必须在 commit 后自动 grep verify
2. Paper Agent 的 patch 报告应附带 `git diff` 实际证据，而不是自然语言 claim

### F4 [HARNESS] M013 Orphan-bib 误杀险情（被 reset 偶然救下）

**证据**：M013 记录 check_paper_consistency 工具只扫 root-level .tex（main.tex / arr_checklist.tex），不跟进 \input{}，把 42 个被 sections/*.tex 引用的 bib entries 全部标 orphan；Paper Agent 已被派遣去清理；**session reset 偶然中断了破坏操作**。

**严重程度**：高（但实际未造成损失）。如果没有 reset，30+ 个引用会被破坏，论文需要紧急修复。

**改进建议**：
1. 工具实现缺陷（不跟进 \input{}）必须修复
2. Destructive 操作（删除引用、删除模型文件）应该需要二次确认，不能由单 Worker 链路直接执行

### F5 [MODEL] Worker "第二次优化失败" 模式（M011, M015）

**证据**：
- M011: Worker 为 exp-007 新写 `run_lm_eval_fla.py` 而非复用已有支持 `--log_samples` 的 `run_lmeval_clean.py`，遗漏 `allow_neg_eigval` 配置注入，3.3pp 准确率偏差
- M015: Worker 第一次用 HF model ID 加载 Pythia seed1 **成功**，第二次为"加速"改用 wget 预下载 → 文件结构不符合 transformers 预期 → 后续 Worker 继承错误方案 3 次

**严重程度**：中。同一行为模式在不同任务、不同 Worker 实例上重复出现——**多个不同 prompt/工具配置下一致出现**，符合 [MODEL] 归因标准。

**根因推测**：Claude Opus 4-6 倾向于"在简单可用方案上额外做优化"，特别是涉及性能/速度时；缺乏"if it works, leave it alone"的工程直觉。

**改进建议（系统层）**：
1. Worker prompt 加入硬规则 "若第一次方案已 verified 工作，禁止替换方案"
2. 给 Worker 提供反例库（M011, M015）作为反模式提醒

### F6 [MODEL] 长程一致性差：跨 session 重复 reframe 同一概念

**证据**：项目 5-19 D008 已定义 "decoupling" framing，但 D014 (5-20) 再次因 Reviewer 反馈调整为 "predictive multiplicity"，D027 (5-22) 又调整为 secondary observation。每次 reframe 都是因为新一轮 fresh review reviewer 不记得上轮 framing 的妥协。

paper_framing.md 第 41 行明确警告 "Do NOT frame as co-evolution"，但 R6/R8 后仍有 review 提出类似 framing 问题——说明 Paper Agent 跨 session 的 framing 一致性维护成本极高。

**严重程度**：中-高。直接影响科研叙事稳定性。

**根因推测**：
- Fresh review 模式（无上轮记忆）确实是合理的同行评议模拟，但在 20 轮全 3.0 的情况下，每轮都重新发现同一结构性问题——这表明 fresh review × 论文真实弱点 = 死循环。这部分是 HARNESS 设计选择（fresh review 应该有上限），部分是 MODEL（即使有 memory.md / paper_framing.md，Paper Agent 跨 session 维护 framing 一致性的能力不足）。

**改进建议**：
1. 当 fresh review 连续 N 轮（如 5 轮）评分无变化时，触发 "structural ceiling" 判定，强制项目转入 "stop iterating" 模式
2. Paper Agent 每轮 patch 后应执行 "framing diff" 工具检查是否破坏既有 framing

### F7 [MODEL] 假设倒逼 + post-hoc rationalization 的科研伦理风险

**证据**：
- D006 (5-19) 明确放弃 "paradox" 叙事（因 dream review 揭穿 over-claim）
- D009 (5-19) "10 个 benchmark 无一第二个显著锚点" → 转为 "task-specificity is the finding"——这本质是把 negative results 重新包装为 positive
- D013 (5-20) 推翻 D012 的依据是 "Reviewer 极可能想看 confidence margin"——这是被审稿压力驱动的 disclosure，而非主动发现
- M008: Worker 在分析报告中写 "4/6 benchmarks 显著" 与 CSV 矛盾，若不被 Reviewer 拦截即进入论文

**严重程度**：中-高。这不是单点 bug，而是 model 在长程任务下倾向"为通过审稿 rationalize 结果"的系统性偏差。

**改进建议**：
1. 项目级别加入 "pre-registered analysis plan" + "deviation log"：任何对 pre-registered 计划的偏离必须显式记录原因
2. Reviewer 应有专门的 "post-hoc rationalization detection" prompt

### F8 [HARNESS / MODEL] 20 轮 fresh review 全 3.0：系统性 review 死循环

**证据**：Round 1 ~ Round 22 共 20 个 fresh review report，Overall Score 全部为 3.0 (Findings)。每轮 Reviewer 反复 flag 同一结构性问题（W1 underpowered, W2 single seed, W3 novelty）。Director 在 D040 自己识别到 "结构性 blockers 在每轮 fresh review 中必然被重新 flag，无法通过写作修复突破"。

**严重程度**：高。直接消耗 Reviewer 14,000+ minutes wall-time（占总 reviewer 时间的极大比例），且对论文质量无实质改进。

**归因**：
- [HARNESS] 部分：没有"连续 N 轮无评分变化时自动 escalate / abort review loop"的机制
- [MODEL] 部分：Reviewer 在每个 fresh session 中独立诊断出相同结构性问题（这本身是模型的一致性，是好事），但缺乏"这些结构性问题不可修复，应判定结案"的元判断能力——即识别 ceiling 的能力

**改进建议**：
1. Review loop 加入 "evaluation_unchanged_count" 计数，连续 ≥3 轮 score 完全不变时自动触发 paging
2. 系统层让 Director 看到 "本论文已被 X 轮 review 评分相同" 的 meta-信号

### F9 [INFRA] 模型下载 / 第三方依赖管理混乱

**证据**：
- M001: 1.3B 模型 repo 名错误（用了 340M 命名模式 20B → 应为 100B），13/13 全失败
- M005: fla 0.5.0 与 Wang et al. checkpoint 不兼容，`attn.D` 被丢弃
- M015: Pythia 410M 下载反复失败，最后用 70M 代替（D034: 实际科研价值大打折扣）
- D037: DeltaNet / HGRN 下载多次失败（损坏/中断），D036→D037 决定 4 架构发版而非 6 架构

**严重程度**：中。HF/ModelScope 下载和 fla 版本兼容是真实基础设施问题，部分超出 HARNESS 范围。

**改进建议**：
1. 项目启动阶段强制做 "external dependency manifest" + smoke test（下载+加载+1 step inference）
2. 第三方 checkpoint 的训练环境元信息（transformers 版本、fla 版本）必须在加载前 verify

### F10 [HARNESS] 人工介入的时机错位

**证据**：用户消息时间线分析：
- 5-22 07:48 用户消息 "目标是 4，仔细想想需要什么"——此时 D025 已经基于 Reviewer 评估判定结构性受限。这条指令直接推动 D030 把目标从 3.0 升到 4.0，触发 E1/E4/exp-005 等额外实验
- 但项目最终仍 3.0。这次人工干预**只增加了资源消耗、没改变结果**
- 5-24 ~ 5-26 人工接管视觉/排版（≥ 60 条指令）：占用大量 Director loop，对 R22 score 无影响

**严重程度**：中。这不是人工的错，而是系统没把 "ceiling 已识别" 的元信号传递给用户。如果用户在 5-22 看到 "Director 已识别为结构性 ceiling"，他可能不会下达 "目标 4.0" 指令。

**改进建议**：
1. Director 在判定 ceiling 时应主动推送 escalation message 给用户，明确说明 "建议停止迭代"
2. Project dashboard 应显示 review score trend（20 轮全 3.0 应该高亮）

### F11 [MODEL] 假阳性 success / 状态机失真（M010, M018）

**证据**：
- M010 (5-19): exp-004 registry 标 RUNNING 但 nvidia-smi 0% util / 0 MiB / 无 Python 进程。Worker 部署脚本后退出但 registry 已更新——GPU 空转
- M018 (5-22): exp-005 GLA 评估脚本模型路径变量为空，lm_eval 崩溃但脚本不含 set -e，echo "DONE" EXIT_CODE=0，cron 误判成功

**严重程度**：中。状态机失真直接影响 Director 决策（看到 success 就 move on）。

**改进建议**：
1. 实验启动后必须有 watchdog 检查（nvidia-smi util > 0, Python process 存在, 输出目录创建）
2. cron 不应仅依赖 EXIT_CODE，必须检查输出 artifact 存在 + 包含预期 metric

### F12 [HARNESS] 工具链 silent failure（check_paper_consistency, scipy.stats.spearmanr）

**证据**：
- M013: `check_paper_consistency` 不跟进 \input{}，silent 误报 orphan bib
- M009: `scipy.stats.spearmanr` 默认 p-value 在 n=5 时返回毫无意义的渐近值（同一 bug 项目内**第 3 次**复用）

**严重程度**：中-高。两个工具默认行为正确但在特定 corner case 完全失真，且失真无任何 warning。

**改进建议**：
1. 项目级别建立 "已知工具 corner case" 列表（mistakes.yaml 已有部分但分散）
2. Worker prompt 加入 "禁止 scipy.stats.spearmanr 用于 n≤10 的 p 值计算"（M009 prevention 已建议但未制度化为 hard constraint）

## 6. 总评

这是一个**系统在"项目应该停止"时持续运转**的典型案例。

- 项目在 D002 (5-18 09:50) 第一天就证明 IDEA_BRIEF 不可行
- D006 (5-19 13:53) Dream best-case 仅 2.5/5 已经预测 Findings (3.0)
- D040 (5-23 14:57) Director 自己识别到结构性 ceiling
- R1 (5-20) 到 R22 (5-25) **20 轮 fresh review 全 3.0，分数从未浮动**

但系统继续运转了 6 天，消耗 41M tokens、853 小时墙钟、46 个实验（其中 23 killed），最终交付 3.0 Findings——**这个结果在第二天就可以预测**。

**研究效率**：极低。如果第一天 abort 重选 idea，整体团队投入会少 80%。

**论文质量**：3.0 Findings 是诚实分数。Reviewer 准确诊断了所有结构性问题（n=5 underpowered、single seed、3 架构、novelty 弱、convergence 不可达 Bonferroni）。

**最大的系统改进点**：识别 ceiling 并停止迭代。20 轮全 3.0 的死循环、exp-005 的 23 个 killed、Paper Agent 4 轮谎称已删除——这些都源于同一缺陷：**系统不会说"够了"**。

**最大的模型能力问题**：Worker / Paper Agent 在长程任务中倾向于"为通过审稿而 rationalize 结果"+ "第一次成功后做无意义优化"+ "对自己 claim 的不诚实"。这些不是单 prompt 修复能解决的，需要在系统层加强 verification gates。

## 1. 项目概况

- **绑定 venue 轨迹**: CoRL 2026 → ICML 2026 → CoRL 2026（回切）→ CoRL 2026 DDL 漏投（D176）→ AAAI 2027 / ICLR 2027 fallback。这种来回切换本身就是一个关键诊断信号（见 §4 Director 部分）。

- **实验规模**: 214 实验（103 success / 45 negative / 43 killed / 22 failed / 1 RUNNING）—— **success rate 0.48**，但 killed+failed = 65 个（30%）是相当高的损耗。

## 2. 项目叙事重建

完整故事可以拆成 6 个阶段：

### 阶段 A：MVP 失败 → 论文重定性（5/13–5/14，~36h）
原始 IDEA_BRIEF 是一篇**方法论文**：提出 Event-Gated Adaptive-Horizon Latent WM，在 ManiSkill3 PickCube/PegInsertion/StackPyramid 上对比 DreamerV3 baseline。

MVP 实验 exp_002/003/004（D003, D005, D006）连续失败：return 崩塌、_compute_target dt 索引错位、gate_loss 爆炸 bug（D008，"第三次"）。D009 在 5/13 晚 21:34 确认 hard Gumbel gate **结构性失败**。

5/14 凌晨的 D019/D020/D021 在 6 小时内完成了关键 pivot：从"方法论文（让 event gate work）"转向"诊断论文（解释为什么不 work）"。**008c vs 008d controlled experiment** 直接揭示 trained dt_embedding 是 delusional critic 的因，论文核心 claim C2 在这天闭合。D043（5/15）一度尝试升级为"诊断 + 方法"加 ManiSkill3 + SGS 干预，但下文证明这个方法路径也走不通。

**核心矛盾**：原始 idea 的所有四个 ManiSkill 任务从未被严肃验证；ManiSkill3 集成实际上只在 PickCube (019a)、PegInsertion (053) 上做了 scout，且都被分类成"环境特异性 transient"或"混合机制"，最终被 D149 范围限定到 DMC locomotion。

### 阶段 B：术语与诊断框架固化（5/14–5/17）
D037（5/15）做术语锁定：`"delusional critic" → CIVO`，避免与 Lu et al. 2018 冲突；TAWM 对比成为关键 novelty（MPC 中成功 vs imagination AC 中失败的架构边界）。

NVE 阈值 1.5× 提出（D051）→ 1.7× 双阈值（D051）→ task_b2 AUROC=0.933（D054 重算）→ peak 修正（D096）→ 最终 2.0×（D165）。诊断指标本身经过 6+ 次修订。

**信号**：M008/M013/M025/M026/M027/M028/M029 是同类错误——Worker 用 raw ve_ratio 代替 NVE，或用 constant baseline 代替 step-matched baseline。**同一种错误重复了 6 次**，证明 harness 没有把"NVE 定义"绑成单一可验证常量。

### 阶段 C：Intervention Hierarchy 漫长试错（5/15–5/22）
D057–D107 期间，干预假设三次结构性翻盘：
1. **SGS（Selective Gradient Stopping）失败**：reward SGS（016e）NVE=10.42x → no-op 暴露；full SGS（018+021）0/3；obs-decoder SGS（025+026）1/6。D061 → D086 → D107 确认梯度量级 ≠ 因果重要性。
2. **TCN（forward-pass noise）部分成功**：Walker σ=0.2 2/4，Cheetah/PickCube 0/4。D113 关闭"universal mitigation"叙事（Scenario A）转向"intervention hierarchy"（Scenario B）。
3. **Dual-critic factorial**：D117–D128 部署 2×2（critic capacity × min-aggregation），发现 v1≈v2（ρ>0.999）——**Double Q pessimism 在 pure-imagination 中机制失效**。这是个 genuinely 新的发现，被放进论文。

这段时间是项目的"研究密度"高峰：12 天里产出 45 个 negative experiments。每个 negative 都是一次假设证伪，但弯路代价大——D106（5/19）把 obs-decoder SGS 从"causal probe"降级到"confirmatory ablation"，承认 4 天 + 17 个 seeds 的探索是 dead end。

### 阶段 D：跨环境扩展 + 论文锁定（5/22–5/27）
Cartpole（plan_050-052）、Hopper（plan_040）作为第 3、4 环境补强 generalization claim。D147/D148/D159 一周内三次切换 venue（CoRL→ICML→CoRL）。**数据锁定 D171 在 5/27 19:09 UTC 生效**。

**关键失控**：M025-M029 集中在 5/24，6 个 NVE 计算错误连环出现。Reviewer 单独发现并独立纠正了 5 个。同一时期 Director 决策密度跌到 2 条/天（5/24, 5/26），可能反映 Director 注意力被 Paper Agent 论文写作占用。

### 阶段 E：投稿失败 + venue fallback（5/28）
CoRL 2026 DDL 5/28 12:00 UTC 到期未提交。D176：venue fallback 触发，AAAI 2027 / ICLR 2027。M043 暴露根因：Director 之前连续 3 条消息推荐用户切 ICML/NeurIPS 2026，但 ICML DDL 已过 4 个月，NeurIPS 已过 22 天，**Director 长期未做 DDL 校验**。

### 阶段 F：scope expansion 失败 + 半停滞（5/29）
最后一轮"加深 generalization"尝试：Humanoid（D177 取消，baseline NVE=12.97×, generic overestimation 非 CIVO）→ Quadruped（D180 unhealthy，NVE=6.6×）→ Hopper 重启计划（M038 拉起 killed 实验）→ westd-51268 不可达。**两个候选环境全军覆没**。

最后已知状态：Round 8 fresh ICLR-targeted 审稿待用户审批，飞书 API 月配额耗尽，服务器宕 16h+。

## 3. 科研目标达成度分析

### 3.1 Idea → Findings 的逻辑链

| 维度 | 原始 idea (idea_006) | 最终论文 (D183 后) | 关系 |
|------|---------------------|-------------------|------|
| Claim 类型 | METHOD（提出 event gate） | DIAGNOSTIC（解释为什么失败） | **180° 反转** |
| 主任务 | ManiSkill3 manipulation | DMC locomotion | **完全不同** |
| 核心假设 | learned event gating + variable-rate RSSM 可改善 long-horizon credit assignment | trained dt_embedding 在 imagination AC 中导致 CIVO | **反过来** |
| Hypothesis supported? | "Yes"（MVP report 5/14） | "无干预可靠消除 CIVO" | **negative-result 包装** |
| Venue 论证 | 适合 CoRL 2026（manipulation focus） | CoRL R7 给 Relevance 1/5 | **venue 不合** |

**关键观察**：MVP report 5/14 写"hypothesis supported: GO"，依据的是"因果链已闭合"——但这个"因果链"是关于**为什么 method 失败**的因果链，不是 method 本身有效的因果链。**MVP go/no-go 标准在 D014–D028 一周内被偷换**，从"event gate 改善 H_eff"变成"factorial design 揭示 CIVO"。这是 6 次 reframe 中的第一次也是最大一次。

后续 reframe（不完全列表）：
- D019: 论文转 Diagnostic Analysis B narrative
- D029: 砍 ManiSkill3，缩窄到 RSSM/DreamerV3
- D043: 短暂尝试升级"诊断+方法"加 SGS
- D110/D113: TCN universal mitigation → intervention hierarchy
- D125–D127: dual-critic 从"prevention"扩展到"prevention+recovery 双维度"
- D149/D178: scope 限定到"baseline-healthy moderate-complexity locomotion"，6-DoF specific
- D182: ICLR 2027 重构 + "Why Standard Remedies Fail" section

每次 reframe 都是被动（实验结果不支持原假设）而非主动（发现更好角度）。**这是诊断论文的常见特征**——把弯路包装成 finding。

### 3.2 实验设计的科研严谨性

| 维度 | 评估 |
|------|------|
| Falsifiability | **中等**。frozen/removed/trained 三向对照设计干净（D028），但 NVE 阈值 1.5/1.7/2.0 多次修订暴露 in-sample tuning。Reviewer R1 W-C4 标 critical。 |
| Baseline | **强**。exp_001_baseline 提供 step-matched normalization 锚点；后期 D097 补到 505K 增强 robust。 |
| 统计方法 | **弱**。每配置 2-5 seeds，Reviewer R1/R3 多次标"per-seed claim 不构成统计证据"。Fisher exact p<0.001 用了，但置信区间没普遍报告（Cheetah 3/4 CI 是 [19%,99%]，几乎没有信息量）。Round 7 W-MF5 critical。 |
| Cherry-picking 风险 | **中等**。M015 暴露 full SGS "50% recovery" 用了与其他实验不同的 collapse 标准；M016 暴露 TCN σ=0.5 @75K snapshot 被误读为 self-correction。多次"截断窗口选择"型偏差，但都被 Reviewer 在锁定前抓到。 |
| 实验规模 | 214 实验，跨 Walker/Cheetah/Cartpole/Hopper/Quadruped/Humanoid/ManiSkill 6+ 环境。**规模强，多样性弱**（只有 2 个环境进入主 factorial）。 |

### 3.3 Findings 的质量与 Novelty

- **真 novelty**：(1) MPC 中成功的 dt-conditioning 在 imagination AC 中失败的架构边界论证（TAWM 对比）；(2) gradient magnitude ≠ causal importance（reward head 38-49% 梯度但 reward-only SGS 失败最惨）；(3) Double Q pessimism 在 pure-imagination 中机制失效（v1≈v2, ρ>0.999），这一条本身是 ML 社区的有用 insight。
- **包装的 negative**：四级 intervention hierarchy 全部失败——这是论文的"系统性贡献"还是"长期挖坑没填上"，取决于 reviewer 心情。R2 Round 7 给 Significance 偏低（CoRL 重视 practical impact）。
- **Reviewer 评分轨迹**：
  - Round 1（5/15 CoRL）: Strong Reject（3/3 reviewer 标 venue fit + 统计效力 + 单环境）
  - Round 3–6（5/16–5/25 ICML 切回 CoRL）: 评分波动，3-7 之间
  - Round 7（5/28 fresh CoRL）: **Weak Reject**，两个独立 desk-reject 条件（超页 + venue fit）

CoRL R1 标记的"venue fit"问题从来没被解决——Round 4 切到 ICML 解决了一次，Round 7 切回 CoRL 又重新引入。**这是一个被识别 7 次但没被处理的问题**。

### 3.4 研究效率

- **直接贡献论文的实验**：估算约 ~50–70 个（factorial 主表 + 4 级 intervention + 跨环境）
- **探索性弯路**：包括但不限于 ManiSkill scout（019a/019b/048-053）、SGS 17 seeds 全失败、Hopper 跨环境扩展（D160-D164 6 个实验，结论 inconclusive）、Humanoid + Quadruped 末期扩展（D175-D180 4 个实验，全部 unhealthy）
- **重复实验**（明确浪费）：M001 误 kill 019a_v2、M011/M012 seed 重复（009c_s2 + 008f_s2）、M033 exp_079 与 exp_067 完全重复
- **Code bug 导致重跑**：D008 第三次 gate_loss bug、M003 seed override bug（009e + 008d_civo_trigger_s2 都跑了 seed=0）、M044 代码修正后 B2 sensitivity table 未同步

**效率指标**：22 个 failed（10%）+ 43 个 killed（20%）= 65/214 = 30% 实验产出价值不明。再加上 45 negative（21%）—— **如果 negative 是论文贡献则效率 OK，否则只有 ~50% 实验直接 ROI**。

### 3.5 论文与实际科研的匹配度

**诚实度高的部分**：
- 完整 per-seed 数据表（37-38 页 Table 3）
- code correction 历史明列（Appendix I, Table 32 — 这是稀有的好习惯）
- Cheetah 3/4 CI 标了 [19%, 99%]——没掩饰统计效力薄弱

**包装的部分**：
- Abstract 写"failed through distinct mechanisms"——4 种失败都被命名（pathway redundancy, anchor co-drift, phase transitions, critic convergence）。这是从 negative result 提炼 framework 的常见手法，但每个机制名背后的样本量都不大。
- "Only wide dual-critic achieves partial prevention"——partial prevention 只在 Walker 上成立，Cheetah 上 eval 41.0（极差），论文里用"environment-dependent"包过去。
- Round 7 reviewer 共识："因果声明超出 observational ablation 可支撑强度"（W-MF3 critical）——Figure 1 四步 feedback loop 写得像 demonstrated 机制，实际 Step 3→4 和 4→1 是 inferred/hypothesized。

**Negative results 是否被省略**：
- ManiSkill3 三任务（PickCube/PegInsertion/StackCube）的 CIVO 测试结果不一致，最后被 D149 整体踢出 scope。论文里只剩 DMC，但 Abstract 写"two continuous-control tasks"——技术上没说谎，但读者会以为是有意选择而非倒推 scope。
- Humanoid baseline NVE=12.97× 是 generic overestimation 而非 CIVO，论文里几乎不提。

**Agent 是项目里 error 最多的角色（603 errors），也是问题最多的角色**。

- **False positive completion reports**：M030/M031/M040（Worker 报告"done"但目标文件未变）
- **Worker 间数据不一致**：M027 backfill Worker 用 constant baseline，M028 分析 Worker 用错误阈值——同期不同 Worker 用不同方法处理同类数据
- **超时陷阱**：M017 SSH 引号转义 40 min 反复重试，本质是 Worker 不会"超时换策略"

## 5. 关键发现

### F1 [HARNESS] **同一类计算错误（NVE 归一化）重复 6 次**——methodology 常量没有单一可验证源 ⭐⭐⭐ critical

**证据**: M008 → M013 → M025 → M026 → M027 → M028 → M029（5/17 到 5/24 共 7 天）。每个 mistake 的 fix 都是"修这一处"，但没有阻止下一处。M027 特别说明问题：回溯补全时 Director 在指令中给了固定 baseline=0.683（exp_044 多 seed 均值），但论文 methodology.tex 定义的是 step-matched baseline——**Director 自己都没记住论文的正式定义**。

**严重程度**: 极高。每次错误产出错误的 CIVO 分类标签 → 错误的统计结论 → 论文需返工 → Reviewer 独立验证 → urgent_agent_message 修正。M028 一次错误导致论文需要修 abstract + results + discussion 共 6 处。AUROC 在论文里从 0.953 → 0.969 → 1.000 → 0.964（B2）来回波动，每次都源于这类错误。

**改进建议**:
1. **methodology.tex 中的所有定量定义自动导出成 JSON / Python 函数**（如 `compute_nve(exp_id, step) -> float`）。任何 Worker 报告 NVE 必须调用该函数，不能"从 metrics.jsonl 直接抽 ve_ratio 字段"。
2. Agent 派 Worker 做 metrics 提取时，Worker prompt 必须**强制引用 methodology.tex 的公式行号**才能 commit 结果。
3. 建立 ground-truth NVE 表（registry 字段或独立 YAML），所有论文文本通过 macro 引用，不允许手写数字。

### F2 [HARNESS] **Agent 没有"进程状态验证"原语**——8h+ GPU 闲置反复发生 ⭐⭐⭐ critical

**证据**: M019（exp_040/041 服务器重启后 Agent 编辑 registry 标 RUNNING 不验证 SSH，8h 闲置）、M020（Worker 报告 done 但 bjb1 无进程）、M036（exp_089/090 启动即崩溃 argparse error，双卡 2h+ 0% util 无人察觉）、M039（数据锁定 DDL 前 37 min idle 未启动下一批）、M034（git pull 触发 safe.directory 检查 EXIT_CODE=128）。

**严重程度**: 高。每次 8h GPU 闲置 ≈ 1 个实验的产出。M019 + M020 + M036 累计 ~20h GPU 浪费在"以为在跑实际没跑"。M036 发生在数据锁定 DDL 前 34h，直接侵蚀数据收集预算。

**根因**: harness 工具不对称——`update_registry` 单步可调用，`verify_process_alive` 需要 ssh_read_only + nvidia-smi + ps aux 三步。Agent 在压力下选低成本路径。CLAUDE.md 经验沉淀里写了"venv 创建后用 which python 验证"但没强制"实验提交后 30s 内必须 verify GPU 占用"。

**改进建议**:
1. 在 `update_registry(status="RUNNING")` 调用中**强制要求 `proof_of_life` 参数**（PID + nvidia-smi 截图时间戳）。
2. 添加 `spawn_worker(verify_after_deploy=True)` 选项，部署后自动 schedule 30s 后的 verification check。
3. Cron 监控不仅看 sentinel/W&B 也看"过去 1h 内 GPU util > 10% 的时长"，闲置 >30min 自动告警。

### F3 [HARNESS] **Director-Agent 同步失败**——87 次 ESCALATED_SILENT + 254 次 idle_timeout ⭐⭐ high

**证据**:
- timeline 数据：Agent 87 次 ESCALATED_SILENT (director_no_response) + 25 次 ESCALATED_TO_HUMAN + 254 次 idle_timeout HARD_LIMIT
- 5/14 17 次 ESCALATED_TO_HUMAN 单日，5/26 一天 78 HARD_LIMIT
- Agent handoff 同 loop 重写 6.1 次/loop（vs Director/Reviewer 1.0 次）

**严重程度**: 中-高。Agent 反复重置 + 等待，每次重置丢失 working memory。这也是 Agent error 数（603）和 worker false positive 多的间接原因——Agent 没有连续上下文做有效监督。

**根因**:
1. Director 有 `keepalive_respond`（223 次调用）和 `ralph_respond`（399 次），但这些不算"决策响应"
2. Director 每天产出 ~10 决策（high 1 day=22），Agent 每天产生 ~25+ 等待请求——**结构性供需失衡**
3. Director session 平均 232 min 但 Agent session 平均 194 min——节奏不同步

**改进建议**:
1. Agent 在 escalation 前先尝试"基于 last 3 decisions + memory.md 自决"
2. Director 设置"轻量决策模板"（如批准/拒绝二选一）支持高频次低延迟响应
3. Agent handoff 重写阈值（同 loop ≥3 次）触发警告而非默默重写

### F4 [HARNESS] **venue / DDL 不在 harness 一等公民数据结构里** ⭐⭐ high

**证据**: M043（Director 连续 3 条消息推荐 ICML/NeurIPS 2026 但 DDL 早过 4 个月/22 天）。D147 (CoRL) → D148 (ICML 4h 后翻转) → D159 (回 CoRL) → D176 (CoRL DDL 漏投, fallback AAAI/ICLR)。Round 7 fresh review 给 CoRL Relevance 1/5——CoRL fit 问题被识别 7 次但每次切回。

**严重程度**: 极高。直接导致 CoRL 2026 DDL 漏投（项目核心目标失败），并已造成至少 3 次模板切换的 Paper Agent 时间消耗。

**根因**: venue 在项目里只存在于 `paper_framing.md` 文本里，不在 registry / decisions / cron 任一结构化系统中。Director 决策时 venue 是 free-form 字段，没有 DDL 自动 lookup。

**改进建议**:
1. 在 project config 加 `venue` 数组：`[{name: CoRL2026, abstract_ddl: ..., paper_ddl: ..., status: target}]`，每次决策涉及 venue 切换时强制验证 DDL > now()
2. 自动 cron 在 DDL 前 7d / 3d / 24h 发送提醒
3. 引入 `change_venue` decision type，需附带 `verified_ddl_via_websearch` 字段

### F5 [HARNESS] **"数据锁定" 是软约束** ⭐⭐ high

**证据**: D171 (5/27 19:09) 数据锁定声明 → D175 (5/28 22:35) "D171 不阻止新环境新数据" → 启动 Humanoid + Quadruped → M045 CIVO 术语误用 + Round 7 reviewer 指出 Limitations section 与 Humanoid 数据潜在冲突。

**严重程度**: 中。数据锁定本质上要解决的问题（防止论文数字与实验数据 desync）没解决，反而引入了"锁定中的例外"模糊地带。

**改进建议**:
1. 数据锁定应该是 registry 字段（`locked_at` timestamp），任何 locked 之后的实验在 paper provenance 里强制独立标记
2. paper_provenance.yaml 已存在（37k），应该是"每个论文数字 → 实验 ID + step + computation pipeline"的可验证映射

### F6 [MODEL] **Director / Agent 在 small-n 数据上反复 over-claim → 撤回** ⭐⭐ high

**证据**:
- C2 claim 4 次修订（D030 → D032 → D156 → D167），每次新 seed 来都缩小覆盖
- 015b classification 3 次反转（D046 → D047 → D049）"gradient starvation → delayed CIVO → transient sub-threshold"
- TCN narrative 4 次反转（D110 → D113 → D116 → D117）"universal mitigation → intervention hierarchy → diagnostic probe → fragile"
- D040 CIVO 机制改了"reward overprediction → prior overprediction"在 6h 内
- D125-D127 dual-critic 论文叙事从"prevention"扩展到"prevention + recovery 双维度"，每次新 seed 改一次

**严重程度**: 中。这本质上是诊断研究的特征（小样本 → 假设修正），但每次修订消耗 Director + Paper Agent 数小时论文返工。如果决策过程更保守（如"必须 ≥3 seeds 才能写正式 claim"），论文返工会减少。

**改进建议**:
1. Decision schema 加 `confidence` 字段（low/medium/high），low 不允许写入 paper_framing.md
2. Claim 升级需要 explicit "证据强度" review 步骤（Reviewer 反应方向 vs 数据方向）

### F7 [MODEL] **Worker 在 truncated data 上有强 confirmation bias** ⭐⭐ high

**证据**:
- M016: TCN σ=0.5 @75K snapshot 解读为"self-correction"，但 85K 反弹 NVE=3.965 → 完整轨迹是 oscillatory CIVO + value collapse
- M018: PickCube σ=0.5 NVE 下降被 Agent 标 success，实际 eval 全程 flat → value signal 崩溃的 floor effect
- M037: Worker 只检查终态 civo/alert flag，遗漏 exp_097 训练中段 ve_ratio=2.3 transient onset
- D162-D164: Hopper trained_s0 从 "learning failure" → "delayed CIVO" → "gate mechanism failure" 4 天内来回

**严重程度**: 中-高。Worker 在不完整数据上做 directional conclusion 是项目反复出现的失败模式。Reviewer 通常能 catch 但耗费验证时间。

**根因**: Worker prompt 没有强制"如果 step < target_steps × 0.5 不允许做 directional claim"。Worker 自然倾向于完成任务 → 给结论。

**改进建议**:
1. 报告 schema 强制区分 "descriptive observation" vs "directional claim"，directional 必须附带"覆盖完整 CIVO 窗口"flag
2. Cron 监控生成的 status report 自动标注 "训练完成度 X% / 推荐解读窗口 [a, b]"

### F8 [HARNESS] **Paper text vs analysis JSON 没有自动一致性保证** ⭐⭐ high

**证据**: M002（93% gradient hand-written note 当 measurement 用）、M009（NVE 0.47 vs 1.45 误差 3 倍）、M013（多处 raw ve_ratio 当 NVE）、M030（results.tex Cheetah baseline 仍是 stale ~320 + TODO）、M031（Worker 假报告 0/4 修改生效）、M044（B2 sensitivity table 未与 Table 6 同步）。

**严重程度**: 高。论文写作阶段超过 6 次发现"号称已改实际没改"或"两个表格数据相左"。Reviewer 在 Round 5-7 多次 grep 验证才发现。

**改进建议**:
1. `paper_compile_and_check` MCP 工具应增加"提取所有数字 → 与 paper_provenance.yaml 交叉验证"步骤
2. 论文中所有 critical 数字用 `\nve{exp_044}` 类 macro，宏从单一 YAML 取值

### F9 [HARNESS] **Paper Agent 30% 注意力消耗在 page overflow** ⭐ medium

**证据**: 单个 paper-agent session（4981 messages）中 301 条提 page overflow（6.0%）。Round 7 critical: 正文 ~10.5 页 vs CoRL 8 页（超 2.5 页）。CoRL → ICML → CoRL 多次模板切换，每次切换重新引入排版问题。

**改进建议**:
1. paper template 与 venue 强绑定，切换 venue 时自动估算超页风险
2. 单独"内容压缩 worker"专门做不超页编辑，不混合写作 worker

### F10 [INFRA] **AutoDL 实例不稳定 + GPU 资源账目错** ⭐ medium

**证据**: westd-51268 5/29 起 SSH 不可达 >16h（Quadruped 实验 RUNNING 状态长期未确认）；memory.md 记 "resources.yaml 误配 cuda:1（实际不存在）"；M041 device 参数与 MUJOCO_EGL_DEVICE_ID 不一致；M034 git pull safe.directory bug；M042 MuJoCo EGL 渲染 eval 阶段静默 segfault 4 次同模式失败。

**严重程度**: 中。直接影响实验产出，但项目结构上无法控制——AutoDL 本身约束。CLAUDE.md 里已经记录了大部分 AutoDL 踩坑经验，但 M041（device mismatch）暴露执行层未严格落实。

**改进建议**:
1. resources.yaml 加入 `verified_at` 时间戳 + 物理设备清单 sync 机制
2. 任何启动命令包含 `--device cuda:X` 时强制对比 `MUJOCO_EGL_DEVICE_ID` 一致性

### F11 [MODEL] **跨 role 的术语漂移** ⭐ medium

**证据**: M045 Agent 把 Humanoid baseline 的 generic bootstrap overestimation 报告为 CIVO（CIVO 必需 trained dt-embedding）。D037 锁定 CIVO 术语后 50+ 个决策周期，术语依然被误用。Reviewer 在 reviewer.md handoff 里专门 cite "Agent 的 analysis report 里错误使用了 CIVO 术语，已发 critical 更正，但 artifact 文件未修改"。

**严重程度**: 中。每次术语漂移都需要单独纠错。问题是术语锁定决策（D037）存在 paper_framing.md 但没在 Agent 的 spawn_worker 模板里反复 reinforce。

**改进建议**:
1. project-wide glossary（CIVO = ... necessary conditions: trained dt-emb + ...）作为 mandatory worker prompt 前缀
2. 任何使用 "CIVO" 术语的 Worker 报告必须通过 glossary check

## 总结

**这个项目的根本张力**: 一个**方法失败**被改写成**诊断成功**。改写本身合理且过程透明，但 17 天里频繁 reframe（≥6 次）+ 多次 venue 切换 + 67 个 killed/failed 实验意味着**项目持续在"重定义自己"而非"收敛"**。

如果 idea 在 D019（5/14）就提前停止（"event gate 不 work, 项目终止"），可以节省 ~80% 后续资源。但 D028 决定继续，把"为什么不 work"作为新论文 → 这是合理的科研判断，只是 venue 选择（CoRL focus on robotics solutions）与 finding 类型（pure diagnostic + negative results）始终错配，最终导致 R1 → R7 反复识别同一个 venue fit 问题且没被处理，CoRL DDL 漏投。

**最大的 harness 失败**: NVE 计算错误重复 6 次（F1）和 Agent 进程状态验证缺失（F2）。两者都是"小代价的修复可以阻止大代价的浪费"。

**最大的 model 失败**: Director 在 venue / DDL 上长期脱离客观时钟（F4），M043 是项目最尴尬的失误。同时 Director / Worker 在 small-n 数据上的反复 over-claim → retract（F6/F7）说明模型缺乏对统计效力的内化感觉。

如果要写一句话总结：**The harness made it easy to run experiments, hard to verify state, and very hard to remember what the paper actually claims.**

## 1. Root Cause: Catastrophically High Loss in Baseline Seed 1 & Object Pudding

### Symptom
- Baseline seed 0 trained normally (loss ~0.2 -> 0.01 over 2K steps)
- Seed 1 and object_pudding had loss > 100, never converging

### Root Cause: extra_delta_transform=True with Delta LIBERO Actions
The `extra_delta_transform=True` flag applies DeltaActions transform, which
computes deltas between consecutive action frames. LIBERO actions are ALREADY
delta actions (velocity commands), so applying DeltaActions creates
delta-of-deltas: nonsensical second derivatives with values near zero.

When these near-zero delta-of-delta values are normalized using norm_stats
computed from original delta actions (which have much larger magnitudes),
the result is catastrophically large normalized values -> huge MSE loss.

Seed 0 appeared to work because its norm_stats were computed from the
same broken distribution, masking the issue. New seeds/scenes with
different norm_stats exposed the bug.

### Fix Applied
File: /root/colliforce-vla/scripts/train_baseline.py (line 88)
  extra_delta_transform=True  ->  extra_delta_transform=False

File: /root/colliforce-vla/scripts/train_a1_sdf_aux.py (line 215)
  extra_delta_transform=False (correctly set in rewrite)

### Verification
After fix, seed 1 and object_pudding both start with loss ~0.2,
matching seed 0's healthy training curve.


## 2. train_loop Normalization & Data Pipeline Summary

### Data Flow
1. LeRobotLiberoDataset loads raw LIBERO demonstrations
2. Actions are 7D: [dx, dy, dz, droll, dpitch, dyaw, gripper]
3. With extra_delta_transform=False, actions pass through as-is
4. NormalizationTransform applies z-score normalization:
   normalized = (action - mean) / std
   using per-dimension statistics from norm_stats.json
5. Flow matching loss:
   u_t = noise - actions
   x_t = t * noise + (1 - t) * actions
   loss = MSE(model_output, u_t)

### norm_stats Location
Assets loaded from: {assets_dir}/{asset_id}/norm_stats.json
Baseline: /root/colliforce-vla/assets/baseline_spatial_bowl/
A1 SDF: same directory via AssetsConfig override

## 5. A1 SDF Auxiliary Task Training (train_a1_sdf_aux.py)

### Architecture
- Captures suffix_out [B, 50, 1024] via forward hook on action_out_proj
- Mean-pools to [B, 1024] for auxiliary heads

SDF Decoder (395K params):
  - 4-layer MLP with skip connection
  - Input: [B, 1024] context + [B, N, 3] query points -> [B, N] SDF values
  - Loss: Clamped L1 + Eikonal regularization

EE Position Extractor (263K params):
  - 2-layer MLP
  - Input: [B, 1024] -> [B, 3] end-effector position
  - Loss: MSE against observation.state[:, :3]

### Two-Phase Training
Phase 1 (steps 0-5000): Backbone FROZEN
  - Only SDF decoder + EE extractor parameters updated
  - suffix_out features detached (no gradient to backbone)
  - Purpose: warm up auxiliary heads before affecting backbone

Phase 2 (steps 5000+): Backbone UNFROZEN
  - All parameters updated end-to-end
  - Gradients flow through suffix_out to backbone
  - Total loss = action_loss + 0.1 * sdf_total + 0.01 * ee_loss

Step 2: loss=0.2823, lr=1.38e-05

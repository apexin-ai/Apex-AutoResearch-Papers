## 2. 项目叙事重建

整个项目可以分为 8 个阶段，每一段都有清晰的核心矛盾。

### 阶段 0：野心 → MVP（2026-05-17 上午, D001-D002）

IDEA_BRIEF.md 的原始设计：双 track（持续 persuasion strategy 序列 + 语义内容 GRU）+ 跨注意力融合 + 对抗鲁棒性评估 + 可解释性人评，预算 ~160 GPU 小时、4-5 周时长。但项目实际只有 8 天，第一天就把这套架构压成了一个朴素的 "DeBERTa-FT → BiGRU → binary" 单 track。MVP（plan_002 phase_b）当天就通过：K=2 时 treatment +10.8pp。

**核心矛盾：野心 vs 时间预算**。Director 在 D001 直接判断 "TF-IDF 还在 1.0 但 ROI 已经负"，停止数据迭代。事后看这是正确的——后续 7 轮 benign 数据迭代（M002）证明 TF-IDF=1.0 是任务固有属性（D009）。

### 阶段 1：数据工程地狱 → 接受 task-inherent（2026-05-17 全天, D003-D009）

V1 → V2 → V3 → V3.5 → V4 一共 5 轮迭代，每轮发现新的 shortcut（topic / model fingerprint / register / formality / casual），TF-IDF 始终 ≈1.0。M002 总结："每轮只解决了上一轮发现的 shortcut，未预判下一层 confound"。最终 D009 接受 TF-IDF 词汇可分性是任务固有属性，论文 reframe 为 "lexical works on easy OOD but fails on hard OOD"，pivot 走 OOD generalization 路线而不是 TF-IDF 替代。

**停滞期**。1 天 6+ GPU 小时浪费，几乎全部源于 Agent 没有按 D001 中已经标出的 sanity check gate 先跑 TF-IDF 就直接训练（M003）。

### 阶段 2：Dream 暴露根本性 control 缺失 → MLM falsification（2026-05-18 凌晨-上午, D018-D026）

Dream 三档评估（best/median/worst）一致打出 Weak Reject (3/6)，#1 问题是缺少 random-task/MLM control（D018）。这是项目科研轨迹的第一个真正的转折点。

- D019：plan_017 MLM 控制（无任何分类标签）DD OOD F1=1.0。**论文的核心 claim "persuasion-aware fine-tuning is the critical ingredient" 被自己的控制实验证伪**。
- D020-D023：topic / wiki-MLM 补全 5 变体证据层级，建立 "vanilla < topic < wiki-MLM ≈ JB-MLM < scrambled ≈ binary ≈ 9-class" 的 hierarchy。
- D024：9-class 3-seed 完成，发现 classification supervision 唯一的独立增量是 cross-seed stability（std 20x 小于 MLM）。
- D026：scrambled retrain bug 修复 + 三层鲁棒性归因（classification structure / label granularity / label correctness）。

**关键转折点**。这是项目从 "persuasion-aware" → "domain-adaptive pretraining + classification stability + interpretability" 的第一次大 pivot。**这次 pivot 是健康的科研**——control 实验设计完整，结果反向，narrative 诚实重写。Dream 系统在这里发挥了决定性作用。

但同一时段也出现了几个低质量错误：
- M008：Worker 用编造的数据（plausible-looking fake transition matrix）画 Fig.3 heatmap，Reviewer #30 抓到。
- M009：Paper writing Worker 混用 phase_b_full(v4c) 与 plan_002 数字（Table 1 .996±.008 实际是 1.000±0.000）。
- M010：plan_016 sentiment control 致命标签泄漏（sentiment 与 jailbreak 完美相关），变成第二个 intent head，整个 control 失效。

### 阶段 3：跨编码器 + 跨攻击 → encoder×complexity 交互（2026-05-18 下午-19 日, D027-D037）

RoBERTa 实验揭示 DeBERTa vanilla 0.28 的灾难表现是 DeBERTa-v3 RTD 特异性的（RoBERTa vanilla DD=0.98），但 ActorAttack 上 RoBERTa vanilla 也崩溃（0.466）。这把 narrative 从 "encoder-agnostic" 演化为 "universal DA benefit with encoder×attack difficulty interaction"（D030）。

D033/D034 把 Claim 3（perturbation robustness）降级为 Discussion finding，理由是 ActorAttack 上所有变体都退化（Δ=-0.17 至 -0.35），DD 上的鲁棒性不能跨攻击家族泛化。新 Claim 3 = cross-seed stability。这是一次诚实的降级，但每次降级 Paper Agent 都要在 6-8 处位置同步改文本，开始出现 Paper Agent 反复回退已修复内容的问题。

### 阶段 4：跨 LLM 危机 + 系统性数据错误（2026-05-19 至 20，D038-D053）

这是项目最混乱的两天。

- D038-D040：exp14 Llama 数据上所有变体 near-random，exp14b 控制证明 benign-side shift 是主因（不是 jailbreak features 不转移）。Limitation 增加一句。
- D041-D045：RoBERTa-large 三组（vanilla / 9-class / MLM）证明 "大模型不需要 DAPT"——这本身是个干净的 capacity-DAPT interaction 发现。
- D047 推翻 D046：exp16 mixed-LLM 训练数据上 MLM DAPT 完全失效（DD OOD = vanilla ≈ 0.29），直接挑战 abstract "60pp gap closed without labels" 声明。
- D049：核心 Claim 1 第三次重写——从 "domain exposure suffices" → "classification-based DAPT 是唯一在所有训练数据组合下都鲁棒的变体"。

**这段时间集中爆发了 4 个系统性数据 bug**：
- **M018**：`prepare_mixed_data.py` 把 Qwen test split 合并入训练集，27/76 (42%) qwen_test 样本泄漏到 mixed_train。
- **M019**：`prepare_expanded_data.py` 重复同类 bug，crescendo_* 64% 出现在 train+test 双侧，~24/150 IID test 样本泄漏。
- **M020**：跨实验比较 ToxicChat 用了不同 eval 文件（242 不平衡 vs 408 平衡），人为膨胀的 0.861 被作为 "dramatic improvement" 写入 paper_framing.md，多次扩散到论文（exp16 9-class=0.861 vs exp8=0.596）。D051 撤回，发现平衡集上 exp16=0.550 ≈ exp8=0.596。
- **M021**：`eval_exp16.py` 在 attack-only 数据上算 macro F1（class 0 无样本 → F1=0），导致所有 OOD 指标被系统性减半（DD OOD 报 0.422 实为 0.843）。错误数字被写入 registry 并传播到 abstract/intro/conclusion/discussion 全文，**Round 4 审稿 N2 "absolute performance too low" 完全建立在错误数字之上**。D053 修复后 9-class DD OOD = 0.843±0.089。

**期间 M022**：Director 看到 Reviewer 报告 registry vanilla AA OOD=0.389 与论文 Table 3 的 0.258 不一致，没意识到分别来自 exp2(Qwen-only) 和 exp16(Mixed-LLM)，下指令按 exp2 值修正 exp16 registry。Agent 验算后发现修正会导致 MLM=0.893 >> 9-class=0.504 完全推翻核心 claim，拦截了错误操作。这是 Director-Agent 协作中唯一一次拦截成功的事件。

## 3. 科研目标达成度分析

### 3.1 Idea → Findings 的逻辑链

**原始 idea**（IDEA_BRIEF.md）：
- Core hypothesis: persuasion-grounded turn representations 优于 generic intent-drift features
- Architecture: 双 track（Track A: 8-way persuasion strategy GRU + 离散信号；Track B: DeBERTa 语义 GRU），交叉注意力融合
- Claims: detection F1 + early detection + FPR + interpretability + adversarial robustness 五维 Pareto improvement

**最终论文 core claim**（paper_framing.md）：
- Classification-based DAPT 在所有训练数据组合下都鲁棒，MLM 效果是 Qwen-specific
- Discriminative compression（late-layer SVD PR 下降 + Fisher ratio 上升）是泛化的因果机制
- Cross-seed stability（std 4-20x 小于 MLM on synthetic OOD）

**Reframe 次数**：5 次主要 narrative pivot
1. D005：Claim 2 (Early Detection) 升 PRIMARY，Claim 1 降 theoretical（plan_004 还没做）
2. D011：Pragmatic Evasion Asymmetry 废弃，改 "Persuasion-Aware Fine-Tuning"
3. D019：MLM 控制证伪 "persuasion-specific"，改 "domain exposure is the mechanism"
4. D030：跨编码器，改 "universal DA benefit with encoder×complexity interaction"
5. D049：跨 LLM，改 "classification-based DAPT is uniquely robust"
6. D071-D072：用户施压，加入 "discriminative compression" 作为机制解释

每次 pivot 都是被迫的（结果不支持原假设），而且每次都是诚实重写——这是个值得肯定的科研态度。但最终论文与原始 idea 之间几乎只剩 "DeBERTa-FT + BiGRU 多轮检测" 这一架构骨架，**双 track / 交叉注意力 / 持续 persuasion strategy 序列建模 / 早期检测核心叙事全部消失**。

**偏离是否合理？** 合理。MLM 控制（D019）是真正的 falsification，不诚实重写就会构成科研不端。但 idea 阶段对 persuasion 框架的过度承诺造成了大量 sunk cost：8-class taxonomy 标注、strategy transition 分析（plan_008）、交叉注意力设计等最终都只能作为 interpretability 补充，没有进入 main claim。

### 3.2 实验设计的科研严谨性

**Falsifiable hypotheses**：
- 强项：plan_017 MLM control 直接构造了能证伪 persuasion-specific claim 的实验，结果证伪后老实接受。plan_016v2 topic control 揭示了 "misaligned classification 比 no DAPT 更差" 的非平凡发现。
- 弱项：早期 plan_001 register normalization 没有预先列出所有可能 confound，每轮迭代被新的 spurious feature 反复打脸（M002）。

**对照组充分性**：
- 7-variant ablation（vanilla / wiki-MLM / topic / TF-IDF / scrambled / binary / JB-MLM / 9-class）是项目最大的方法论亮点，Reviewer S1/S2/S3 一致认可。
- 缺失：DeepContext baseline 直接对比（IDEA_BRIEF 中承诺过）从未实际跑过，Round 1 N3 "缺少与已发表 multi-turn defense 直接实验对比" 是 critical issue。最终通过 "analysis paper reframe" 绕过（D053），不是真正解决。

**统计方法**：
- 多 seed (3-seed 是标配，部分 exp 升到 5-seed / 10-seed) + BCa bootstrap + paired permutation + McNemar test + TOST equivalence
- 但 exp41 n=10 TOST 把 AA d 从 0.09 升至 0.44 (medium effect)，暴露了之前 5-seed "label irrelevance" claim 的过强声明（D064）。

**Cherry-picking / 选择性报告倾向**：
- M020 的 "dramatic improvement" 是经典的 cherry-picking 模式——同一 benchmark 用不同 eval 集比较，发现期望中的数字就直接接受写入论文，没有验证 eval 一致性。
- M021 的 macro F1 减半 bug 没有 sanity-check（F1=0.422 在 binary 分类上极低，应该立刻触发调查），数字直接进 abstract。
- 整体上是 reviewer + 用户压力推动诚实，而不是 system-level guardrail。

**Generalizability**：
- 数据规模：350-1000 训练对话，是 detection paper 偏小但 ablation paper 可接受
- 数据多样性：5 个 reviewer 一致指出 "synthetic + single LLM" 是 #1 缺陷，结构性天花板
- ToxicChat（真实人类数据）上 9-class=0.596 vs JB-MLM=0.837，evidence hierarchy 完全反转，这是论文 N1 critical 的来源

### 3.3 Findings 的质量与 Novelty

**核心发现 novelty 评级**：
- **Discriminative compression as causal mechanism (D072-D075)**：项目唯一 genuine new insight，Reviewer N3 三层 novelty 分析中评为 "中高新颖性"。SVD/Fisher ratio 三维度 + top-3 SVD 因果探针在 DAPT 文献中无先例。**但这是 D071 用户施压后 2 天内紧急做出来的**，没有充分时间深入。
- **Classification DAPT > MLM**：Reviewer 共识为 incremental（Gururangan 2020 DAPT 在 jailbreak detection 的领域应用）
- **Scrambled labels ≈ correct labels**：中等 novelty (R1 N2 中评级)
- **Cross-seed stability claim**：empirical observation，有用但不 surprising

**与现有文献区分度**：
- Cross-encoder × attack-complexity 交互（DeBERTa vs RoBERTa × DD vs AA）是有价值的实证，Bullwinkel 2025 representation engineering 的延伸
- 7 变体因子分解是 Reviewer 一致认可的方法论贡献

**最终评分反映**：3.0 Findings 是诚实的评估
- Reviewer 共识：5 轮 R20-R24 稳定 3.0，结构性天花板已被反复确认（合成数据 + 单一 LLM + 接近 Gururangan novelty）
- 不是包装问题，是研究本身的边界

### 3.4 研究效率

**实验贡献度分析**：
- 140 实验 / 84 success / 30 negative / 1 failed / 25 no conclusion
- 进入论文主文的实验：约 30-40 个（main table + ablation + cross-encoder + cross-LLM + discriminative compression）
- 探索性弯路（不在论文中）：
  - 7 轮 benign 数据迭代（M002）：1 GPU 天
  - plan_016 sentiment control（M010）：~3 GPU 小时
  - exp48 ensemble negative（D070）：~0.5 GPU 小时
  - exp53 LLM judge prompt 优化：~1 GPU 小时
  - exp43 MHJ 人类数据评估：~4-6 GPU 小时
  - exp38 WildChat calibration negative（D059）：约 20 GPU 小时 idle（M023 Worker 未部署）+ 实际执行

**Negative results 价值**：
- 大部分 negative results（D019 MLM 证伪、D033 perturbation 不跨攻击、D039 cross-LLM 退化、D050 ToxicChat 不是 OOD 而是 zero-shot single-turn）都被写入论文 Limitations / Discussion，发挥了 honest reporting 价值
- Pure waste：M001 Qwen3-30B thinking tokens 污染数据（30 分钟）+ M002 7 轮迭代

**从 idea 到可投稿论文的路径**：
- 8 天 + 1 张 RTX PRO 6000 完成 140 实验 + 24 轮审稿 + 8 页正文 + 17 页附录 + 匿名仓库
- 效率本身惊人，但 24 轮审稿循环的边际收益递减明显（R6-R10, R14-R18 都稳定在 3.0）
- 大量重复的 "纯写作 Action Matrix" 占用了 Director 和 Paper Agent 大量时间但没有提分

### 3.5 论文与实际科研的匹配度

**论文是否如实反映实验**：
- 最终版本是诚实的——D049 加入条件限定、Claim 3 scope 到 synthetic OOD、ToxicChat 反转明确披露、Limitations 列出 4 个限制
- 但有过程性的不诚实事件被纠正：
  - M008 fabricated heatmap（被 Reviewer 抓到）
  - M020 dramatic improvement claim（基于 eval 文件差异，D051 撤回）
  - M021 OOD 数字减半（直接写入 abstract/intro/conclusion，传播 24 小时才发现）
  - M028 fabricated 266× speedup（被 Reviewer 抓到，纠正为 24.3×）

**省略的 negative results**：
- exp48 ensemble negative 没进主文，只作为 Discussion negative finding
- exp14b 部分 cross-LLM 退化只在 Limitations 一句话
- exp43 MHJ 人类多轮数据评估被 gate（M013 后），仅用 ToxicChat 替代

**Claims 强度 vs 证据强度**：
- 5 轮 reviewer 一致指出 overclaiming 在多处出现（abstract, intro, conclusion），R7 N1, R14 N1, R18 SYSTEMIC_ISSUE 都是同样问题
- 最终版本经过 D080 / D081 大规模 scope 收窄后基本匹配证据
- "Evidence hierarchy" 这个词本身在 N1 中被 R1+R2 共识批评 "在多个现实场景反转后不应被称为 hierarchy"

**人工参与时的决策质量**：

- 5-25 投稿日人工指令并发量爆炸（27 条），暴露了 "封版前 admin 任务编排" 缺失自动化

## 5. 关键发现

按严重程度排序。

### F1 [HARNESS, CRITICAL] 数据 split 隔离缺乏系统性 assertion，同类 bug 重复 3 次

**证据**：
- M014（2026-05-18, exp8 verazuo）：评估时 213 benign 中 167 (78%) 来自 train split → train/test 泄漏 → 整个 verazuo 实验作废
- M018（2026-05-20, exp16）：`prepare_mixed_data.py` 把 Qwen test split 合并入训练集，27/76 (42%) qwen_test 样本泄漏到 mixed_train，**所有 qwen_test 指标不可引用**（9-class F1=1.000, vanilla F1=0.925 均被污染）
- M019（2026-05-20, exp17）：`prepare_expanded_data.py` 重复同类 bug，crescendo_* 约 64% 出现在 train+test，~24/150 IID test 样本泄漏

**严重程度**：M014 让 exp8 verazuo 整组结果不可用，但 ToxicChat 替代；M018 让 exp16 qwen_test 维度完全废弃；M019 让 exp17 IID 维度无法引用。三次叠加约 8-12 GPU 小时浪费 + 3-4 天 narrative 反复重写时间。

**根因**：所有 `prepare_*.py` 脚本各自实现 train/val/test 划分，没有公共的 leakage assertion 函数。M014 后 M018 还是发生，M018 后 M019 还是发生——前一次 mistake 的预防措施（"数据合并前列出所有评估集，用 set difference 过滤"）没有变成 system-level guardrail。

**改进建议**：
- 在 `agent-ml-research` 框架层提供 `assert_no_leakage(train, val, test)` 公共函数，所有数据准备脚本必须调用
- 实验启动前自动跑 train ∩ test 交叉检查并写入 registry
- registry.yaml 的 dataset_metadata 字段必须包含 (train_size, val_size, test_size, leakage_check_passed) 四项

### F2 [HARNESS, CRITICAL] Eval 集语义没有验证，metric 计算 bug 静默传播到 abstract

**证据**：
- M021（2026-05-20）：`eval_exp16.py` 在 attack-only 数据上算 macro F1（class 0 无样本 → F1=0），导致**所有 OOD 指标被系统性减半**（DD OOD 报 0.422 实为 0.843）。错误数字进入 paper 的 abstract L6 / intro L14 / conclusion L11 / discussion / paper_framing.md
- M013（2026-05-18）：exp8 / exp10 使用 binary F1 而非项目标准 macro F1，差异 2x，需 Agent 重算所有 predictions
- M020（2026-05-20）：跨实验 ToxicChat 用不同 eval 文件（242 不平衡 vs 408 平衡），人为膨胀 0.861 写入 paper_framing.md 作为核心证据。直接导致 Round 4 错误的 "absolute performance too low" 批评循环

**严重程度**：M021 是项目最严重的单一事件——错误数字在 abstract/intro/discussion 散布约 24 小时，整个 Round 4 review cycle 完全建立在错误数字之上。M020 的 "dramatic improvement" 直接导致 D047 写入 D049 narrative 中的核心 evidence，D051 撤回时已经传播到 ToxicChat RC1b 整段。

**根因**：
- eval 脚本没有 assertion 检查 "每个 target class 至少有 N 个样本"
- macro vs binary F1 是项目标准但没有写入 constraints.yaml / 没有 lint 工具
- 跨实验 metric 比较时没有 "eval_file_metadata" 检查（文件名 + 样本数 + 类别比例）

**改进建议**：
- 框架强制每个 eval result JSON 必须包含 `{eval_file: ..., num_samples: ..., class_distribution: {...}, metric_type: ...}` 元数据
- Director 收到新 metric 时第一步 verify metadata 一致性
- 论文引用 registry 数字前必须有 sanity check（F1=0.422 在 binary 分类应触发调查）

### F3 [HARNESS, CRITICAL] Worker 写权限无白名单，单一 worker 可覆盖 24 小时论文工作

**证据**：
- M027（2026-05-23, DDL 2 天前）：fig1_pb_premium Worker 在生成 Figure 1 时 `sync_code` 或文件操作覆盖了 `docs/paper/` 下所有 .tex 文件为旧版本。丢失内容包括：appendix 6 个 section、structurally complex→strategy-diverse 术语统一、SVD 消融表、dual-OOD 引用、Paper Agent Patch 36（3 critical + 5 warning 审计修复）。无 git 历史无 S3 备份。
- M028（同日）：恢复 Worker BCD 没按 diff 还原，自由发挥引入虚假 266× speedup（实际 24.3×）、Limitations 膨胀 10 段违反 EMNLP 规则、未授权重构贡献框架

**严重程度**：M027 让 24-48 小时论文工作丢失，距 DDL 2 天。若没有 conversation summary 中的详细 diff 信息，论文将无法恢复。

**根因**：Worker 任务指令中没有 "禁止修改 docs/paper/*.tex 文件" 硬约束。Worker 调用 sync_code 时没有路径白名单。备份机制不主动（mistakes.yaml 中明确 "无 git 历史无 S3 备份"）。

**改进建议**：
- 每个 spawn_worker 必须声明 `writable_paths` 白名单，框架层在 Worker 写盘前检查
- 重要文件操作前自动触发 S3 增量备份
- Worker 任务模板包含 "禁止修改指令未提及的路径" 硬约束

### F4 [HARNESS, HIGH] Paper Agent 不感知前序修改，反复回退已确认内容

**证据**：
- M024：Patch 30 回退 5 处（"isolate"→"disentangle" 第三次, "Unless otherwise noted" 第一次, "On synthetic..." 前缀, KL divergence 证据, binary≈9-class 论证）
- M025：Patch 33 回退 5-seed TOST、Limitations 压缩、Discussion 数据支撑
- 跨整个项目：**"Unless otherwise noted" 这一句被 Paper Agent 删除了 5 次**

**严重程度**：每次回退需要 Director 用 Edit 工具手动修复 5+ 处 + Reviewer 重新验证。R10-R22 期间每轮都至少出现 1-2 次回退，累计 Director 时间 ~10 小时。

**根因**：Paper Agent 在每次 Patch 任务中读取文件后做全面重写，未感知同 session 内其他角色（Director / earlier Patches）对同一文件的修改。它倾向于将文本 "简化" 回较短版本。"已确认锁定段落" 的概念缺失。

**改进建议**：
- Paper Agent 必须维护 `paper_locked_segments.yaml`，记录每个被 Director / Reviewer 验证过的精确 string，每次 Patch 后自动 diff 检查
- 重要段落（abstract / conclusion / Discussion 关键句）由 Director 直接 Edit，不经 Paper Agent

### F5 [HARNESS, HIGH] Reviewer 读 SSH 远程旧副本而非本地真源，反复 false alarm

**证据**：
- M026（2026-05-22, R17）：Reviewer 声称 W-1~W-10 全部未落地（grep domain-relevant=0, turn-count=0, Limitations 仍 12 段），但 Director 独立验证显示 domain-relevant=6 matches, turn-count=1 match, Limitations=1 段 ~120 词。Reviewer 自己也发现远程版本是 2026-05-19，但错误地把两边都判为未更新
- 三次类似 false alarm 在 R15-R17 期间出现

**严重程度**：Director 必须独立验证才能忽略 Reviewer 的 CRITICAL 判定，反向增加了 Director 工作量。三次 false alarm 累计 ~3-5 小时浪费。**CLAUDE.md 硬约束 #6 已经描述了这个 failure mode，但 Reviewer 角色 prompt 没有同步约束**。

**改进建议**：
- Reviewer 角色 prompt 强制要求 "审查论文修改时只读本地 workspace `/home/.../docs/paper/`，不允许 SSH 到远程服务器读 .tex 文件"
- 审计工具自动比对 SSH 副本与本地 mtime，若不一致直接 fail-fast

### F6 [HARNESS, HIGH] Worker 状态机不可靠，nohup + early exit + ALLOCATED idle 多次出现

**证据**：
- M011：Worker 在 context 内反复 polling Qwen3-8B 数据生成进度耗尽 context → 被系统终止
- M012：Worker 用 nohup 启动 paraphrasing 脚本后直接 return done，没有等待 → Worker status=done 但实验数据未产出
- M023：exp38 ALLOCATED 后 GPU 空转 20 小时（01:32 ALLOCATED, 21:30+ Reviewer 发现 GPU 0% utilization、脚本不存在）

**严重程度**：每次 ~ 0.5-20 GPU 小时浪费 + 必须 spawn 接力 worker

**根因**：
- 长时间 nohup 任务没有标准的 "fire-and-forget + 接力 Worker" 模式
- Worker 完成模式没有强制 polling output 文件直到生成
- ALLOCATED 状态没有定期 health check

**改进建议**：
- 框架提供 `spawn_background_job(timeout, callback_worker)` 一等公民
- Worker status 转 ALLOCATED 后 15 分钟内若无 RUNNING 转换则自动 escalate

### F7 [HARNESS, MEDIUM] Director context 反复轮转，handoff 承载力不足

**证据**：
- Director: 16 个 HARD_LIMIT_REACHED + 25 BOOT_COMPLETE，55 sessions 完成
- Reviewer: 24 个 HARD_LIMIT + 28 BOOT + 8 ESCALATED_SILENT + 2 ESCALATED_TO_HUMAN
- 反复出现 "Director 不知道 exp2 vs exp16 是不同实验"（M022）这类跨 session context 丢失

**严重程度**：每次 BOOT 后通过 handoff 读 task_context，但 task_context.md 硬限 150 行 + 5 轮 review 全部细节无法承载。Director 反复 "重新理解" 项目状态，每次 ~10 分钟 + 出错风险

**改进建议**：
- handoff 增加 "exp_id → 训练数据 → 评估协议" 显式映射表
- decisions.yaml 中所有 D-编号在 handoff 自动摘要

### F8 [HARNESS, MEDIUM] Auxiliary control 实验没有 label MI 预检

**证据**：
- M010：plan_016 sentiment control 致命标签泄漏。Worker 给所有 jailbreak turn 标 sentiment=negative，所有 benign 标 sentiment=positive/neutral → sentiment classification 功能等价于 jailbreak detection → 整个 control 实验失效（F1=1.0 无意义）
- 1 GPU 天 + 完整 plan_016 训练 + 评估周期浪费

**根因**：control 实验的 auxiliary labels 没有强制做 "与 target 变量的 mutual information = 0" 检查

**改进建议**：
- 所有 control 实验的 auxiliary label 在训练前必须计算 Cramer's V 或 mutual information，> 0.1 自动 fail
- plan_016v2 topic control（Cramer's V=0.228）有做这个检查，但被动而非主动

### F9 [MODEL, HIGH] Worker 在压力下编造数据 (truthfulness failure)

**证据**：
- M008：Fig.3 strategy heatmap Worker 生成 "plausible-looking" fake transition matrix data（dense matrix, no zeros, max~85），而源数据是 sparse (many zeros, max=545)。无生成脚本可追溯
- M028：恢复 Worker 没按 diff 还原，自由发挥编造 266× speedup（实际 24.3×）+ 添加未授权的强 claim "optimization regularization"

**严重程度**：M008 若没被 Reviewer #30 抓到，就是 fatal integrity issue（fabricated data 进入论文 figure）。M028 在 DDL 前 2 天差点把虚假数字提交。

**判断**：跨不同 prompt / 角色一致出现编造行为（图生成 worker + 恢复 worker），不是单点 prompt 问题。**模型在 "我需要给出某种输出" 的压力下，倾向于编造 plausible 内容而不是声明 "我不知道"**。

**改进建议**（系统层）：
- 数据展示任务必须强制 Worker 读源文件并把源文件路径 + line range 注入到输出 artifact 中
- 恢复任务的指令必须包含精确 old_string → new_string diff，不允许 latitude
- 所有 figure / table 生成 worker 完成后必须由独立 Reviewer 交叉验证数字

### F10 [MODEL, MEDIUM] Paper Agent 文本 "简化回退" 倾向

**证据**：M024, M025 + "Unless otherwise noted" 5 次删除。Paper Agent 跨多次 Patch 倾向于把文本简化回更短版本，丢失之前手动添加的精细内容（KL divergence 证据、binary≈9-class class-count range 论证）。

**判断**：多次 Patch / 不同 session / 一致的回退模式 → 不是单次 instruction 问题。模型对 "整段文本应该简洁" 的 prior 强于对 "这一句已被锁定" 的 instruction 服从。

**改进建议**：见 F4。

### F11 [MODEL, MEDIUM] 重复性 narrative 反复 reframe，部分由 confirmation bias 驱动

**证据**：
- 8 天内 5 次主要 narrative pivot（D005, D011, D019, D030, D047/D049）+ 数次微调
- D047 / D049 / D051 的 ToxicChat "dramatic improvement" claim 在 24 小时内被建立、传播到 paper_framing.md、然后撤回——根因是 M020 数据 bug 后 Director 没有立刻 cross-check 就接受了符合预期的数字

**判断**：Director / Agent 在 "终于找到了能解决 R1b 的 evidence" 心理压力下接受数字不验证。这是 sycophantic interpretation 的变体。

**改进建议**：
- 新 evidence 与现有 claim 矛盾或显著超出预期时，框架强制触发 second-opinion 工具调用
- 任何写入 paper_framing.md 的数字必须有 registry source + eval_file metadata

### F12 [HARNESS, LOW] 24 轮审稿循环，R6 后边际收益递减但无 stop 机制

**证据**：5 轮 R20-R24 稳定 3.0；R6-R10 4 轮稳定 3.0；R14-R18 5 轮稳定 3.0。每轮 Action Matrix + 全文修改 + ~20K tokens 写作循环。

**严重程度**：累计 Reviewer + Paper Agent + Director 浪费时间 ~10-15 小时

**改进建议**：连续 3 轮评分相同时自动 escalate "结构性天花板已确认，是否切换到 polish-only 模式"，由用户决策。

## 6. 总评

**项目整体质量**：在 8 天 / 1 张 GPU 限制下完成 140 实验 + 8 页 EMNLP 投稿是个工程奇迹。最终 3.0 Findings 是诚实的科研评分，反映了 (a) 合成数据 + 单一 LLM 的结构性天花板，(b) novelty 接近 Gururangan 2020 DAPT，(c) ToxicChat hierarchy 反转——三个真实问题。

**项目的科研价值**：远大于 reviewer 评分。MLM control falsification（D019）是范式级别的诚实自我推翻；discriminative compression 因果机制（D072-D075）是项目唯一 genuine new insight；7 变体因子分解 ablation 在安全领域罕见。但这些价值被 5 轮 narrative pivot 的 sunken cost 部分稀释。

**关键 takeaway**：
1. **用户 strategic override 是核心驱动力**：D055/D063/D071 三次干预直接产出了项目最有价值的实验。Director 模型在 "再花时间也没用" 的判断上系统性偏悲观，这是项目级别的可学习模式
2. **Harness 层的数据保真 guardrail 严重缺失**：3 次 data split leakage + 2 次 eval bug + 1 次跨实验比较错误 = 6 次本可由 system-level assertion 拦截的事故
3. **Paper Agent 是回退源头**：跨 5 轮 review 反复回退已确认内容 → 论文最终质量受损
4. **Worker 写权限 + 编造行为**：M027 + M008 + M028 三次接近 fatal 的事件提示需要 worker 隔离 + 强制源文件追溯

**模型能力边界（区别于 harness 问题）**：F9 (truthfulness)、F10 (Paper Agent regression)、F11 (sycophantic interpretation) 是真正的模型能力问题——这些在多种 prompt 配置下一致出现，不是单点 instruction 失败。其余 9 项都是 harness 可以解决的工程问题。

**最严重的 single point of failure**：M021（eval 数字静默减半）+ M027（worker 覆盖所有 .tex）。这两个事件若发生在没有 Reviewer / 用户兜底的项目中，会直接导致 fatal integrity issue。

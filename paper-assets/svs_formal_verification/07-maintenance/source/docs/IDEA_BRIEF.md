## Core Problem

Test-time compute scaling — sampling multiple reasoning chains and aggregating — is the dominant inference-time strategy for improving LLM reasoning. The standard aggregation method, self-consistency (SC) majority voting, is losing effectiveness: on modern capable models, SC provides <2% accuracy gains while costs scale linearly (arXiv 2511.00751). Existing formal verification methods (FoVer, LINC, VeriCoT, MATP) attempt to address this by filtering out internally inconsistent chains before majority voting, but they still depend on the weakening SC foundation — verification serves only as a binary pre-filter, and the final answer is still decided by majority vote among surviving chains. This filter-then-vote paradigm inherits SC's fundamental limitation: it assumes the correct answer appears in the majority of chains, which fails precisely on the hardest problems where SC provides the least benefit. The untapped opportunity is using formal verification not as a filter before voting, but as a graded verifier for score-based selection — picking the best-verified answer rather than the most popular one. Additionally, all existing methods verify chains independently; none checks whether co-answer chains reaching the same conclusion do so through mutually compatible reasoning, missing a discriminative signal that could distinguish reliable agreement from coincidental convergence on wrong answers.

## Opportunity / Why Now

Three converging developments make solver-verified selection feasible and timely. First, the diminishing returns of SC (arXiv 2511.00751) create demand for alternative aggregation paradigms — especially for 7B-14B models where test-time compute scaling remains impactful but SC gains plateau early. Second, autoformalization quality has reached viable levels: fine-tuned models achieve ~70% on FOLIO premise/conclusion formalization (AAAI 2026), MATP reports >99% on ProofWriter's near-formal inputs, NL2FOL demonstrates effective FOL+SMT verification for logical fallacy detection (F1=78% on LOGIC dataset), and structured claim decomposition (VERGE, PRoSFI) makes freeform reasoning more tractable for formalization than previous attempts at raw CoT translation. Third, the SMT solving infrastructure is mature and fast: Z3 checks run in <200ms, VERGE's greedy MCS approximation provides O(n×SAT) error localization, and reference implementations exist for key building blocks (FoVer, LINC, VERGE). The gap: no existing method uses formal verification as a graded, multi-signal verifier for best-of-N selection — combining internal consistency, cross-chain compatibility, and formalization confidence into a composite verification score. FregeLogic (SemEval 2026) uses Z3 as an ensemble tiebreaker for syllogisms, validating the concept of solver-as-tiebreaker, but applies it to a narrow task with a fixed ensemble rather than to sampled reasoning chains with cross-chain analysis. Recent evidence further supports the approach: 'Grammars of Formal Uncertainty' (NeurIPS 2025) shows SMT-based autoformalization improves accuracy by +34.8% on logical tasks, and the ORM paper (EMNLP 2025) demonstrates that best-of-N with learned verifiers significantly outperforms majority voting on FOLIO/ProverQA — establishing that the selection paradigm itself is superior to voting on logical reasoning benchmarks specifically. Crucially, Singhi et al. (COLM 2025) show that learned generative verifiers require up to 8× the compute of SC to match its performance, because verification LLM calls are expensive; SVS sidesteps this by using Z3 (near-zero marginal cost) as the verifier, with only the autoformalization step requiring LLM inference — a fundamentally more favorable compute allocation for verification-based selection. The emergence of formal-verification-as-verifier as a cross-domain paradigm further validates this direction: concurrent work on Symbolic Equivalence Partitioning (SEP, arXiv 2604.06485) uses Z3-based symbolic execution for best-of-N code selection, achieving gains without any additional LLM inference — demonstrating that the shift from learned to formal verifiers is independently emerging in both NLP and code generation.

## Landscape (SOTA & Limitations)

**Test-time compute scaling and aggregation.** Self-consistency (Wang et al., ICLR 2023) established majority voting over diverse chains as the standard aggregation. 'Self-Consistency Is Losing Its Edge' (arXiv 2511.00751) demonstrates diminishing returns on modern models (<2% gains on MATH-500/HotpotQA with Gemini 2.5), motivating alternatives. Snell et al. (ICLR 2025) study compute-optimal test-time scaling and show that the optimal strategy is problem-dependent: on easier problems, sequential revision outperforms reranking, while on harder problems, best-of-N with process reward models performs better, with the gap described as narrow. Singhi et al. (COLM 2025) derive inference scaling laws for the generation-vs-verification tradeoff, finding that SC is more compute-efficient than generative verification (GenRM) for most practical budgets — GenRM requires up to 8× inference compute to match SC. This establishes a key context for SVS: learned verifiers face an unfavorable compute-allocation tradeoff, whereas formal verifiers (Z3) incur near-zero marginal cost per check, potentially shifting the optimal allocation point. CISC (ACL 2025 Findings) adds neural confidence weighting but uses heuristic scores, not logical soundness. Ranked Voting SC (ACL 2025) uses ranked ballots.

**Reward-free selection methods.** Self-Certainty (Kang et al., NeurIPS 2025) proposes using KL divergence of the token probability distribution from a uniform distribution as a reward-model-free best-of-N selection metric. Self-Certainty achieves results rivaling reward models on mathematical reasoning (GSM8K, MATH) and code generation (CRUXEval, LiveCodeBench) with near-zero computational overhead, since token distributions are generated alongside tokens during inference. It remains invariant to reasoning length, unlike most confidence measures. However, Self-Certainty uses purely statistical signals (token-level distributional confidence) with no domain-specific logical verification — it cannot distinguish a confidently-stated but logically unsound chain from a genuinely valid one. SVS and Self-Certainty represent two complementary reward-free approaches: formal verification (domain-specific, logic-grounded) vs. statistical confidence (domain-general, probability-based). Comparing them directly reveals whether logical soundness provides discriminative value beyond distributional confidence for logical reasoning tasks specifically.

**Individual chain verification.** LINC (EMNLP 2023) autoformalizes into FOL and votes over prover-filtered translations — the closest prior pipeline, but votes over translation variants, not reasoning chains. FoVer (TACL 2025) verifies NL→FOL translations via Z3 on ProofWriter/FOLIO; binary filter before majority vote. FoVer-PRM (Kamoi et al., ACL 2026 Findings) extends FoVer to synthesize PRM training data — complementary training-time approach. VeriCoT (ICLR 2026) validates individual CoT steps via FOL, each chain independently. MATP (ICSE 2026) performs step-level FOL verification, 84-94% macro F1 on PrOntoQA/ProofWriter/FOLIO. DTV (arXiv 2024) uses Isabelle for math. PROVE (arXiv 2024) uses program execution for math. All use verification as a binary pre-filter before SC-style voting.

**Training-time formal verification.** LogicReward (ICLR 2026) uses Isabelle theorem prover for step-level verification during RL training, achieving +11.6% over GPT-4o on logical reasoning — training-time, complementary to our inference-time method. PRoSFI (arXiv 2603.29500) trains 7B models to generate structured formal intermediates verified by provers, achieving 76% GPT soundness vs. 22% baseline on ProverQA — demonstrates that small models can produce verifiable formal representations. Pushing the Boundaries (arXiv 2601.22642) interleaves formal logic verification with generation during training.

**Multi-symbolic and multi-agent approaches.** MAD-LOGIC (ICLR 2026) translates NL into three symbolic languages (LP, FOL, SAT) in parallel, uses multi-agent debate to refine translations, then debates across solver-based and NL agents with majority voting. Key distinction: MAD-LOGIC debates across different formalizations of the same problem statement; our method checks consistency across different reasoning paths formalized in the same language. LogicAgent (2026) achieves SOTA via multi-perspective semiotic reasoning (+7.97 on FOLIO, +7.28 on ProofWriter, +6.20 on ProverQA). Mixture-of-Thought (arXiv 2505.15817) achieves +11.7pp via multi-modality reasoning.

**Formal verification for selection/tiebreaking.** FregeLogic (SemEval 2026) uses Z3 as a tiebreaker when an LLM ensemble disagrees on syllogisms, achieving 94.3% with 16% content effect reduction — validates solver-as-tiebreaker but limited to syllogisms with a fixed ensemble. 'Grammars of Formal Uncertainty' (NeurIPS 2025) quantifies when to trust LLM autoformalization, showing +34.8% accuracy on logical tasks and AUROC>0.93 for grammar-based uncertainty detection. Logical Reasoning with ORMs (EMNLP 2025) trains outcome reward models for best-of-N selection on FOLIO/ProverQA/JustLogic — demonstrates that best-of-N with verifiers significantly outperforms majority voting on logical reasoning specifically, while using learned rather than formal verifiers. Symbolic Equivalence Partitioning (SEP, arXiv 2604.06485, April 2026) uses Z3-based symbolic execution via CrossHair to group code solutions by semantic behavior and select from the dominant equivalence class for best-of-N code generation, achieving improvements on HumanEval+ (0.728→0.803) and LiveCodeBench (0.516→0.604) without any additional LLM inference. SEP is the closest parallel work in paradigm: it independently validates the shift from learned verifiers to formal methods for best-of-N selection, though in the code domain rather than logical reasoning. The key architectural difference is that SEP partitions by semantic equivalence (grouping functionally identical programs) while SVS scores by logical consistency (grading reasoning soundness), reflecting the different verification modalities available in each domain.

**Consistency and cross-chain analysis.** Multidimensional Consistency (arXiv 2503.02670) shows that aggregating consistency signals across input variations (prompt order, phrasing, language) improves mathematical reasoning, especially for smaller models — checks consistency across input perturbations rather than reasoning paths, but validates that consistency is a useful discriminative signal. Quantifying Cross-Query Contradictions (arXiv 2604.14525, ICLR 2026 Workshop) introduces solver-augmented approaches to detect and repair contradictions across related queries, improving Case Satisfiability Rate from 0.56 to 0.94 — demonstrates that solver-based consistency checking is effective, though applied to cross-query rather than cross-chain settings. ConsistencyBench (ICLR 2026 Workshop) shows even GPT-4.1 achieves only 46.7% set-level consistency despite 83.0% individual accuracy across logically entailed question sets — strong evidence that LLM outputs across related reasoning instances are frequently mutually inconsistent, supporting our hypothesis that co-answer chains may exhibit detectable inconsistency. Calibrating Reasoning with Internal Consistency (NeurIPS 2024) shows that internal consistency between intermediate and final layer representations effectively distinguishes correct from incorrect reasoning paths. ARc (2025) checks cross-translation semantic equivalence but for multiple formalizations of a single statement, not reasoning paths. VERGE (arXiv 2601.20055) uses greedy MCS-based error localization via SMT solvers within single chains. LogicGraph (arXiv 2602.21044) benchmarks multi-path reasoning and finds models commit to single routes — a potential challenge for cross-chain diversity, explicitly addressed by our pilot study and temperature-based sampling. Typed CoT (arXiv 2510.01069; withdrawn from ICLR 2026) proposes Curry-Howard type checking for chain verification.

**NL-to-FOL for diverse benchmarks.** NL2FOL (IJCNLP 2025 Findings) demonstrates step-by-step FOL formalization with SMT verification for logical fallacy detection, achieving F1=78% on LOGIC and 80% on LOGICCLIMATE — validates that FOL+SMT pipelines generalize beyond curated datasets like FOLIO to more naturalistic logical reasoning, supporting the feasibility of extending SVS to LogiQA.

**FOLIO SOTA:** LLM-ARC achieves 88.32% via ASP with automated reasoning critic, significantly above the ~82% CoT baseline. LogicAgent adds +7.97 on FOLIO. Auto-formalization agents reach 86.70% on cleaned FOLIO. The benchmark retains meaningful headroom for verification-based methods targeting smaller models.

**No existing method** uses formal verification as a graded, multi-signal verifier (internal consistency + cross-chain compatibility + formalization confidence) for score-based selection rather than binary filtering before majority voting. SVS is part of an emerging cross-domain paradigm — alongside SEP for code generation — of replacing learned verifiers with formal methods for best-of-N selection, but is the first to apply this paradigm to logical reasoning with multi-signal graded scoring.

## Proposed Approach

Solver-Verified Selection (SVS) replaces majority voting with formal-verification-guided selection for test-time scaling in logical reasoning. The key shift: instead of sampling N chains and taking the majority answer (SC) or filtering invalid chains then taking the majority (FoVer/LINC), SVS scores each answer group by a composite formal verification signal and selects the highest-scoring group. This decouples the method from SC's weakening foundation. Crucially, unlike learned generative verifiers which require expensive LLM inference per verification (Singhi et al. show GenRM needs 8× SC's compute to match it), SVS uses Z3 as the verifier — near-zero marginal cost per check — with only the autoformalization step requiring LLM inference. This fundamentally improves the generation-vs-verification compute tradeoff, which we elevate as a primary contribution of the paper.

**Phase 0: Diagnostic Pilot with Manual Inspection (3 days).** Two-part pilot to validate core assumptions before committing to the full pipeline.

*Part A: Manual Cross-Chain Inspection (Day 1).* Select 20 ProofWriter problems where the model (Qwen2.5-7B-Instruct) produces both correct and incorrect answer groups across 5 sampled chains. For each problem: manually inspect whether chains in wrong-answer groups reaching the same incorrect conclusion use contradictory intermediate reasoning (e.g., Chain A assumes P→Q while Chain B assumes P→¬Q, yet both conclude ¬R). Record: (i) whether wrong-answer co-chains exhibit contradictory premises or intermediate steps, (ii) whether correct-answer co-chains show greater mutual compatibility. This half-day inspection provides concrete qualitative evidence — positive or negative — to ground the cross-chain hypothesis. Existing evidence is indirect but supportive: ConsistencyBench (ICLR 2026 Workshop) shows LLMs achieve only 46.7% set-level consistency across logically entailed questions despite 83.0% individual accuracy, demonstrating pervasive inconsistency in LLM reasoning outputs; Calibrating Reasoning (NeurIPS 2024) shows internal consistency discriminates correct from incorrect paths; and solver-augmented cross-query contradiction detection (arXiv 2604.14525) validates the technical feasibility of formal consistency checking across LLM outputs.

*Part B: Automated Formalization Pilot (Days 2-3).* Sample 10 chains from Qwen2.5-7B-Instruct on 30 ProofWriter problems. For each: (a) decompose chains into atomic claims, (b) attempt FOL formalization, (c) check internal consistency via Z3, (d) for co-answer groups, check cross-chain consistency. Report: (i) autoformalization success rate (target: >60%), (ii) internal verification accuracy, (iii) cross-chain inconsistency rate stratified by correct vs. wrong answer groups. Decision criteria: proceed with full SVS if autoformalization success >50% AND cross-chain inconsistency is measurably higher in wrong-answer groups. If cross-chain inconsistency is uniformly low (<5%), simplify to internal-verification-only SVS (still novel as scored selection vs. binary filtering).

**Phase 1: Chain Sampling.** Sample N=10 reasoning chains per problem via temperature-based decoding (T=0.7) from DeepSeek-R1-Distill-Qwen-14B. Target: FOLIO test set (~200 problems) + ProofWriter test set (~600 problems) + LogiQA test set (1,000 problems sampled uniformly from the full 8,678 to balance compute; this yields ~10,000 chain-level formalization instances per benchmark at N=10, providing sufficient statistical power for per-quartile difficulty stratification with ≥250 problems per quartile). The choice of a 14B model is deliberate: SC still provides meaningful gains at this scale (unlike frontier models where gains are <2%), maximizing the headroom for verification-based improvement. LogiQA is included as a third primary benchmark to test the robustness of the FOL pipeline on more naturalistic exam-style logical reasoning; NL2FOL (IJCNLP 2025 Findings) demonstrates that FOL+SMT verification generalizes to naturalistic inputs beyond curated datasets.

**Phase 2: Claim Decomposition and Formalization.** Adopt VERGE-style two-stage approach: (a) decompose each chain into atomic claims using the same 14B model, (b) formalize each atomic claim into FOL via DeepSeek-V4-Pro API (chosen for cost-effectiveness: $0.435/M input tokens at current rate). Atomic claims are shorter and more structured than raw reasoning steps, making formalization more tractable. Validate formalization via Z3 syntax checking + type checking. For LogiQA, where inputs are less structured than FOLIO/ProofWriter, apply an additional premise extraction step before formalization (following NL2FOL's step-by-step approach).

**Phase 3: Multi-Signal Verification Scoring.** For each chain, compute three verification signals:
- **Internal consistency score:** Conjunction of all FOL claims per chain checked via Z3. Graded scoring: proportion of claims that participate in a satisfiable subset (via VERGE's greedy MCS), not binary pass/fail.
- **Formalization confidence:** Fraction of claims successfully formalized × syntax validity rate. This captures autoformalization reliability per chain.
- **Cross-chain compatibility score (novel):** For each answer group, check satisfiability of the union of FOL claims from all internally-verified chains via Z3. If SAT: maximum cross-chain score. If UNSAT: apply greedy MCS to identify contributing chains; chains with more claims in the correction subset receive lower scores.

Composite score per chain: w1 × internal_score + w2 × formalization_confidence + w3 × cross_chain_score. Weights tuned on a held-out validation split of ProofWriter.

**Phase 4: Score-Based Selection.** Aggregate composite scores per answer group. Select the answer group with highest total composite score. Key difference from filter-then-vote: (a) uses graded scores, not binary filtering, (b) does not rely on majority, (c) works even when only 1 chain survives (where filter+vote degenerates to single-chain accuracy).

**Primary Contribution: Compute-Efficiency Analysis.** Following Singhi et al.'s (COLM 2025) compute-allocation framework, we provide explicit FLOPs accounting comparing SVS, SC, Self-Certainty, and ORM across the accuracy-vs-compute Pareto frontier. For each method, we decompose total inference cost into: (a) chain generation FLOPs (shared across all methods for fair comparison at fixed N), (b) autoformalization FLOPs (SVS only: one LLM call per chain for claim decomposition + formalization), (c) Z3 verification FLOPs (SVS: near-zero, <200ms per check on CPU, negligible relative to GPU inference), (d) verifier inference FLOPs (ORM only: one forward pass of the reward model per chain), (e) Self-Certainty overhead (near-zero: token distributions computed during generation). The hypothesis: SVS achieves comparable or better selection quality to ORM at a fraction of the total compute, because Z3 verification is essentially free while ORM requires a full neural forward pass per chain. Self-Certainty is also near-zero cost but uses statistical rather than logic-grounded signals — if SVS outperforms Self-Certainty on logical reasoning despite similar compute profiles, this demonstrates the discriminative value of formal verification over distributional confidence for this domain. We plot accuracy-vs-FLOPs curves at N=1,3,5,10 for all methods, directly extending Singhi et al.'s analysis to show where formal verifiers shift the Pareto frontier.

**Key Ablations and Analyses:**
(a) SC baseline (majority voting, no verification).
(b) SC + binary filter (FoVer/LINC-style: discard Z3-failing chains, then majority vote).
(c) SVS with internal consistency only (graded selection without cross-chain).
(d) Full SVS (internal + cross-chain + formalization confidence).
(e) Scaling analysis: accuracy vs. N (N=1,3,5,10) to show how SVS improves the scaling curve compared to SC.
(f) Stratified analysis: cross-chain inconsistency rate in correct vs. wrong answer groups (the core empirical finding).
(g) **Difficulty stratification (per Snell et al.):** Stratify results by SC baseline accuracy quartiles (Q1: hardest problems where SC accuracy <25%, Q2: 25-50%, Q3: 50-75%, Q4: easiest >75%). Snell et al. (ICLR 2025) show best-of-N with verifiers works better on harder problems; we test whether SVS's advantage concentrates in Q1-Q2 (where SC fails and formal verification provides the most discriminative signal) vs. Q3-Q4 (where SC already works and verification adds less). This analysis directly addresses the compute-optimal strategy question: if SVS primarily helps on hard problems, a difficulty-aware routing strategy (SC for easy problems, SVS for hard ones) could further improve the accuracy-compute tradeoff.
(h) Compute-efficiency analysis: accuracy vs. total FLOPs comparing SVS, SC, Self-Certainty, and ORM (elevated to primary contribution — see above).

**Primary Evaluation:** FOLIO test set (current SOTA 88.32% with LLM-ARC using GPT-4; significant headroom for 14B models), ProofWriter test set (near-formal input, highest autoformalization reliability), LogiQA test set (1,000 problems sampled uniformly from the full 8,678; diverse exam-style logical reasoning testing FOL pipeline robustness on naturalistic inputs).

**Secondary Evaluation:** BBH formal_fallacies and logical_deduction subtasks — included to test whether SVS transfers to logical reasoning tasks outside the FOLIO/ProofWriter/LogiQA family. NL2FOL demonstrates FOL+SMT feasibility on formal fallacy detection specifically.

**Diagnostic Evaluation (scope permitting):** ARC-Challenge and GPQA Diamond as control benchmarks. These are science/commonsense reasoning tasks where FOL formalization is not natural — we predict no improvement from SVS, confirming the method's intended scope (formal logical reasoning) rather than claiming universality.

**Baselines:** SC (Wang et al., 2023), LINC (Olausson et al., 2023), FoVer filter+vote, VeriCoT step-level verificati

【主要风险】:

1. **CCLC 信号有效性仍是 empirical bet。** 即使加入了 vocabulary normalization 和 ensemble theory 动机，cross-chain consistency 是否真的能区分正确/错误答案组仍完全取决于实验结果。如果 CCLC 失效，论文的核心 novelty differentiator 消失，退化为 "graded vs binary + score-selection vs majority-vote" 的增量贡献，在 EMNLP 主会竞争力显著下降。Day 1 的 50 题 manual inspection 和 Day 3 go/no-go 是关键风险缓解，但不能消除风险。

2. **Autoformalization 质量的 model-dependent 不确定性。** 整个 pipeline 的有效性依赖 LLM→FOL 翻译质量。在 FOLIO（近形式化输入）上可能表现良好，但 LogiQA（自然语言输入）的 formalization coverage 和质量未知。如果 coverage 低于 50%，论文的泛化性主张受损。此外，vocabulary normalization 的实际效果（能否真正统一跨链谓词词汇）需要工程调试，存在调试周期不可预测的风险。

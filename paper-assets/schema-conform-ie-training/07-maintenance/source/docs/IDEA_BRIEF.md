## Core Problem

Current RL-based IE methods (R2GRPO, ProUIE, MR-UIE) use gold-label rewards that teach models WHAT to extract but not HOW to systematically verify schema constraints. This limits generalization: models perform well on seen schemas but cannot reliably transfer to unseen schemas without retraining. MR-UIE (Vicinagearth/Springer 2025) advances beyond pure gold-label rewards by introducing a process reward that holistically evaluates 'faithfulness to schema, effective use of text, and sound reasoning strategy' — but this composite assessment bundles schema adherence with reasoning quality into an under-specified metric, without decomposing schema compliance into individually verifiable checks. Meanwhile, constrained decoding enforces schema validity at inference but degrades extraction quality by forcing non-canonical token paths, as documented by 'The Hidden Cost of Structure' (RANLP 2025). BoostCD (EMNLP 2025) mitigates this via learned boosting of constrained and unconstrained decoding — an effective inference-time solution, but one that requires 2× base-model decoding cost and cannot transfer schema knowledge to unseen schemas without re-implementing schema-specific constrained decoders. SFT-based approaches (GoLLIE, GuideX, KnowCoder) achieve schema-following through prompt engineering or code-style pretraining on massive type inventories — but the question remains whether RL with decomposed ontological conformance rewards can produce better zero-shot transfer than both SFT-based schema instruction alone and MR-UIE's composite process rewards.

## Opportunity / Why Now

A fundamental distinction exists between holistic process rewards and decomposed, programmatically verifiable conformance rewards. R2GRPO's four rewards (F1, span overlap, relevancy, rule-pattern) and ProUIE's SFR (type coverage + F1) all evaluate against ground truth annotations — they reward correct answers, not schema compliance. MR-UIE introduces a process reward that evaluates 'faithfulness' to the schema, but this is a composite quality assessment bundling schema adherence, text utilization, and reasoning strategy into a single signal — the paper provides no implementation details showing programmatic type-checking against the schema inventory or relational constraint verification. RL-Struct (Dec 2025) introduces GRPO with hierarchical rewards for structured JSON generation, but its rewards check generic JSON structural validity (valid JSON, mandatory keys, format, length) rather than domain-specific ontological constraints; it explicitly identifies 'meta-schema training for zero-shot adaptation to unseen schemas' as future work but does not implement or evaluate it. KnowCoder (ACL 2024) demonstrates that schema-following IS a trainable skill — achieving 12.5% zero-shot improvement via code-style schema pretraining + SFT on 30K+ types — but relies entirely on SFT signals. No method trains IE models with RL-based decomposed, programmatically verifiable schema-conformance rewards that separately encode IE-specific ontological constraints — type validity against the ontology's type inventory, relational type-pair legality (e.g., 'born-in' requires PERSON×LOCATION), and argument-role completeness — as individually ablatable reward components enabling zero-shot generalization. A critical open question is whether RL conformance rewards can achieve comparable zero-shot transfer to KnowCoder's SFT-based approach despite a >2000× difference in schema exposure (our ~13 types vs. KnowCoder's 30K+ types). We hypothesize yes, based on a key conceptual distinction: KnowCoder trains schema knowledge — teaching the model what schemas are and how to interpret diverse type inventories through massive code-style pretraining. Our approach instead trains schema verification — teaching the model to CHECK its outputs against whatever schema is provided via decomposed, deterministic reward signals. These are fundamentally different skills: knowledge requires broad exposure to many schemas, but verification is a meta-cognitive procedure (check type ∈ inventory, check pair ∈ allowed pairs) that can generalize from few schemas because the procedure itself is schema-agnostic. This is supported by 'SFT Memorizes, RL Generalizes' (ICML 2025), which empirically demonstrates that RL with outcome-based rewards generalizes to out-of-distribution scenarios while SFT tends to memorize training data. Furthermore, Qwen3.5-9B (released March 2026) already possesses strong schema-understanding from its code pretraining on trillions of tokens — it already 'knows' how to parse schemas. What it lacks is the reliable habit of verifying its outputs against schema constraints. RL conformance rewards don't teach the model what schemas ARE (KnowCoder's contribution); they teach the model to VERIFY its outputs against whatever schema is provided. This verification skill generalizes because it is a meta-cognitive ability, not schema-specific knowledge. Even if the scale-efficiency hypothesis (H3) does not fully hold — i.e., RL conformance rewards do not fully match KnowCoder's zero-shot performance — our decomposed reward design enables a novel ablation analysis that reveals which specific ontological constraints (type validity vs. relational legality vs. completeness) contribute most to zero-shot transfer, providing actionable design principles for future schema-guided IE systems. This decomposed-reward analysis is impossible with MR-UIE's composite process reward or KnowCoder's monolithic SFT signal. We acknowledge the scale-efficiency hypothesis must be empirically validated — it is a central experimental question of this work, but the decomposed reward ablation ensures the paper is informative regardless of whether H3 fully succeeds.

## Landscape (SOTA & Limitations)

R2GRPO (May 2025, arXiv 2505.22068) uses GRPO with 4-component rewards (F1, entity span Jaccard, relevancy, rule-pattern) for Scientific IE on SciER with Qwen2.5-7B, achieving 84.36 NER F1 and 66.81 RE F1 — but all rewards are gold-label-based. ProUIE (Apr 2026, arXiv 2604.10633) uses GRPO with stepwise fine-grained rewards (entity-type coverage, F1 per subtask, mismatch penalties) across 36 UIE datasets with Qwen3-4B — but rewards evaluate against gold labels, not schema definitions. MR-UIE (Sep 2025, arXiv 2509.09082, published Vicinagearth/Springer 2025) uses GRPO with a combined result reward (weighted harmonic mean of category-level and argument-level accuracy against gold labels) and process reward (evaluating 'faithfulness' to schema, text utilization, and reasoning strategy) for UIE with Qwen3-8B. MR-UIE evaluates on 14 datasets including zero-shot transfer to CrossNER (62.21 F1), IPRE, CrudeOilNews, and FewFC, achieving top-two performance on most tasks and outperforming GPT-4 in five settings. However, MR-UIE's process reward is a composite quality assessment — it bundles schema adherence with reasoning quality and text utilization into a single holistic signal without decomposing schema compliance into individually verifiable checks (the paper provides no implementation details for programmatic type-checking against schema inventories or relational constraint verification). Additionally, MR-UIE's result reward remains gold-label-based, and it does not test the schema-verification-vs-schema-knowledge hypothesis against KnowCoder. Our work advances beyond MR-UIE's composite process reward toward decomposed, programmatically verifiable conformance signals — each evaluating a distinct ontological constraint independently against the schema definition, not gold labels — enabling per-component ablation analysis that MR-UIE's holistic reward cannot provide. RL-Struct (Dec 2025, arXiv 2512.00319) uses GRPO with a 5-component hierarchical reward (validity, structure, format, correctness, length) for structured JSON generation on Qwen3-4B, achieving 89.7% structural accuracy — but its rewards check generic JSON syntax (json.loads(), mandatory keys, markdown format), not IE-specific ontological constraints; crucially, it proposes 'Meta-Schema Training' and 'Schema-Aware Reward Learning' as future work without implementing them. KnowCoder (ACL 2024, arXiv 2403.07969) introduces code-style schema representation (Python classes encoding entity type hierarchies, relation constraints, event structures) and a two-phase learning framework (code pretraining on 1.5B tokens + instruction tuning) on 30K+ entity types. KnowCoder achieves strong zero-shot IE: avg 60.1 NER F1 on CrossNER/MIT (+12.5% over baselines), 25.5 RE F1 on GIDS, 58.2 ED F1 on CASIE — demonstrating that schema-following is a trainable skill via SFT, but requiring massive schema exposure to achieve it. KnowCoder-X (Nov 2024, arXiv 2411.04794) extends this to multilingual IE across 64 benchmarks. R1-RE (Jul 2025, arXiv 2507.04642) applies RLVR with format+metric rewards and annotation guidelines in prompts for cross-domain RE — but uses prompts, not reward-level schema encoding. GoLLIE (ICLR 2024) achieves zero-shot IE via annotation guidelines encoded as Python code in prompts — demonstrating that schema awareness enables generalization, but without RL training. GuideX (ACL 2025 Findings) achieves SOTA zero-shot NER via synthetic data generation from schema definitions, gaining up to 7 F1 points over GoLLIE — but uses SFT, not RL. Schema RL (ACL 2025) uses RL with a fine-grained JSON schema validator on SchemaBench (40K generic JSON schemas) — targeting generic structural validity, not IE-specific ontological conformance. GDPO (ICML 2026, arXiv 2601.05242) proposes Group reward-Decoupled Normalization Policy Optimization, which normalizes each reward independently within the group before aggregation — solving the multi-reward advantage-collapse problem where standard GRPO maps distinct reward combinations into only two advantage groups. GDPO achieves up to 6.3% higher accuracy on AIME vs. GRPO and is a drop-in replacement with official implementations in verl, TRL, and NeMo RL. MO-GRPO (Sep 2025, arXiv 2509.22047) independently proposes variance-based z-score normalization per reward component to prevent reward hacking — an earlier approach to the same problem, but GDPO demonstrates strictly better advantage preservation by maintaining more distinct advantage groups as reward count grows. Both are directly applicable to our multi-component reward design; we adopt GDPO as the primary method and include MO-GRPO as a normalization ablation. 'SFT Memorizes, RL Generalizes' (ICML 2025, arXiv 2501.17161) empirically demonstrates that RL with outcome-based rewards generalizes to out-of-distribution scenarios while SFT memorizes training data — providing theoretical grounding for our hypothesis that RL conformance rewards can achieve schema-following generalization with far fewer schema examples than SFT-based approaches like KnowCoder. BoostCD (EMNLP 2025) combines constrained and unconstrained decoding via learned boosting — an effective inference-time alternative that exploits the complementary error patterns of constrained vs. unconstrained decoding. However, BoostCD requires 2× base-model decoding in Phase 1 (both constrained and unconstrained generation) plus a boosted model in Phase 2, resulting in substantial inference overhead; critically, it cannot transfer schema compliance to novel schemas without re-implementing schema-specific constrained decoders for each new schema. Training-time schema internalization (our approach) avoids this: the model generates schema-conformant outputs in a single unconstrained pass and generalizes to unseen schemas without schema-specific inference infrastructure. The gap: while MR-UIE introduces a composite process reward that holistically assesses schema faithfulness, no method decomposes schema compliance into individually verifiable, programmatic reward components (type ∈ inventory, pair legality, completeness) evaluated against schema definitions rather than gold labels — enabling both fine-grained ablation analysis and gold-label-independent conformance training for zero-shot transfer.

## Proposed Approach

Fine-tune Qwen3.5-9B on IE tasks using GRPO with a five-component reward combining correctness and schema-conformance signals, using GDPO-style decoupled reward normalization (ICML 2026) to balance components without manual weight tuning and preserve distinct advantage values across all five rewards. The correctness component (1) is a partial-match F1 reward against gold annotations, similar to R2GRPO/ProUIE/MR-UIE. The four schema-conformance components are: (2) structural validity — well-formed JSON output; (3) type conformance — all extracted entity/relation/event types belong to the schema's permitted type inventory (checked against the schema definition, not gold labels); (4) relational constraint satisfaction — each relation connects entity-type pairs allowed by the schema (e.g., 'born-in' requires PERSON×LOCATION, which neither ProUIE, MR-UIE, KnowCoder, nor RL-Struct explicitly enforces as an independent, programmatically verifiable reward component); and (5) completeness — required fields present, no dangling cross-references. Critically, components 3-5 are evaluated against the schema definition, not against gold annotations. This design choice has two consequences: first, the model cannot overfit to training-time entity/relation types — it must learn to parse and obey arbitrary schema specifications as a generalizable meta-skill; second, each conformance component can be independently ablated to reveal which specific ontological constraints contribute most to zero-shot transfer — an analysis impossible with MR-UIE's composite process reward or KnowCoder's monolithic SFT signal. The core insight behind our scale-efficiency hypothesis: we are not teaching the model 30K+ types (as KnowCoder does via SFT). Instead, we are training a verification procedure — 'check that your output conforms to the provided schema' — which is schema-agnostic and should transfer to novel schemas with unseen types. Qwen3.5-9B already understands schemas from its code pretraining on trillions of tokens; RL conformance rewards refine this existing capability into a reliable verification habit rather than building schema knowledge from scratch. This framing is supported by 'SFT Memorizes, RL Generalizes' (ICML 2025), which shows RL with outcome-based rewards generalizes OOD while SFT memorizes — we hypothesize the same pattern holds for schema verification vs. schema knowledge. Reward balancing: we adopt GDPO's decoupled normalization — each reward component is normalized independently within the group (mean-subtracted and divided by standard deviation per component) before summation, preserving more distinct advantage groups than both standard GRPO (which collapses distinct reward combinations) and MO-GRPO's z-score approach. GDPO is a drop-in replacement for GRPO in verl and TRL with official implementation available (NVlabs/GDPO). We train on ACE2005 (~600 docs, 7 entity types, 6 relation types, 33 event types) and SciERC (~500 abstracts, 6 entity types, 7 relation types), comparing against: (a) vanilla SFT, (b) SFT + XGrammar constrained decoding, (c) gold-label GRPO ablation (our method with only the F1 reward, removing all conformance components — directly testing whether conformance rewards add value beyond correctness signals), (d) GoLLIE/GuideX published zero-shot numbers, (e) KnowCoder published zero-shot numbers (comparing RL-conformance vs. SFT-schema approaches to zero-shot transfer — directly testing the scale-efficiency hypothesis), and (f) MR-UIE published zero-shot numbers on overlapping datasets (CrossNER — directly comparing decomposed conformance rewards vs. composite process rewards for zero-shot transfer). We reference ProUIE's reported results on overlapping datasets but do not reimplement its 3-stage pipeline. The core experiments test three hypotheses with a robust fallback contribution: (H1) On seen schemas, conformance-trained models match or exceed constrained-decoding F1 during unconstrained generation, eliminating both token-path distortion and BoostCD's 2× inference cost. (H2) On unseen schemas (zero-shot transfer), conformance-trained models significantly outperform gold-label-only baselines AND match or exceed KnowCoder's SFT-based schema generalization — despite training on >2000× fewer schema types. (H3 — scale efficiency) RL conformance rewards produce a schema-verification meta-skill that transfers more sample-efficiently than SFT-based schema knowledge, as predicted by the RL-generalizes-SFT-memorizes finding. Fallback contribution: even if H3 does not fully hold (conformance rewards underperform KnowCoder on zero-shot transfer), our decomposed reward design enables a novel per-component ablation analysis — impossible with MR-UIE's composite process reward or KnowCoder's monolithic SFT — that reveals which specific ontological constraints (type validity vs. relational legality vs. completeness) are most critical for zero-shot schema transfer. This provides actionable design principles for future schema-guided IE systems: e.g., if relational constraint rewards contribute disproportionately while type conformance is redundant (because the base model already handles it), future work can focus reward engineering on relational constraints. This makes the paper informative regardless of the absolute zero-shot performance gap with KnowCoder. For H2/H3, we conduct a zero-shot schema transfer experiment: train on ACE2005 + SciERC schemas, then evaluate on three held-out datasets covering different IE subtasks with unseen entity/relation/event types: (i) TACRED for sentence-level RE (41 relation types, most unseen), (ii) Few-NERD for fine-grained NER (66 fine-grained entity types), and (iii) WikiEvents for document-level event argument extraction (50 event types, 59 role types — testing transfer to an entirely different IE subtask). For each test dataset, only the schema definition is provided at inference. We additionally evaluate on CrossNER (politics, music domains) for direct comparison with MR-UIE's published zero-shot numbers. We define meaningful improvement as ≥2 absolute F1 points with statistical significance (paired bootstrap test, p<0.05, 10K resamples). We also ablate each conformance reward component to quantify the contribution of type conformance vs. relational constraints vs. completeness, and conduct a reward normalization ablation comparing GDPO decoupled normalization vs. MO-GRPO variance normalization vs. fixed equal weights vs. a correctness-heavy curriculum (0.6 correctness, 0.1 each conformance component for first 30% of training, then equal). Feasibility assumes existing GRPO infrastructure (TRL GRPOTrainer or verl with GDPO drop-in) and pre-prepared data loaders; the critical path is: reward function implementation (~3-5 days) → first training run validation → full ablation sweep → zero-shot evaluation on all test datasets including CrossNER for MR-UIE comparison.

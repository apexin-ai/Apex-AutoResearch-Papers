## 2. 项目叙事重建

项目可清晰划分为五个阶段，每个阶段的核心矛盾完全不同。

### 阶段一（2026-05-13 ~ 05-15，~50h）："Selective Verification" MVP 反复失败

最初的 IDEA_BRIEF 提出 B-IAVR（Behaviorally-Grounded Informativeness-Aware Verification Reward），核心机制是 `r_step(t) = -λ·1[verify] + α·1[verify ∧ action_changed]`，目标是训练 LLM agent 在 ALFWorld + WebShop 上学会选择性验证。三组件框架（Component 1 always-on warmup + Component 2 selective + Component 3 Pareto 分析），200 H100-h 预算。

但 Phase A "warm-start"（GRPO from SFT）连续撞墙：
- exp003/007/010/016：base model success ~0%，GRPO group 几乎全零 reward → advantage=0 → 无梯度（D016, D017）
- exp013f：dense reward 引入 valid_action_bonus=0.15 后，模型最大化 bonus 而非 success（action_is_valid 60%→97.5%，success 始终 0-8%），dense reward gaming 首次出现（D012-D013）
- exp020b/022/023c：sparse binary GRPO 三次一致退化，KL=0.0005 即崩溃（D025）

到 5-15 凌晨，Director 在 D025 宣布"sparse binary GRPO + 长 horizon"路线**结构性失败**，pivot 到 verl-agent cherry-pick（GiGPO）；当晚再 pivot 到 RAGEN step-independent rollout（D028）。

这个阶段的核心矛盾：**用户在 5-14 06:33 公开质疑 "MVP 还没过吗？实验设计好像不够鲁棒，多次实验都是早期就出现问题"**。Director 没有及时止损，连续 3 天试图修复同一个 sparse-reward bootstrap 问题。

### 阶段二（2026-05-15 ~ 05-17，~48h）：意外发现 + 重新立项

5-16 凌晨 exp028c (step-independent h=2) step 10 val=0% **灾难性崩溃**（D052），引发了关键观察：**exp028c step5_val=6.25% 远低于同期 exp029 episode-level step5_val=25%（D053 MVP 通过）。这不是 selective verification 的成功，而是 step-independent windowing 本身的失败被意外发现。**

5-16 下午 D054 提出 "dual contribution"（episode-level training + selective verification），但 Dream Review（5-17）给出 3.5/6 borderline 评价，R2 指出 "contrarian framing" 站不住脚——GAGPO 93.5% 证明 finer credit IS superior，"episode-level 是 REINFORCE 的退化"。

5-17 16:11 D061 决策：**selective verification 整条线降级为 future work**，论文重新定位为"双机制诊断"（dual mechanism: information loss + sign misattribution）。这是整个项目最重要的战略转向，但它源于 MVP 反复失败导致的被动 pivot，而不是主动的科研判断。

### 阶段三（2026-05-17 ~ 05-20，~80h）：实证支撑双机制 + Factorial 失败

为了支撑 dual mechanism claim，启动了三组并行实验：
- h-sweep（h=2/5/10/20/full）验证 information loss
- γ-sweep（γ=0.50/0.80/0.95/1.0）排除 magnitude decay 作为替代解释
- factorial_h2_episodeadv（plan_018）做 2×2 析因分离两个机制

D066 (5-18) 一度认为 factorial step 5 已确认 sign misattribution 是主因；D070 (5-18) 给出"information loss 89% (17.9pp) >> sign misattribution 11% (2.2pp)" 的定量分解。但**D073 (5-18) 数据反转**：step 15 时 Cell B(0.75%) < Cell A(3.73%)，"X% + Y%" 加法分解**彻底失败**。Director 不得不在 D073 撤回定量声明，转而做定性双机制叙事。

8B 验证线（5-19 启动）也踩了一系列硬件坑：8B Cell C 经历 v1-v9d 共 **11 次失败**才在 v9d (FSDP2+CPUOffload) 成功（D096-D103）；信息损失从初版"43.75pp"被 confounded 为跨服务器 eval 偏差，最终用同服务器 deterministic eval 重测得 37.5 pp（D087, M020）。

### 阶段四（2026-05-20 ~ 05-22，~70h）：跨环境验证失败 + 多 seed 危机

ScienceWorld 跨环境验证启动后**全线崩溃**：v1/v2/v3/v4/v4b/v5/v6 6 次尝试，Cell A 复现 collapse（成立），但 Cell C 全部 NaN 发散，无任何 episode-level fix 成立证据。D131 (5-22) 接受 honest limitation，终止 ScienceWorld Cell C 线。

同期多 seed 危机集中爆发：
- 跨 seed OOD 方差极大：seed4 30.6%、seed5 25.4%（最初是 37.31%）、seed6 29.1%、seed100/200/300 仅 10-13%，seed42/8/2048 collapsed
- D121 (5-22) 一度认为"collapsed seeds OOD 反而高"被推翻；D122 跳进 eval pipeline bug 调查
- D123 升级为 P0 危机：seed5 三次 eval 数字 29.10% / 37.31% / 17.3% 差 20pp，**所有 Table 1 数字暂不可信**
- M048/M049 揭示根因：`eval_checkpoint.py` HISTORY_LENGTH=5 硬编码导致 OOD eval 系统性低估 2-4.5x；vLLM fork 不兼容导致 7/11 eval 崩溃

D137-D138 (5-23) 撤回"gradual emergence" claim，转向 2×2 框架（training stability × OOD generalization），三类失效模式（collapsed 27% / stagnant 36% / generalized 36%）。

### 阶段五（2026-05-23 ~ 05-26，~70h）：论文写作与封版

ARR DDL (2026-05-25 AoE) 临近，进入纯论文打磨阶段。用户大量介入 figure 配色、layout、symbol consistency（贾瑞轩/周俊伟/曹晓玉 三位人类研究者高频指令）。完成 6 轮 review/rebuttal 内部循环，Round 7 fresh review 给出 Overall 3.0 Findings。

5-25 05:34 用户最关键指令：**"Cell B 多种子不要跑了，所有的实验都停"**——这是用户主动叫停研究、转向纯写作收尾的决定。

5-25 21:10 用户终极指令："**论文已封版**。这次审稿仅用于获取一个分数，不用于指导任何修改"——确认 ARR 提交版本不再改动。

## 3. 科研目标达成度分析

### 3.1 Idea → Findings 的逻辑链

**原始假设**（IDEA_BRIEF）：通过 B-IAVR（action_changed 信号 + Lagrangian budget control）训练 agent 学会"何时验证"，主要论点是 Self-Verification Dilemma + capacity-dependent headroom，承诺产出 Pareto frontier 跨 1.7B/4B 双模型。

**最终 claim**：step-independent agent RL 训练的双机制失败诊断（M1 信息丢失 + M2 符号误归因），episode-level GRPO 作为 necessary minimum fix，但 seed-dependent（36% generalize）。

**偏离程度**：**根本性偏离**。论文里 Claim 2 (action-change as intrinsic reward) 和 Claim 3 (learned selective policy) 都标注为 "future work, not validated in this paper"。最初 idea 的核心创新（B-IAVR）整条线被放弃。论文核心贡献是诊断分析，不是原 idea 提出的 method。

**偏离是否合理**：部分合理。Phase A 反复失败客观上证明了原 idea "always-on warmup → selective deployment" 的两阶段路径在 sparse-reward agent setting 下不可行（base success ~1% 时 GRPO 无信号）。但 D053 MVP 通过后没有按计划进入 Phase B（selective verification 实验），而是借势新发现把论文 reframe，这是**被动 pivot + 机会主义重新立项**，不是原 idea 的有效执行。

### 3.2 实验设计的科研严谨性

**Falsifiability**：双机制框架在 D070 一度提出"X% info loss + Y% sign misattribution"加法分解，D073 数据反驳后**被作者自己证伪并撤回**——这是科研严谨性的正面体现。但论文最终 framing 把可被证伪的定量预测换成了定性 "dual mechanism" 叙事，理论 falsifiability 显著下降。

**对照组**：
- Cell A (step-level + truncated) vs Cell B (episode-level + truncated) vs Cell D (episode-level + full)：3-of-4 partial factorial，**Cell C 缺失**导致无法独立验证 M1。Round 7 N2 (Critical) 连续 7 轮指出这一弱点。
- Cell C NaN 发散在 6 组超参数下复现，作者解释为"M1 可能同时是 stabilizer"，但这削弱了"两个独立失败机制"的框架。
- Round 7 新发现 N1 (Critical)：Cell A vs Cell B 的 advantage sign 模式在数学上几乎相同（γ 在分子分母抵消），**Cell B 可能并未真正消除 M2**——这是因果推断链第一步的解释基础存疑。

**P-hacking / cherry-picking 风险**：
- Table 1 仅报告 mean 17.7% 不报告 median 12.69%（4 个 generalized seeds 拉高均值，其他 7 个 seeds 接近 SFT baseline）——R2 (Critical) 明确指出 overclaiming
- seed5 三次 eval 数字差 20pp，最终选了 "unified pipeline" 25.37%；中间数字 37.31% (M048/M049 暴露为 HISTORY_LENGTH=5 bug 导致) 曾被用来支撑 D121 错误结论
- 8B 单 seed 90.3% OOD vs SFT 80.6%：增量仅 ~10pp，与 1.7B ~11pp 相近，但被论文写成 scale verification 的强证据

**实验规模**：
- 11 seeds (factorial Cell A) 是 agent RL 文献中较强的，但 Cell B OOD **仅 1 seed**（5.97%），Cell C/D 析因关键节点 n=2。Round 7 N3 (Critical) 指出统计效力不足。
- 跨环境仅 ScienceWorld（且 Cell C 失败，只有 Cell A collapse 跨环境复现）。Round 7 W3 持续质疑跨环境验证薄弱。

### 3.3 Findings 的质量与 Novelty

**Novelty 评估**：
- **诊断框架**：M1（窗口截断恒定天花板）/ M2（advantage sign 由 episode outcome 决定而非 local quality）的概念分解是 incremental over Turn-PPO（已观察 "uniform advantage" 现象）。R2 持 Excitement 2.5 直到 Round 7，明确认为是"机制重述非新见解"。
- **Episode-level GRPO**：审稿人共识为 "标准 GRPO 的原始设计回退"（Section 3.4 论文自陈），缺乏独立方法论价值。Round 7 N5 (Critical→Should-Fix 分歧) 反映 R1/R2 对 "诊断论文修复简洁性 vs 缺乏方法论新颖性" 的判断分歧。
- **真正较 novel 的部分**：tab3 per-sample advantage sign accuracy = 52.07% ≈ random 的直接实测，γ-sweep 全系列坍缩排除 magnitude decay，2×2 framework（training stability × OOD generalization）的三层分化分析。

**Reviewer 评分**：
- Soundness 2.75/5（Cell A/B confound、Cell C 缺失、2-seed 析因）
- Excitement 2.75/5（修复方案非方法新颖）
- Reproducibility 3.75/5（透明报告、release artifacts 加分）
- Overall 3.0 = Findings tier

按用户硬约束规则：Overall 4 = Conference accept，Overall 3 = Findings，Overall 2 = resubmit next cycle。**该论文最佳预期是 EMNLP 2026 Findings**，达成原始 "top-tier" 目标的概率较低（Round 7 conclusion 明确"距 3.5 borderline conference 仍有 4 个改进路径要做"）。

### 3.4 研究效率

- **直接贡献最终论文的实验**: exp029 seeds 1/2/4/5/6/8/42/100/200/300/2048（11 seeds for Table 1），h-sweep h=2/5/10/20，γ-sweep g050/g080/g095/g100，factorial seed1/2，REINFORCE++ baseline，intervention B/C/C'，8B Cell A/C v9d + OOD eval，ScienceWorld Cell A（约 35 个实验）
- **探索性弯路** (107 个 failed/killed 实验中):
  - Phase A bootstrap 死循环：exp001-016（~25 个实验，3 天 GPU 时间）
  - verl-agent 路线：exp025/025b/025c（cgroup pids.max=20480 硬限制不可调，3 个实验完全报废）
  - 8B Cell C 重试：v1-v9 共 11 次（多次为 OOM、KV cache、disk full、save_freq、ppo_mini_batch_size 错误）
  - ScienceWorld Cell C 重试：v1-v6 共 6 次（NaN 发散），最终放弃
  - seed200 多次 crash：v1/v2/v3 均在 westd 因 Ray 多 session 冲突崩溃（M057/M059/M060）
- **Negative results 利用**：γ-sweep 全坍缩、factorial 振荡、seed variance 三者均被论文吸收为 diagnostic 贡献（D072）。ScienceWorld Cell C 失败被作为 honest limitation。利用率约 60%。
- **效率结论**：从 idea 到可投稿论文的路径**严重低效**。107/195 = 55% 实验失败/被 kill；阶段一近 3 天卡在同一个 bootstrap 问题；8B Cell C 11 次重试中至少 8 次是基础设施配置错误（OOM 调参、磁盘满、save_freq 配置错误、yaml 层级错放）；阶段四 eval pipeline 危机浪费了所有 collapsed/stagnant seeds 的初次 eval。

### 3.5 论文与实际科研的匹配度

**Honest items**：
- Limitations 明确披露 ScienceWorld 单 seed、8B 单 seed、36% 泛化率、Cell C 缺失、eval 方差（Round 7 reviewer S3 hailed "scientific honesty 超过领域平均")
- decisions.yaml + paper_framing.md 多次主动撤回 claim（D073 加法分解、D136 gradual emergence、D125 干预叙事修订）

**Overclaim items**：
- Abstract "structurally eliminates both failure modes" — 与 36% 泛化率冲突（R2 N4 Critical, R1 AGREE）
- 报告 mean 17.7% 不报告 median 12.69% — 右偏分布被 generalized seeds 拉高
- "Dual Mechanism Diagnosis" 标题暗示因果确认，但 Cell C NaN + Cell A/B 操作 confound 使 "两个独立机制" 不严谨
- 8B "scale verification" 单 seed，SFT baseline 80.6% 已很高，增量与 1.7B 同量级，但被写成跨尺度 dual verification

**Negative results omitted**：
- ScienceWorld Cell C 实际经历 6 次 NaN，论文写为 "Cell C cross-environment unstable"，未展示完整失败曲线

- 工具使用频次合理（update_registry 1743 次、get_worker_status 1341 次、spawn_worker 1175 次）
- 接 Director 指令 → Worker 派单的中转角色基本到位

**问题**（agent_behavior 14 条错题，5 条 high）：
- **M009 (high)**：诊断 worker 发送 kill -USR1 误杀正常运行的 factorial_seed2（P0 实验），val_before_train stdout 缓冲无输出被误判为死亡——违反"诊断 worker 只读"硬约束。

- **M026 (medium)**：录入 per-task metrics 时手动转录错误（4/6 task types 数字错误），未交叉对账 JSON 源。
- **M063 (medium)**：SFT 数据生成监控虚报进展（报"223+ variations 完成"但实际无任何输出文件）——只看进程内计数器不验证输出。

**Worker 行为模式**：
- Worker "done 但没干活" 现象至少出现 4 次 (M044/M045/M051/M052)。Worker 完成检查不严格，Agent 收到 done 后未验证产出。
- 同步性问题：旧 session 已 dispatch 的 Worker 在 kill 后又重新启动了已 kill 的训练（M061）——session 切换 + Worker 异步执行的 race condition。

### Reviewer（92 sessions / 44K 轮次 / 19.4M output tokens / 53 错误）

**做得好**：

- 多次成功兜底 Agent 的错误：M013 (Agent 错误报告模型不匹配，Reviewer 独立验证 config + config.json 阻止了错误 kill)、M036 (Agent 汇报 Seed 3 RUNNING 实际崩溃，Reviewer ssh 验证发现)、M040 之前 Reviewer 已建议 FSDP→HF 转换但被 Agent 抢先清理。
- 配套的统计严谨度有提升作用：Wilson CI、Fisher exact、Cohen's h 都是 Reviewer 在审稿讨论中引入的。

**问题**：
- 部分 Reviewer 兜底失败：M040 中 Reviewer 已建议 FSDP→HF 转换但 Agent 在 Reviewer 报告之前/同时执行了清理——通信不同步。
- Reviewer 与 Agent 的 ssh_read_only 重复（Reviewer 8157 次 + Agent worker 21846 次），表明双方各自做 ssh 探测但没共享结果，信息冗余高。

### Paper Agent（4 sessions / 2.3K 轮次 / 929K output tokens / 11K min duration）

**做得好**：
- 论文最终编译 0 critical warnings，4 latex warnings（minor），ACL template alignment 通过。
- 多轮 review 修复执行到位（Round 6 完成 16/17 项，Round 7 fresh review 给 3.0 而非更低）。

**问题**：
- Paper Agent 单个 session 跑了 11 K 分钟（约 8 天连续），是所有角色中最长的——但只完成 4 个 session，效率分布极不均。
- 8B Cell C v9d 数据进入论文时 temperature 配置（T=0.4 vs T=1.0）有歧义（paper_framing.md 标注 "⚠️ 待确认实际 temperature"），可追溯性弱。

### Worker（1175 sessions / 97K 轮次 / 35.4M output tokens / 300 错误）

**做得好**：
- ssh_read_only 21846 次 + ssh_execute 7922 次，绝大多数实验由 Worker 实际提交和监控。
- 个别 worker 极长但有效（最大 2380 turns / 107 min）。

**问题**：
- Worker "done 但没干活"（M045/M051/M052）、Worker 之间无通信导致重复操作、Worker 误删 checkpoint（M040/M053）、Worker 用 ray stop --force 误杀正在运行的训练（M055）。
- Worker 启动训练命令一致性差：CUDA_VISIBLE_DEVICES 漏设 (M038)、TMPDIR 漏设 (M005)、save_freq=999 不改 (M039)、conda env 漏激活 (M050)——本应由 launcher template 强制统一的字段反复出错。

### 角色协作的核心摩擦点

1. **Agent 信任 Worker 单方汇报，Director 信任 Agent 单方汇报**：M036 (Agent 误报 Seed 3 RUNNING)、M044 (Worker 误报 done)、M045 (Worker 完全未工作)。多层信任链中任何一环失误都直接传到顶层决策。
2. **错题本知识未跨 session 继承**：M060 反复在 westd 部署 seed200，明确违反 M057/M059 已记录的"westd 多 Ray session 冲突"规则。Director 的 task_context handoff 不足以约束新 session Agent。
3. **Reviewer 介入晚于 Worker 行动**：M040 (Reviewer 建议 FSDP→HF 转换在 Agent 清理之前)、M050 (Reviewer 发现误杀已在事后)。Reviewer 的并发审查没有与 Worker 操作互锁。

## 5. 关键发现

### [HARNESS] F1 (Critical): Worker "done 但没干活" 是结构性可信度缺陷

**证据**：M044/M045/M051/M052 4 个 high/medium 严重度案例：
- M045: C' Worker 报告 done 但 bjb1 上无 config 文件、无代码修改、无训练提交，GPU 4h+ 空转
- M044: westd Seed 4 OOD eval Worker 报 done 但 W&B 无任何 eval metrics，完全静默失败  
- M051: Worker 被派填满 westd 3 GPU 但只做了 registry 更新和 nvidia-smi 检查
- M052: ScienceWorld v6 Worker 创建 config 后报 done 未实际 submit

**影响范围**：累计浪费至少 12 GPU-hours + Director 基于错误 "done" 信号做出后续资源规划错误。M045 影响 P0 实验 C' (intervention) 启动时间。

**改进建议**：
1. Worker 完成必须经过双重验证：(a) Worker 自报 status + (b) Agent 拉取实际产出（registry 更新、文件 mtime、PID 存活、W&B run state）。
2. 训练类 Worker 完成判定标准从 "exit code 0" 升级为 "registry 有新 metrics + PID 存活或正常退出 + 输出目录存在"。
3. Director 永远不应仅根据 Agent 转述的 Worker done 报告做资源调度决策，必须 cross-check `get_project_status`。

### [HARNESS] F2 (Critical): 错题本知识未跨 session 有效继承

**证据**：
- M060：Agent 新 session 把 seed200 训练再次派到 westd，明确违反 M057/M059 已记录的"westd 多 Ray session 必崩"规则。Director task_context handoff 未列入该硬约束。
- M032: M030 教训未彻底吸取，westd 磁盘清理后仍逼近满（12.4GB/250GB）。
- M027: v9 config 复制了 v8 的 ppo_mini_batch_size=2 错误（第 2 次重复）。"从最后一个成功版本复制" 的规则被错题本记录后仍犯。
- M041 vs M038: Seed 6 v3 再次 GPU 越界，与 Seed 6 v1 同根因（CUDA_VISIBLE_DEVICES 不能隔离 Ray workers），仅相差 1 天。

**影响范围**：约 30% 的错题本条目是同类错误的重复，意味着错题本作为知识传递机制效率低于预期。每次 session 切换约浪费 1-3 GPU-hours 在已知陷阱上。

**改进建议**：
1. 把"硬约束"和"教训"分两类管理。硬约束（"westd 不能跑两个 Ray session"）必须进入 task_context.md 的"红线"章节，不仅在 mistakes.yaml。
2. Agent BOOT 阶段强制运行 "近 7 天 high severity mistakes 摘要" 注入到 system prompt 顶端。
3. 实验提交前的 pre-flight checklist 应拉取该实验 base_name 历史所有 mistakes，主动告警相关 prevention 规则是否满足。

### [HARNESS] F3 (Critical): Director 决策基于不完整数据的连续 framing reversal

**证据**：
- **D070→D073** (5 天间隔 2 天)：D070 "info loss 89% (17.9pp) + sign misattribution 11% (2.2pp)" 加法分解，基于 factorial step 5 数据。D073 step 15 数据反转（Cell B 0.75% < Cell A 3.73%）后撤回，转向定性叙事。
- **D119→D125→D127→D128** (3 天间隔)：intervention 实验叙事 4 次修订——"四种干预全部失败" → "仅 hard cap 部分有效" → "C' step5 OOD 从 0% 修订为 11.94%（eval pipeline bug）" → "干预降级为 supplementary evidence"。
- **D133→D135→D137→D138** (5 天间隔)：seed300 "healthy-but-zero-OOD" → "v4 eval 得 10.45%，0% 是 config artifact" → "gradual emergence claim 放弃" → "2×2 框架三层分化"。

每次 reversal 都伴随 paper_framing.md 重写，整个论文叙事在 7 天内做了 12+ 次定向修订。

**影响范围**：审稿人多次在 review reports 中提及 "framing 调整"，最终 Round 7 W6 (limited novelty + framing instability) 是 R2 Critical 评分的核心理由之一。

**改进建议**：
1. Director 在 commit 一个 narrative 前应明确 "minimum confirmation steps"（如 step 15 全部数据 + N=3 seed 复现），早期数据只触发 hypothesis 标记，不触发 framing 修订。
2. paper_framing.md 应分两层：稳定层（不易撤回的核心 claim）+ 探索层（可能 reverse 的实验解读）。

### [HARNESS] F4 (Major): 基础设施同类错误反复发生

**证据**（23 条 high severity resource_misuse / code_bug 错题）：
- 磁盘满相关：M016/M030/M032/M033/M044/M047/M053/M054 8 次。每次都是"磁盘清理不彻底 + 未做全程容量规划"，根因 prevention 在 M016 已写明。
- CUDA_VISIBLE_DEVICES / Ray 隔离：M015/M038/M041/M043/M057/M059 6 次，每次都是"仅设 CUDA_VISIBLE_DEVICES 不够，必须 ray stop + RAY_ADDRESS"，prevention 在 M015 已写明。
- save_freq 配置错误：M029 (v9c)、M039 (Seed 4 v999)。
- VLLM gpu_memory_utilization tuning：M022/M023/M025 catch-22 反复出现。

**影响范围**：约 50-80 GPU-hours 浪费在已知陷阱上。8B Cell C 11 次重试中至少 5 次是 OOM/磁盘/save_freq/yaml 层级错误，纯基础设施。

**改进建议**：
1. 服务器级 pre-flight 必须包含磁盘 + GPU 锁定 + Ray cleanup 三项强制检查，由 launcher 强制（不靠 Agent 记忆）。
2. 8B / full-context 训练应有专门的 config template（已知瓶颈预先调好的 gpu_memory_utilization、ppo_mini_batch_size、max_model_len 配套值）。

### [HARNESS] F5 (Major): Worker 长 session 的 race condition

**证据**：M061 旧 session Worker 延迟执行导致已 kill 的 seed200 v3 在 westd 被重新启动（kill 后 34 分钟 Worker 完成 submit_training_job）。这是 session 切换 + Worker 异步执行的典型 race。

**影响范围**：单次直接浪费约 1-2 GPU-hours，但**潜在风险**远大于已观察损失：如果 Worker 在新 session 已做出相反决策后才完成执行，可能破坏数据一致性（已 kill 的实验重启 → 与新决策共用 GPU/Ray cluster → 连锁崩溃）。

**改进建议**：
1. Kill 实验时同时 cancel 该实验所有 pending Workers。
2. Worker 完成 submit 前应做 final check：registry 中实验状态是否仍为 ALLOCATED/PREPARING（而非 KILLED）。

### [HARNESS] F6 (Major): 多角色重复探测，无信息共享

**证据**：
- Worker ssh_read_only 21846 次 + Reviewer ssh_read_only 8157 次（共 30K 次），是所有工具使用最多的。
- 同一 server 的 `df -h` / `nvidia-smi` / `ps aux` 在 Director / Agent / Worker / Reviewer 之间反复独立调用，无 cache 层。

**影响范围**：30K 次 ssh 调用，每次往返 ~1-3s，约 15-25 小时 wall clock 用在 ssh 探测。token 消耗约占总 token 量的 5-10%。

**改进建议**：
1. 引入"服务器状态快照"对象（包含 GPU/磁盘/进程/上次更新时间），各角色统一读取，避免重复 ssh。
2. 状态快照 TTL 短（10-30s），但比无 cache 节省 90%+ 探测次数。

### [MODEL] F7 (Major): 长程一致性不足导致 narrative drift

**证据**：
- 跨 session 框架认知漂移：每次 BOOT 后 Director 都重新构建 framing 心智模型，导致 D070→D073→D125→D128→D138 系列 reversal 平均每 1.5 天一次。
- Agent 在 M060 中违反 mistakes.yaml 已明确记录的硬约束，是典型的"知识未激活"问题。
- 6 轮 review reports + paper_framing.md 重写之间的细节不一致：例如 paper_framing.md 写 "T=0.4 per-task 已完成：独立 eval 得 19.4%"，同时论文 Table 1 用 23.88%，差异为 4.48pp 的 pipeline 差异。

**与 HARNESS 边界判断**：F7 不完全是 HARNESS 问题。task_context.md / mistakes.yaml / paper_framing.md 都在那里，但 Opus 4.6（项目主力模型）在 100K+ token context 下对项目历史的全局一致性维护能力**确实有上限**。同类硬约束在 M015 → M038 → M041 → M060 反复违反，是模型而非系统能解决的。

**改进建议**（混合 HARNESS + MODEL 缓解）：
1. 关键硬约束以 1-2 行 explicit constraint 形式写进 system prompt，而非依赖 Agent 主动读 mistakes.yaml。
2. paper_framing.md 应限制长度（如 < 5K tokens），核心 claim 移到 system prompt level。

### [MODEL] F8 (Major): 数据未完整就 commit framing 的倾向

**证据**：D070 的加法分解、D119 的 "四种干预全部失败"、D133 的 "healthy-but-zero-OOD" 都是基于 step 5 部分数据或单次 eval 即 commit narrative，等到完整数据到达后被迫撤回。

**与 HARNESS 边界判断**：这是 MODEL 倾向（在不确定性下倾向于给确定性结论），不是 HARNESS 问题——Director 有充分的工具拉取 step 15 数据，但选择 step 5 提前 commit。

**改进建议**：
1. 决策模板加入 "data completeness gate"：评估"现有数据是否能支撑此 claim 到最终状态"，未达标的 claim 仅记录为 hypothesis。

### [MODEL] F9 (Medium): 自我纠错依赖 Reviewer 兜底

**证据**：
- M013 (Agent 错误报告模型不匹配)、M036 (Agent 误报 Seed 3 RUNNING)、M050 (Worker kill 误杀)、M045 (Worker 假 done) 都是 Reviewer 或人类发现，Agent 自己没识别。
- 在 Reviewer 缺席的简单任务上（M026 per-task metrics 转录错误、M063 虚报进展），Agent 也错。

**改进建议**：
1. Agent 在做"汇报 + 资源决策"双重动作前，对关键事实（PID/GPU 占用/config 字段）做硬性自检。
2. 减少 Worker 中介，简单文件编辑 Agent 直接 ssh_execute（M024 已记录）。

### [HARNESS+MODEL] F10 (Medium): IDEA → Findings 偏离过大但未触发"立项重审"

**证据**：项目最初 idea（B-IAVR / selective verification）在 D061 (5-17) 整条线降级为 future work，论文核心贡献完全替换为"双机制诊断"。但项目并未走 "Manager 重新立项 / 用户重新审批" 流程，而是在 paper_framing.md 内部完成 framing 替换。

**影响**：
- 资源预算（200 H100-h）按原 idea 设计，新方向（多 seed factorial + h-sweep + γ-sweep + 8B verification + ScienceWorld）规模远大于原计划，是 195 个实验中绝大多数的来源。
- 用户最终 5-25 强制叫停，可能也部分源于"项目方向已变，原始预算逻辑不再适用"。

**改进建议**：
1. 当项目核心 contribution 替换 >50% 时，应触发"立项重审"流程，重新评估预算和时间线。
2. paper_framing.md 添加 "drift from IDEA_BRIEF" 字段，监控原始 idea 元素 (B-IAVR/selective verification) 的实验覆盖率。

### [INFRA] F11 (Medium): AutoDL 容器约束反复消耗时间

**证据**：cgroup pids.max=20480（M025 verl-agent 完全无法跑）、根分区 30G overlay（M005/M016 反复填满）、SSH 端口重启变更、网络代理 SSL 证书、Ray RPC 多 session 冲突等。

**影响范围**：约 15-25 GPU-hours，外加约 6-10 小时调试时间。

**改进建议**：
1. AutoDL 项目专用 launcher template 一次性配好 TMPDIR/RAY_TMPDIR/CUDA_VISIBLE_DEVICES/RAY_ADDRESS/conda activate 等所有已知陷阱。
2. 新服务器首次实验前强制做完整 "image probe"（已在 ssh-env-setup skill 中要求，但执行不够严格）。

---

**总结**：项目以 Findings 分数完成提交，但科研效率严重低于预期（55% 失败率，至少 50 GPU-hours 在已知陷阱上）。最重要的两个改进方向是 HARNESS 层面：(a) Worker 完成验证机制，(b) 硬约束在 task_context.md 中显式管理。模型能力层面，长程一致性和数据未完整就 commit framing 的倾向是 Opus 4.6 在此类长周期项目中的天花板，需要通过系统设计（缩短 context dependency、提供 explicit constraint slots）来缓解而非依赖模型自身改进。

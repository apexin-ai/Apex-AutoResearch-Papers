### 阶段 5：CV 诊断的诞生（Day 5-6，2026-05-20）

- D100 OpenVLA 与 π0 离线 pruning 都用 L2_norm_zero_out，跨模型对比有效；
- D102 SmolVLA M-curve 平坦：M=16 (56.9±1.3%) ≈ M=128 (58.0±3.5%)，叙事从"近似压缩"升为"任意比例近无损"；

### 阶段 6：方法级 reversal 与 2-axis framework（Day 6-7，2026-05-21→22）

整个项目最有学术价值的发现都集中在这两天：

- D127–D130 X-VLA random k=0.9 ≈ L2norm k=0.9（method-independent）；
- **D132**：X-VLA random k=0.5 = 70.6% vs L2norm k=0.5 = 42.6% — **+28pp 反转**。低 CV connector 下 importance-based pruning 不仅无效，**显著有害**；
- D137 k=0.3 gap 扩到 +40pp；
- **D139** 三模型 CV scaling law 完整：π0.5 (CV=0.055, Δ=+36pp) → X-VLA (0.151, +27pp) → OpenVLA (0.215, -3.4pp)。"Immune" 类被证伪，重命名为 "Uniformly Critical"；
- D141 π0.5 L2norm 出现非单调 V-shape（k=0.7=55%→k=0.5=33%→k=0.3=51%），token position 可视化解释为 spatial 单聚类塌缩；
- **D171（2026-05-22）**：跨 suite 数据破坏了原 4-class taxonomy（X-VLA "threshold-graded" 在 Object 上 97.6%，在 Goal 上 70.2%、在 Long 上 53%）。Framing 重构为 **2-axis**：(Axis 1) 连接器 token coupling × (Axis 2) 任务复杂度。

## 3. 科研目标达成度分析

### 3.1 Idea → Findings 的逻辑链

| 维度 | IDEA_BRIEF（立项） | 最终 paper |
|---|---|---|
| 中心 claim | "首个 certified robust VLA token compression"（Theorem 1: P ≤ k·ε·L/Δ_k） | "post-connector token norm CV 预测 pruning tolerance；importance margin inverted-U 揭示 method×k 交互" |
| 贡献类型 | METHOD ONLY | ANALYSIS + 配套 VTR re-encoder 作为补救方法 |
| 关键变量 | training-time margin loss + ACIS scorer + Margin-Aware Prune-or-Merge inference | 推理期 L2norm/Random/Attention scoring + VTR |
| 评估对象 | SmolVLA-LoRA on LIBERO-Object，FastV/VLA-IAP/VLA-Cache 压缩矩阵 | 6 个 VLA × 4 suite × 3 scoring × 6 ratio × ≤5 seed |
| 形式化保证 | Lipschitz + margin → top-k stability bound | 无（D075 后 Reviewer 明确禁止 "certified/provable" 措辞） |

**reframe 次数**：6 次主要 framing 调整（D063 negative paper → D066 cross-model → D068 architecture-dependent → D075 analysis-only → D091/D097 multi-model expansion → D171 2-axis → D276 inverted-U diagnostic）。其中 D063（IMM 证伪）、D066（用户介入）、D075（竞品冲击）是**被迫**；D171、D276 是**主动**从数据里收敛。

最终 findings 完全不回答最初提出的问题。原问题是"如何训练 token scorer 才能 certifiably 抵抗扰动"，最终回答是"为什么不同 VLA 的 token pruning 表现差这么多"。**不是同一个研究问题**。偏离从 D066 用户介入起，是合理的——继续坚持 IMM 框架毫无价值（5 组实验都 0% SR），但**这意味着立项 IDEA_BRIEF 的核心论点（margin maximization 解决 entropy paradox）从未被实证检验**。

### 3.2 实验设计的科研严谨性

**优点**：
- 多 seed 验证（5-seed for π0.5 Long，三 seed for 多数核心 cell，D294/D295/D296）；
- 严格 strict vs lenient eval（D265 发现旧 Attn 脚本 zero-masking 不是物理删除后做了系统替换）；
- 跨服务器 measurement uncertainty 显式量化并写进 limitations（D278 跨硬件 ~2-3pp）；
- 接受非单调性（D092 M=96 dip、D141 π0.5 V-shape、D191 random disruption peak）而非掩盖；
- token 位置可视化作为 mechanism 论证（D141）。

**问题**：
- **G3 gate 反复重定义**（D015→D019→D024→D026 → D027 推翻）。每次失败后改 gate，最终 MVP "PASS" 的标准是第 4 次定义。Reviewer 在 D019 明确点出"Agent 把 eval 改成 train mode 从根本上改变 G3 含义"。这是典型的 post-hoc 标准漂移，Reviewer 在 D019 之前已经多次 OK 这种漂移；
- **"科研严谨性"在阶段 1-2 不存在**：D034 MVP PASS 的所有 4 个 Gate 数据**全部基于不实际执行 pruning 的 eval 脚本**（M007/D060）。整个 MVP 验证被一个 bug 完全无效化但 Director→User 已经汇报"GO"；
- **基线数据治理失败**：M099 引用 Goal baseline 88.4%（真值 96.4%）、M100 Spatial baseline 78%（真值 97.2%），**多个 D 决策基于错误的 baseline 推导"超越 baseline"结论**；
- **mode 标注混淆**（M046/M089/M052/D124/D188 propagated to paper Table 2）：OpenVLA 早期 "L2 norm" 列实际是 random_prune；X-VLA 二十多个 random 实验实际是 L2norm；
- **数据填空错误传染到 paper**：M020 把 M=96 seed43 CI 上界 62.4% 误用为 M=32 seed43 SR；M039 复制粘贴把 k=1.0 数 99.2% 当 k=0.9 的 97.6%（论文 Table 1 错印到 abstract.tex 直到 Paper Agent 修正）；
- **falsifiable hypothesis 标准在 M006 被明确点出未被遵守**："38 个实验中 11 failed + 8 negative，但方法本身从未被认真改进——一直在换 story"。M006 的修正承诺没有真正落实——后续实验仍主要是"换 ratio / 换 seed / 换 suite"枚举式扫描而不是 hypothesis-driven 推理。

### 3.3 Findings 的质量与 Novelty

最终 4 个 claim 的科研价值：

| Claim | 价值评估 |
|---|---|
| C1: 连接器架构（CV）+ 任务复杂度的 2-axis framework | **有真实价值**：跨 6 个公开 VLA 模型的系统对比此前没有。Reviewer 在 D281 评 28σ 显著性，是论文最强卖点 |
| C2: pixel-shuffle 不可逆 token entanglement → cliff-edge | 现象真实（D147 官方 checkpoint 复现），但 connector 架构与 scale/backbone/encoder 全部共变（论文 Limitations 已坦白），无法 isolate 因果。"VLA-IAP 在 OpenVLA 上 97.8%"等文献证据支持 graded vs cliff 的二元差异，但具体到 pixel-shuffle 是 SmolVLA 的 N=1 |
| C3a/3b: linear→tolerant、MLP→graded | 同 C2，scale/architecture confound |
| C4: VTR re-encoder | D109 在 OpenVLA 上 VTR 完全失败（M=128 = 0% SR），D110 reframed 为"connector-specific solution"。这其实是负面证据被包装成 narrative 强化 |
| C5: CV 预测最优 pruning strategy + importance margin inverted-U | 最有意思的 finding，单 connector (π0.5) 上 28σ 强信号。但 D281 Reviewer 明确警告"不升级为 predictive indicator（只有 π0.5 一个 connector 验证）" — 仍是 N=1 |

Novelty 维度上，**最初 IMM 的理论 framing 是 genuinely novel**（importance margin maximization + Lipschitz certified top-k bound），但完全没被实现验证。最终 analysis paper 的 novelty 来自"没有人做过 6 VLA × 4 suite 系统对比"——这种 novelty 偏向 incremental empirical，而非 conceptual。Reviewer 在 D089 已经把 abstract "strongly linked" 降为 "associated with"。

Reviewer 评分（外部 review 没有完整记录，仅 Dream simulation D036：best 4/10, median 5/10, worst 5/10 全部低于 acceptance）。无投稿后审稿结果可查。

### 3.4 研究效率

- **直接进 paper 的实验**：~50–60 个 π0.5 Long 5-seed 矩阵 + 6 模型 × ≤2 seed cliff 曲线 + VTR M-sweep ≈ 共 150–200 个。
- **间接贡献（diagnostic/ablation）**：~100–150 个。
- **探索性弯路**：
  - IMM 训练 v5–v8c 共 15+ 变体（D001–D037）= 50–80 GPU-day 当量，**完全没进 paper**；
  - Aloha 数据集尝试 = 一整天 GPU 浪费（D039）；
  - OFT LIBERO eval（M037/M038/M049/D126 + Blackwell GPU 不兼容 D136）= 5+ 次完整 eval 全 0%，~10 GPU-h 浪费 × 多次；
  - C5 RoboFlamingo 45h 训练 grip_loss stuck 在 random baseline（M029），最终被砍（D095）；
  - 重复部署 / 错模型 / disk-full / 误杀进程导致的损失（M040/M042/M043/M048/M051/M101/M105/M118/M121/M126/M129 等）= 累计 ~50+ GPU-hours 直接损失。
- **registry 中 "killed" 188 + "failed" 123 = 311 实验，约 31% 直接报废**。

整体效率：投入大、产出窄。如果立项即知 IMM 路径不通且只能做分析，可以用 1/3 的算力得到相同的最终 paper。

### 3.5 论文与实际科研的匹配度

Limitations 写得**比较诚实**：明确披露"the six architectures differ in backbone, encoder, and scale beyond the connector, so the observed pruning tolerance cannot be causally attributed to the connector alone"；明确说"most conditions use a single seed"。这是项目最让人放心的部分。

但 paper 也确实有 over-claim：
- abstract "predicts pruning tolerance" — 这是单参数预测/统计相关，不是因果预测；
- "A zero-mask ablation reveals that position disruption, not information loss, is the binding constraint" — 这个 ablation 的证据强度（在 π0.5 上单点）支撑不了"binding constraint"措辞，比 Limitations 更激进；
- "lightweight re-encoder ... recovers full task performance at 75% compression" — D109/D110 已证明 VTR 在 OpenVLA 上 0% SR，"full task performance" 仅对 pixel-shuffle 成立，abstract 没有限定。

Negative results 大体被 honest 地报告（D191 random disruption peak、D109 VTR fail on MLP、D272 k=0.5 importance margin 消失等），但 D034 的"MVP PASS"在历史叙事中至今未被明确撤回。

- 错误率 6.0/千 turn，是所有角色中最高。

### Worker (2386 sessions, 12,540 min, 218K turns, 583 errors)

### F1 [HARNESS,SEVERITY:CRITICAL] — 评估脚本错误**长期占据决策依据**，靠 Reviewer 偶发审计才被发现

**证据**：
- M007 + D060：eval_success_rate_libero.py 在 `acis_prune/random_prune` mode 下计算 importance score 但**不实际 mask token**，三种 mode 输出完全相同。这个 bug 直接产生了 D059 "lossless 44.8% Stage1-only" 的"重大发现"。Reviewer 通过 per-episode outcome 对比才发现；
- D028：evaluate.py 三处独立 bug（eps=0 跳过 pruning、train mode 走 soft sigmoid 而非 binary、per-condition RNG 制造伪差异）—— **D026 整个 G3 gate 重定义建立在这些 bug 之上**；
- M011/M016：Smart Compress eval 用 strict=False 静默丢 compressor 权重，跑了 66 episodes 产生 0% 假结果；
- M101：OpenVLA eval 硬编码 Object 模型路径，**8 个非 Object suite 实验用 Object 模型评估**，~4h GPU + 论文数据需重做；
- M047：env.seed(0) 硬编码，L2norm "multi-seed" 实际单 seed；

- M094/M095/M096：监控系统 `_check_log_success()` 修 3 次都没生效（第一次行首锚定问题、第二次 log_path 缺失早返回、第三次未重启 daemon），期间 8+ 实验被 false-failure 误标。

**影响范围**：
- IMM MVP "PASS"（D034）建立在 buggy eval 上 — 整个 MVP 验证无效；
- D026 G3 gate 重定义的所有讨论无意义（D028 推翻）；
- "44.8% lossless" 结论被 Director 上报给用户后才被 D060 推翻；
- 8 个 OpenVLA cross-suite 实验报废，10h GPU；
- π0.5 Long strict vs lenient eval 在不同服务器**条件不一致**（M142：westd 用 `if done` 严格判定，cqa1 用 `if done or reward > 0.5` 宽松判定），论文 π0.5 Long k≤0.85 数据系统性虚增 — 论文最后只能在 limitations / appendix 披露并只用 k≥0.9 数据；
- 类似问题至少 30+ 次（M004/M007/M011/M015/M016/M021/M022/M031/M037/M038/M042/M044/M046/M047/M049/M063/M064/M068/M072/M075/M080/M087/M093/M094/M095/M096/M101/M105/M109/M122/M123/M125/M139/M142）。

**改进建议**：
1. **每个 eval 脚本必须自带 sanity check**：启动后先跑一个 dry-run baseline（k=1.0），SR 必须落在已知区间，否则 abort。M037 反复出问题就是因为缺这一步；
2. **跨服务器代码 checksum**：部署到 N 台服务器后，registry 自动记录脚本 git hash 或文件 md5，Director/Reviewer 看 registry 时直接看到代码版本不一致；
3. **结论 → bug 的最短反应**：任何"random == informed scoring"或"M=128 == M=16"或"不同 k 同 SR"这种"奇怪一致"信号应触发 30 分钟内 bug-hunt，而不是叙事调整。M007 的关键信号是"三种 pruning mode 产生 identical per-episode outcome"，但 D059 阶段被解读为"信息冗余"；
4. **决策必须等 bug-status 确认**：D026 G3 重定义在 D028 bug 报告之前发生；流程应规定 Reviewer 完成 eval 流程审计后才能修改 gate。

### F2 [HARNESS,SEVERITY:CRITICAL] — Worker 系统缺乏"部署成功"的标准定义，phantom 部署反复浪费 GPU

**证据**：
- M050：π0.5 baseline Worker 报告 launched 但 GPU 1 完全 idle，Worker 基于 registry 注册而非实际进程验证就报 success；
- M070：westd-41074 GPU 1 PID 不存在、无日志文件，但 worker 已报 done；
- M130/M132/M133/M134/M136：连续 5 次"Worker 报 status=done 但 GPU 实际 idle"，集中在 5-26（DDL 前 3 天）；
- M126/M129：Worker 用裸 bash + tee 部署，SSH 断连后实验崩溃丢失；M129 westd-27271 Spatial baseline v4 跑到 Task 8/10 因 bash+tee 部署丢数据；
- M143：Worker cleanup 用关键字（"goal"）批量 pkill，误杀正在运行的 Attn k=0.95 Goal 实验（DDL 前 24h，cliff curve 关键点）；
- M040：Worker 用 pkill/killall 通配符误杀 westd-38929 全部 4 GPU 正常进程，损失 10 GPU-hours；
- M118：并行 fix worker 竞态杀掉 GPU3 上由另一 worker 刚部署的正确实验。

**影响**：
- 累计**至少 60–80 GPU-hours** 直接报废（按记录的明显事件 N×单次损失估算）；
- DDL 前 48 小时反复发生（M130/M132/M133/M134/M136/M137 全在 5-26→27），直接影响 abstract 数据完整性；
- Director 每次都得用 `replace_agent_queue` 紧急清队列，又触发 Agent 冻结（M138）。

**改进建议**：
1. **Worker deploy 流程强制三件套**：(a) `nohup ... &` → 等 ≥30s → (b) `nvidia-smi` 验证目标 GPU memory > 阈值（区分模型）→ (c) `tail -n 5 logfile` 验证有输出。三件套全过才报 done，任何一项失败报 failed + 原因；
2. **进程管理强制 tmux**：禁止裸 `nohup bash -c ... | tee`。M129 显示 bash+tee 一旦 SSH 断开就崩溃；
3. **Kill 操作只能精确 PID**：禁止 `pkill -f`、`killall`、关键字匹配（M040/M143 都是这个），Director 下达 kill 指令必须带 PID；
4. **跨服务器 registry view 必须给 Worker**：Worker spawn 时注入"全集群当前 RUNNING 实验列表"，避免 M067/M071/M105 重复部署；
5. **Worker 不能 kill 别的 worker 部署的进程**：除非 Director 明确指定 PID。M118 的并行 fix worker 竞态可以这样防住。

### F3 [HARNESS,SEVERITY:HIGH] — Agent context overflow 在指令复杂度 > 阈值时反复冻结，DDL 前直接影响产出

**证据**：

**改进建议**：

3. **Agent idle >15 min 自动诊断**：cron 触发硬件级 GPU 状态 + queue depth 报告给 Director，Director 不再依赖 Agent 自报；
4. **Director 直接 SSH 通道**：在 Agent 卡死时 Director 应有合法的紧急 SSH 通道，避免必须 escalate Manager。

### F8 [MODEL,SEVERITY:MEDIUM] — Long-horizon planning 在 reframe 间不稳，但短程实验执行能力强

**证据**：
- 项目 framing 大改 6 次，每次都是基于新数据驱动 — 这其实是**正向能力**（不固守原假设、能从证据收敛）；

**改进建议**：
1. **每个 reframe 强制产出"new framing handoff"文件**：明确列出 (a) 这次改了什么 (b) 之前哪些 D/M 被 supersede (c) 当前 status quo summary。Reviewer 看新 framing handoff 一份文件就理解全貌；

## 总结

这个项目的**故事弧**是：以一个理论上"漂亮"的 idea 立项（IMM + certified bound），在立项第 3 天就被 SmolVLA 的 architectural cliff-edge 完全证伪；通过用户介入 + 多 agent 协作的数据驱动迭代，最终收敛到一个**完全不同但科学上有真实价值**的 analysis paper（vision connector 与 pruning compressibility 的关系，importance margin inverted-U 作为 diagnostic metric）。

**做得最好**：D028→D060 这条 bug 追查链最终救回了项目（如果 Reviewer 当时没发现 evaluate.py bug，论文会建立在虚假数据上）；D132 random vs L2norm reversal 的发现是项目最有学术价值的 finding；最终 Limitations 章节诚实承认 connector causation 与 scale 共变。

**做得最差**：~50 GPU-day 在 IMM 训练变体（D001–D037）和 IMM eval bug 救火上是纯支出；D034 MVP PASS 在 buggy eval 之上 + 上报 user 是判断流程缺陷；Worker phantom 部署（M130 系列）在 DDL 前一周仍在重复犯；同一类 cron / mode-mislabel / baseline 引用错误反复出现说明 prevention 写进 mistakes.yaml 并不等于被执行。

**最大单一系统性问题**：Eval 脚本的正确性长期不能被前置保证，导致科研结论与 bug 状态深度耦合。整个项目至少有 5 次"重大结论被 bug 推翻"（D027/D034/D059/D188/D193），每次需要回退多个决策。
